**Link:** https://leetcode.com/problems/largest-rectangle-in-histogram
**Difficulty:** Hard | **LeetCode #84**
**Bloomberg frequency:** 38% at three months.

The **span** application of the monotonic stack, and the hardest of the three bar problems
(with 4.1 Trapping Rain Water and 2.4 Container With Most Water). It is also the engine
behind 4.11 Maximal Rectangle, so the effort pays twice.

## 1. Problem statement

Given an array `heights` representing the heights of the bars of a histogram, where each bar
has width `1`, return the **area of the largest rectangle** in the histogram.

```
heights = [2,1,5,6,2,3]  ->  10    the rectangle of height 5 spanning bars 2 and 3
heights = [2,4]          ->  4
```

## 2. Clarifying questions

1. **Must the rectangle be axis-aligned and contiguous?** Yes - it spans a contiguous range
   of bars, and its height is the **minimum** bar in that range.
2. **Can heights be zero?** Yes. A zero bar splits the histogram, since no rectangle of
   positive height can span it.
3. **Return the area or the bounds?** The area.
4. **Sizes?** Up to 10^5, so `O(n^2)` will time out.
5. **Can the array be empty?** Return 0.
6. **Is this the same as Trapping Rain Water?** No - same input shape, different question and
   different technique. If both have come up, distinguish them explicitly.

## 3. Intuition

### The reframing that makes it tractable

The naive search is over all `O(n^2)` ranges. Instead, fix the **height**:

> **For each bar, find the largest rectangle whose height is exactly that bar's height. The
> answer is the best of those `n` candidates.**

Why this is complete: every maximal rectangle is limited by some bar - the shortest one it
spans - so considering each bar as "the limiting bar" covers every possibility.

For a given bar `i`, that rectangle extends left and right as far as bars are **at least as
tall**, stopping at the first strictly shorter bar on each side. So:

```
width = (index of next shorter bar to the right) - (index of previous shorter bar to the left) - 1
area  = heights[i] * width
```

And "previous smaller" and "next smaller" are exactly what a monotonic stack computes - the
template from the Part 4 primer.

### Doing it in one pass

You do not need two separate passes. With a stack of indices kept in **increasing height**
order:

- When bar `i` arrives and pops bar `j`, then **`i` is `j`'s next smaller bar** (that is why
  it popped), and **the new stack top is `j`'s previous smaller bar** (everything between was
  already popped, so it was taller).

Both bounds materialise at the moment of popping. That is the elegant part and it is what to
explain.

```
width = i - stack[-1] - 1      after popping, if the stack is non-empty
width = i                      if the stack is now empty (j extends to the far left)
```

### The sentinel

At the end of the loop, bars still on the stack have no "next smaller" bar. Rather than
writing a second drain loop with slightly different width logic, **append a sentinel bar of
height 0**, which is shorter than everything and forces the stack to flush through the same
code path.

That trick - append a value that resolves everything - is worth internalising generally.

## 4. Approach

1. `stack = []` (indices, heights increasing); `best = 0`.
2. Iterate over `heights + [0]`:
   - while `stack` and `heights[stack[-1]] >= h`: pop `j`; compute the width from the new
     stack top; update `best`.
   - push `i`.
3. Return `best`.

## 5. Solution

```python
def largest_rectangle_area(heights):
    """Area of the largest rectangle in a histogram.

    For each bar, the largest rectangle limited by it extends until a strictly shorter
    bar on each side. A stack of indices with increasing heights delivers both bounds
    at the moment a bar is popped: the popping index is its next-smaller bound, and
    the new stack top is its previous-smaller bound.
    """
    stack = []                      # indices, heights increasing bottom to top
    best = 0
    # The appended 0 is a sentinel shorter than every bar, forcing a final flush.
    extended = heights + [0]

    for i, h in enumerate(extended):
        while stack and extended[stack[-1]] >= h:
            height = extended[stack.pop()]
            # Left bound is the new top (exclusive); right bound is i (exclusive).
            width = i if not stack else i - stack[-1] - 1
            best = max(best, height * width)
        stack.append(i)

    return best
```

```python
largest_rectangle_area([2, 1, 5, 6, 2, 3])      # 10
largest_rectangle_area([2, 4])                  # 4
largest_rectangle_area([])                      # 0
largest_rectangle_area([5])                     # 5
largest_rectangle_area([0])                     # 0
largest_rectangle_area([1, 1, 1, 1])            # 4
largest_rectangle_area([5, 4, 3, 2, 1])         # 9
largest_rectangle_area([1, 2, 3, 4, 5])         # 9
largest_rectangle_area([2, 1, 2])               # 3
largest_rectangle_area([0, 9])                  # 9
largest_rectangle_area([4, 2, 0, 3, 2, 5])      # 6
```

Worth narrating:

- **`[5,4,3,2,1]` and `[1,2,3,4,5]` both give 9.** Monotonic inputs in either direction, and
  the answer is `3 * 3` in both cases. They are quick symmetry checks.
- **`[2,1,2]` -> 3.** The best rectangle is height 1 across all three bars, *not* height 2 on
  a single bar. This is the case that catches anyone who only considers individual bars or
  only adjacent equal bars.
- **`[0,9]` -> 9.** A zero bar contributes nothing but must not break the width arithmetic.

Trace `[2,1,5,6,2,3]` at the moment `2` arrives at index 4:
- The stack holds indices `[1,2,3]` with heights `1,5,6`.
- `6` pops: width is `4 - 2 - 1 = 1`, area 6.
- `5` pops: width is `4 - 1 - 1 = 2`, area **10**.
- `1` does not pop (it is not `>= 2`).

That single step produces the answer and shows both width formulas in use.

### The explicit two-pass version

Clearer if the one-pass width arithmetic feels risky under pressure:

```python
def largest_rectangle_area_two_pass(heights):
    """Compute previous-smaller and next-smaller bounds separately, then combine.
    More code, same complexity, much harder to get subtly wrong."""
    n = len(heights)
    if n == 0:
        return 0

    prev_smaller = [-1] * n         # index of the nearest strictly smaller bar to the left
    stack = []
    for i in range(n):
        while stack and heights[stack[-1]] >= heights[i]:
            stack.pop()
        prev_smaller[i] = stack[-1] if stack else -1
        stack.append(i)

    next_smaller = [n] * n          # index of the nearest strictly smaller bar to the right
    stack = []
    for i in range(n - 1, -1, -1):
        while stack and heights[stack[-1]] >= heights[i]:
            stack.pop()
        next_smaller[i] = stack[-1] if stack else n
        stack.append(i)

    return max(heights[i] * (next_smaller[i] - prev_smaller[i] - 1) for i in range(n))


largest_rectangle_area_two_pass([2, 1, 5, 6, 2, 3])     # 10
largest_rectangle_area_two_pass([2, 1, 2])              # 3
largest_rectangle_area_two_pass([5, 4, 3, 2, 1])        # 9
largest_rectangle_area_two_pass([0, 9])                 # 9
largest_rectangle_area_two_pass([])                     # 0
```

A note on duplicates: both passes use `>=`, which means equal-height bars pop each other. For
a run of equal bars, the *last* one computes the full width and the earlier ones compute
truncated widths - so the maximum is still correct. That is worth saying, because `>=` versus
`>` looks like it should matter and here it does not affect the answer.

### The brute force

```python
def largest_rectangle_area_brute(heights):
    """O(n^2): extend each start rightwards, tracking the running minimum height."""
    best = 0
    for i in range(len(heights)):
        min_height = heights[i]
        for j in range(i, len(heights)):
            min_height = min(min_height, heights[j])
            best = max(best, min_height * (j - i + 1))
    return best


largest_rectangle_area_brute([2, 1, 5, 6, 2, 3])    # 10
largest_rectangle_area_brute([2, 1, 2])             # 3
largest_rectangle_area_brute([])                    # 0
```

## 6. Complexity

| | Time | Space |
|---|---|---|
| All pairs, recomputing the min | `O(n^3)` | `O(1)` |
| All pairs with a running min | `O(n^2)` | `O(1)` |
| Divide and conquer on the minimum | `O(n log n)` average, `O(n^2)` worst | `O(log n)` |
| **Monotonic stack** | **`O(n)`** | `O(n)` |

Each index is pushed once and popped at most once, so linear despite the nested `while`.

The divide-and-conquer approach is worth naming: split at the minimum bar, and the answer is
the best of (the full-width rectangle at that height, the left half, the right half). It
degrades to `O(n^2)` on a sorted histogram, which is why the stack wins.

## 7. How to present it

1. **Restate**, and state the key property: *"a rectangle's height is the minimum bar it
   spans."*
2. **Give the brute force** with the running minimum, `O(n^2)`.
3. **State the reframing** - this is the insight and it should come before any mention of
   stacks: *"instead of enumerating ranges, I'll ask for each bar: what is the widest
   rectangle whose height is exactly this bar? Every maximal rectangle is limited by some
   bar, so that covers everything."*
4. **Derive the width**: *"it extends until the first strictly shorter bar on each side, so
   the width is next-smaller minus previous-smaller minus one."*
5. **Name the tool**: "previous-smaller and next-smaller are exactly what a monotonic stack
   gives me."
6. **Offer the two-pass version first** if you want safety, or go straight to one pass and
   explain the key observation: *"when bar `i` pops bar `j`, `i` is `j`'s right bound and the
   new stack top is its left bound - both arrive at once."*
7. **Explain the sentinel** as you write it: *"appending a zero flushes the stack through the
   same code path instead of a separate drain loop."*
8. **Trace `[2,1,5,6,2,3]`** at index 4, where the `5` pops and produces 10.
9. **Test `[2,1,2]`**, the case that proves you are not just checking single bars.
10. **Close**: `O(n)` time and space, with the amortised argument, and note that this is the
    subroutine for Maximal Rectangle (4.11).

## 8. Follow-ups and variations

- **"Maximal Rectangle in a binary matrix"** (LC 85, at 4.11). Build a histogram per row -
  heights are the counts of consecutive `1`s above - and run this function on each row.
  `O(rows * cols)`. **This is the main reason to know 4.9 cold.**
- **"Return the rectangle's bounds, not just the area."** Record `(height, left, right)` when
  `best` improves.
- **"Largest square instead of rectangle."** A different problem - DP, `O(mn)` (LC 221).
- **"Maximum area under a histogram with a width limit."** Cap the width when computing the
  area; the stack machinery is unchanged.
- **"Sum of subarray minimums"** (LC 907). Same spans, but summing `height * count_of_ranges`
  instead of maximising. Here the strict/non-strict choice **does** matter - use `>` on one
  side and `>=` on the other to avoid double counting. A great follow-up to show you
  understand the spans rather than the recipe.
- **"Trapping Rain Water"** (4.1) and **"Container With Most Water"** (2.4). Three bar
  problems, three techniques. Be able to say which is which in one sentence each.
- **"Divide and conquer version?"** Split at the minimum; `O(n log n)` average but `O(n^2)`
  on a sorted input. Worth naming and rejecting.
- **"Streaming bars?"** The stack processes incrementally, but an early bar's answer may
  depend on a much later one, so you cannot emit results online.

## 9. Pitfalls

- **Only considering rectangles of a single bar's width**, missing `[2,1,2]` -> 3.
- **Computing the width as `i - j`** (the popped index) instead of `i - stack[-1] - 1`.
  **The defining bug**, and it silently undercounts.
- **Forgetting the empty-stack case.** When the stack empties, the popped bar extends all the
  way to the left edge, so the width is `i`. (Note `i - (-1) - 1` equals `i`, so treating the
  empty stack as a sentinel index of `-1` is equivalent - but write whichever form you can
  justify, rather than discovering the coincidence mid-interview.)
- **Forgetting to drain the stack** (or to add the sentinel), losing every rectangle that
  extends to the end of the array.
- **Using `>` instead of `>=`** in the pop condition. Here it still gives the right maximum,
  but be deliberate - in *Sum of Subarray Minimums* the same choice causes double counting.
- **Storing heights instead of indices**, making widths impossible.
- **Mutating the caller's list** with `heights.append(0)` instead of building a new list.
- **Confusing it with Trapping Rain Water.**
- **Claiming `O(n^2)`** because of the inner `while`.
