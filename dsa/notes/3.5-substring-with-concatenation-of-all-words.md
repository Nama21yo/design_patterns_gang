3.3 *Find All Anagrams* with **words instead of characters**. The naive solution is easy to
state; the elegant one requires seeing that you should run `wordLength` separate sliding
windows, one per starting offset. That observation is the question.

## 1. Problem statement

You are given a string `s` and an array `words` of strings **all of the same length**.

A **concatenated substring** is a substring of `s` that is the concatenation of every string
in `words` exactly once, in **any order**.

Return the starting indices of all concatenated substrings. Order does not matter.

```
s = "barfoothefoobarman", words = ["foo","bar"]  ->  [0,9]
    "barfoo" at 0, "foobar" at 9

s = "wordgoodgoodgoodbestword", words = ["word","good","best","word"]  ->  []

s = "barfoofoobarthefoobarman", words = ["bar","foo","the"]  ->  [6,9,12]
```

## 2. Clarifying questions

1. **Are all words the same length?** Yes - this is the constraint that makes the problem
   tractable. **Confirm it**, because without it the problem becomes much harder (it would
   need a trie or DP).
2. **Can `words` contain duplicates?** **Yes** - example 2 has `"word"` twice, and that is
   exactly why you need a `Counter` rather than a `set`. This is the trap.
3. **Must the words be used exactly once each?** Yes, with multiplicity.
4. **Can the words appear in any order?** Yes.
5. **Can matches overlap?** Yes - example 3 has answers at 6, 9 and 12.
6. **Sizes?** `len(s)` up to 10^4, `len(words)` up to 5000, word length up to 30.

## 3. Intuition

Let `m = len(words)`, `w = len(words[0])`, so the total match length is `m * w`.

### Naive

For each start index `i` in `0..n - m*w`, slice the next `m*w` characters into `m` chunks of
length `w`, count them, and compare with `Counter(words)`.

`O(n * m)` chunk operations, each `O(w)` to slice and hash, so roughly `O(n * m * w)`. For
LeetCode's limits that is often fast enough, and it is a perfectly good first answer. **Write
it**, state the bound, then improve.

### The sliding-window insight

Any valid match starts at some index `i`, and its chunks sit at `i, i+w, i+2w, ...`. So every
match is aligned to one of exactly **`w` residue classes** modulo `w`.

> **Run `w` independent sliding windows - one starting at offset `0`, one at `1`, ... one at
> `w-1`. Within each, advance by whole words rather than by characters.**

Inside one such window, the problem is exactly 3.3: a fixed-size window over a sequence of
tokens, maintaining a count and a `matched` tally.

Why this is faster: in the naive version, moving from start `i` to `i+1` throws away all
`m` chunks and recounts them. In the offset version, moving from `i` to `i+w` drops **one**
word and adds **one** word. Each character of `s` is visited `O(1)` times per offset, and
there are `w` offsets, so the total is `O(n * w)` - independent of `m`.

### Handling surplus

Unlike 3.3, a word can appear **too many** times in the window. When that happens you cannot
simply shrink by one - you must shrink until that specific word is back within its quota.
That is the extra `while` loop compared with the anagram version, and it is the main
implementation difference.

## 4. Approach

For each `offset` in `0..w-1`:
1. `left = offset`, `window = Counter()`, `count = 0`.
2. For `right` in `offset, offset+w, offset+2w, ...` while `right + w <= n`:
   - `word = s[right:right+w]`
   - if `word` not in `need`: reset the window entirely (`window.clear()`, `count = 0`,
     `left = right + w`)
   - else: add it; while `window[word] > need[word]`, remove `s[left:left+w]` and advance
     `left` by `w`
   - if `count == m`, record `left`, then slide off one word to look for the next match.

## 5. Solution

```python
from collections import Counter


def find_substring(s, words):
    """Start indices of every concatenation of all `words` (each used exactly once).

    All words share a length w, so every match is aligned to one of w residue classes
    mod w. Run one sliding window per offset, advancing a whole word at a time: each
    step drops one word and adds one, instead of recounting all m of them.
    """
    if not s or not words or not words[0]:
        return []

    w = len(words[0])
    m = len(words)
    total = m * w
    n = len(s)
    if total > n:
        return []

    need = Counter(words)           # a Counter, not a set: words may repeat
    result = []

    for offset in range(w):
        left = offset
        window = Counter()
        count = 0                   # words currently in the window

        for right in range(offset, n - w + 1, w):
            word = s[right:right + w]

            if word not in need:
                # No match can span this word: discard the whole window.
                window.clear()
                count = 0
                left = right + w
                continue

            window[word] += 1
            count += 1

            # Too many copies of this word: drop words from the left until it fits.
            while window[word] > need[word]:
                dropped = s[left:left + w]
                window[dropped] -= 1
                count -= 1
                left += w

            if count == m:
                result.append(left)
                # Slide off the leftmost word to search for the next match.
                dropped = s[left:left + w]
                window[dropped] -= 1
                count -= 1
                left += w

    return result
```

```python
sorted(find_substring("barfoothefoobarman", ["foo", "bar"]))                # [0, 9]
sorted(find_substring("wordgoodgoodgoodbestword", ["word","good","best","word"]))   # []
sorted(find_substring("barfoofoobarthefoobarman", ["bar", "foo", "the"]))   # [6, 9, 12]
sorted(find_substring("aaaaaa", ["aa", "aa"]))                              # [0, 1, 2]
sorted(find_substring("", ["a"]))                                           # []
sorted(find_substring("a", ["a"]))                                          # [0]
sorted(find_substring("ab", ["a", "b"]))                                    # [0]
sorted(find_substring("wordgoodgoodgoodbestword", ["word","good","best","good"]))   # [8]
sorted(find_substring("lingmindraboofooowingdingbarrwingmonkeypoundcake",
                      ["fooo","barr","wing","ding","wing"]))                # [13]
```

The results are sorted because the offset loop produces indices grouped by residue class
rather than in increasing order. The problem says any order is acceptable - but sorting in
your own tests is the honest way to compare, and saying so is worth a moment.

Two cases to narrate:
- **`["word","good","best","word"]` -> `[]`** but **`["word","good","best","good"]` -> `[8]`.**
  Same string, same multiset size, different multiplicities. This pair proves you are using
  a `Counter` and not a `set`.
- **`"aaaaaa"` with `["aa","aa"]` -> `[0,1,2]`.** Overlapping matches across different
  offsets, and it exercises the surplus-shrink loop.

### The naive version - write this first

```python
from collections import Counter


def find_substring_naive(s, words):
    """Check every start index independently. O(n * m * w) but easy to get right."""
    if not s or not words or not words[0]:
        return []
    w, m = len(words[0]), len(words)
    total = m * w
    need = Counter(words)
    result = []

    for i in range(len(s) - total + 1):
        seen = Counter()
        for j in range(i, i + total, w):
            word = s[j:j + w]
            if word not in need:
                break
            seen[word] += 1
            if seen[word] > need[word]:
                break
        else:
            result.append(i)        # the for-else fires only if no break happened
    return result


sorted(find_substring_naive("barfoothefoobarman", ["foo", "bar"]))          # [0, 9]
sorted(find_substring_naive("barfoofoobarthefoobarman", ["bar","foo","the"]))   # [6, 9, 12]
sorted(find_substring_naive("aaaaaa", ["aa", "aa"]))                        # [0, 1, 2]
sorted(find_substring_naive("wordgoodgoodgoodbestword", ["word","good","best","word"]))  # []
```

The `for ... else` is worth explaining if you use it: the `else` runs only when the loop
completes without `break`. If that construct is unfamiliar under pressure, use an explicit
`ok = True` flag - clarity beats idiom.

Note this version returns indices already in increasing order, which is a small advantage.

## 6. Complexity

Let `n = len(s)`, `m = len(words)`, `w` the word length.

| | Time | Space |
|---|---|---|
| Naive | `O(n * m * w)` | `O(m * w)` |
| **Offset sliding windows** | **`O(n * w)`** | `O(m * w)` |

The offset version runs `w` windows, each visiting `n/w` positions and doing `O(w)` work per
position to slice and hash the word - so `O(w * (n/w) * w) = O(n * w)`. Crucially it is
**independent of `m`**, which is the win when there are many words.

Space is the two counters, holding up to `m` words of length `w`.

## 7. How to present it

1. **Restate, and confirm the two key constraints**: all words are the same length, and
   `words` may contain duplicates. Say that duplicates mean a `Counter`, not a `set`.
2. **Compute the match length** `m * w` out loud - it makes the fixed-window nature obvious.
3. **Give the naive solution and its bound.** It is a complete, correct answer; get it on the
   board so you have something.
4. **Name the waste**: "Moving from start `i` to `i+1` recounts all `m` words, even though
   most of them are the same."
5. **State the insight**: *"Every match is aligned to a multiple of the word length, so there
   are only `w` distinct alignments. If I run one window per alignment and advance a whole
   word at a time, each step drops one word and adds one."*
6. **Note the difference from the anagram problem**: here a word can appear too many times,
   so the shrink is a `while` on that specific word's count, not a single step.
7. **Write it**, narrating the three cases inside the loop: unknown word (reset), surplus
   (shrink), complete match (record and slide).
8. **Test** the duplicate-words pair and the `"aaaaaa"` overlap case.
9. **Close**: `O(n * w)`, independent of the number of words.

## 8. Follow-ups and variations

- **"What if the words have different lengths?"** The alignment argument collapses entirely.
  You would need a trie over the words plus backtracking or DP over positions - and the
  problem becomes much harder. Saying precisely *which* assumption broke is the right answer.
- **"What if each word may be used any number of times?"** That is *Word Break* (LC 139, at
  23.20 / Part 15) - a DP, not a window.
- **"Return the substrings rather than the indices."** Slice `s[i:i+total]`.
- **"Find the shortest window containing all the words, not necessarily contiguous multiples?"**
  That is *Minimum Window Substring* generalised to tokens - a variable window.
- **"Very large `words` with a big alphabet."** Hash each word once to an integer id and work
  with ids, which avoids repeated string hashing. A rolling hash over the whole window is
  another option, at the cost of collision handling.
- **"Count the matches instead of listing them."** Same loop, increment a counter.
- **"What if `s` is streamed?"** The offset windows work, but you need `m*w` characters of
  lookbehind.
- **"Relation to Find All Anagrams?"** Identical structure with words as the alphabet and one
  window per offset. Drawing that parallel explicitly is the best framing.

## 9. Pitfalls

- **Using a `set` instead of a `Counter`**, so duplicate words are mishandled. The
  `["word","good","best","word"]` versus `["word","good","best","good"]` pair is the test.
- **Running only one window instead of `w`**, missing every match not aligned to offset 0.
- **Advancing by one character instead of one word** inside an offset window.
- **Using `if` instead of `while`** for the surplus shrink - several copies may need dropping.
- **Forgetting to reset the window** when an unknown word is encountered; shrinking one word
  at a time there is correct but slower, and forgetting entirely is wrong.
- **Not sliding off one word after recording a match**, so the same window is reported
  repeatedly.
- **Off-by-one in `range(offset, n - w + 1, w)`.**
- **Assuming the results come out sorted.** They do not with the offset version; the problem
  allows any order, but say so.
- **Not guarding `m * w > n`.**
