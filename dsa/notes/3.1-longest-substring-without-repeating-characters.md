## 1. Problem statement

Given a string `s`, find the length of the **longest substring** without repeating
characters.

```
s = "abcabcbb"  ->  3      "abc"
s = "bbbbb"     ->  1      "b"
s = "pwwkew"    ->  3      "wke"   (note: "pwke" is a subSEQUENCE, not a substring)
```

## 2. Clarifying questions

1. **Substring or subsequence?** **Substring** - contiguous. The third example is designed
   to catch this: `"pwke"` has no repeats but is not contiguous, so the answer is 3 from
   `"wke"`, not 4. Say this back; it is the one real trap in the statement.
2. **Return the length or the substring itself?** The length. Returning the substring is a
   trivial extension - track the start index.
3. **What is the character set?** ASCII, Unicode, digits, spaces, symbols? It decides whether
   a fixed 128-slot array is legitimate instead of a dict.
4. **Case sensitive?** Assume yes.
5. **Can the string be empty?** Return 0.
6. **Are all characters distinct a possibility?** Yes - then the answer is `len(s)`.

## 3. Intuition

Brute force: check every substring for duplicates. `O(n^3)`, or `O(n^2)` with an incremental
set. State it, then improve.

The window formulation:

> **Grow the window to the right one character at a time. When the incoming character is
> already inside the window, shrink from the left until it is not. The answer is the largest
> window ever seen.**

This is valid because the constraint is monotonic in the window size: a window with no
repeats stays repeat-free when you shrink it, and can only gain a repeat when you grow it.
That is the precondition from the primer, and it is worth one sentence.

### Two implementations, and why the second is better

**(a) Set-based.** Keep a `set` of the characters in the window. On a collision, remove
`s[left]` and advance `left` one at a time until the duplicate is gone.

**(b) Last-index map.** Keep a dict from character to the **last index** where it was seen.
When the incoming character was seen *inside the current window*, jump `left` directly to
`last[ch] + 1` - skipping all the intermediate shrink steps in one move.

Version (b) is the better answer, and the reason is worth articulating: with the set you
shrink one position at a time; with the map you jump straight to the only position that can
possibly work. Both are `O(n)` amortised, but (b) is a single pass with no inner loop at all,
which makes the linearity obvious rather than requiring an amortised argument.

**The critical detail in (b)**: `left` must only ever move **forward**. The map retains
characters that have already slid out of the window, and jumping to their stale index would
move `left` backwards and corrupt the window. The fix is
`left = max(left, last[ch] + 1)` - and that `max` is the single most commonly omitted line
in this problem.

Concretely, on `"abba"`:
- `a` at 0, `b` at 1, `b` at 2 -> `left` jumps to 2, window `"b"`.
- `a` at 3: `last['a']` is 0, which is **behind** `left`. Without the `max`, `left` would
  jump back to 1 and the window would wrongly include the `b` at index 2 - giving an answer
  of 3 instead of 2.

## 4. Approach

1. `last = {}` mapping character to its most recent index.
2. `left = 0`, `best = 0`.
3. For each `right`, `ch`:
   - if `ch in last and last[ch] >= left`: `left = last[ch] + 1`
   - `last[ch] = right`
   - `best = max(best, right - left + 1)`
4. Return `best`.

Using `left = max(left, last.get(ch, -1) + 1)` collapses the condition into one line and is
what most people write.

## 5. Solution

```python
def length_of_longest_substring(s):
    """Length of the longest substring with no repeated characters.

    `last[ch]` is the most recent index of ch. When ch reappears INSIDE the current
    window, left jumps past its previous position in one step.
    """
    last = {}                       # character -> most recent index seen
    left = 0
    best = 0

    for right, ch in enumerate(s):
        # The max is essential: last[ch] may refer to a position already left behind,
        # and left must never move backwards.
        left = max(left, last.get(ch, -1) + 1)
        last[ch] = right
        best = max(best, right - left + 1)

    return best
```

```python
length_of_longest_substring("abcabcbb")     # 3
length_of_longest_substring("bbbbb")        # 1
length_of_longest_substring("pwwkew")       # 3
length_of_longest_substring("")             # 0
length_of_longest_substring("a")            # 1
length_of_longest_substring("abba")         # 2
length_of_longest_substring("dvdf")         # 3
length_of_longest_substring("tmmzuxt")      # 5
length_of_longest_substring("abcdef")       # 6
length_of_longest_substring("aab")          # 2
```

The three cases that catch bugs, and the ones to test out loud:

- **`"abba"` -> 2.** The `max` guard. Without it you get 3.
- **`"dvdf"` -> 3** (`"vdf"`). `left` jumps to 1 when the second `d` arrives, and the window
  can still grow past it.
- **`"tmmzuxt"` -> 5** (`"mzuxt"`). The final `t` was last seen at index 0, well behind
  `left` - another `max` test.

### The set-based version

```python
def length_of_longest_substring_set(s):
    """Same answer, shrinking one position at a time. Easier to see as a window,
    but it needs the amortised argument to justify its linearity."""
    seen = set()
    left = 0
    best = 0
    for right, ch in enumerate(s):
        while ch in seen:           # `while`, not `if`: shrink until the clash is gone
            seen.remove(s[left])
            left += 1
        seen.add(ch)
        best = max(best, right - left + 1)
    return best


length_of_longest_substring_set("abcabcbb")     # 3
length_of_longest_substring_set("abba")         # 2
length_of_longest_substring_set("dvdf")         # 3
length_of_longest_substring_set("tmmzuxt")      # 5
length_of_longest_substring_set("")             # 0
```

Note this version needs no `max` guard - `left` advances only through the `while`, so it
cannot go backwards. That is the trade: one fewer subtlety, one more loop.

### Returning the substring itself

```python
def longest_substring_text(s):
    """The substring, not just its length."""
    last = {}
    left = 0
    best_len = 0
    best_start = 0
    for right, ch in enumerate(s):
        left = max(left, last.get(ch, -1) + 1)
        last[ch] = right
        if right - left + 1 > best_len:
            best_len = right - left + 1
            best_start = left
    return s[best_start:best_start + best_len]


longest_substring_text("abcabcbb")      # 'abc'
longest_substring_text("pwwkew")        # 'wke'
longest_substring_text("tmmzuxt")       # 'mzuxt'
longest_substring_text("")              # ''
```

## 6. Complexity

Let `n = len(s)` and `k` the alphabet size.

| | Time | Space |
|---|---|---|
| Brute force, all substrings | `O(n^3)` | `O(min(n,k))` |
| Brute force with an incremental set | `O(n^2)` | `O(min(n,k))` |
| **Set window** | **`O(n)` amortised** | `O(min(n,k))` |
| **Last-index map** | **`O(n)`** | `O(min(n,k))` |

Space is bounded by the **alphabet**, not the string: the window can never hold more than `k`
distinct characters. So for ASCII it is effectively `O(1)`. Saying "`O(min(n, k))`" rather
than `O(n)` is a precise touch that interviewers notice.

The map version is a genuine single pass - no inner loop - so its linearity needs no
amortised hand-waving. Point that out as the reason to prefer it.

## 7. How to present it

1. **Restate, and confirm substring versus subsequence** using the `"pwwkew"` example.
   *"'pwke' would be longer but it isn't contiguous, so the answer is 3."* Say this first;
   it is the trap in the problem statement.
2. **Ask about the character set** - it determines whether an array beats a dict.
3. **Brute force in one sentence**, `O(n^2)` with an incremental set.
4. **Name the pattern**: "This is a variable-size sliding window - grow right, shrink left
   while the window has a duplicate."
5. **Justify the window**: "The no-duplicates property is monotonic in the window size, so
   shrinking always helps and the window is valid."
6. **Offer the improvement**: "Rather than shrinking one at a time, I'll store the last index
   of each character and jump `left` straight past the previous occurrence."
7. **As you write the `max`, explain it**: *"`left` must never move backwards - the map still
   holds characters that have slid out of the window."* Then give `"abba"` as the case that
   proves it. **This is the scoring moment of the question.**
8. **Test out loud**: `"abcabcbb"`, `"bbbbb"`, `"pwwkew"`, `""`, `"abba"`, `"dvdf"`.
9. **Close**: `O(n)` time, `O(min(n, alphabet))` space; offer to return the substring itself.

## 8. Follow-ups and variations

- **"Return the substring, not the length."** Track the best start index - shown above.
- **"At most k distinct characters instead of zero repeats"** (LC 340). The same skeleton
  with `while len(counts) > k`. Remember to `del` zero-count keys.
- **"At most two distinct"** (LC 159) - the `k = 2` special case, often asked as
  *Fruit Into Baskets* (LC 904, at 3.8 here).
- **"Longest substring with at most k replacements"** (LC 424, at 3.4). The window tracks the
  most frequent character count; replacements needed is `window_size - max_count`.
- **"Longest repeating character replacement", "minimum window substring"** (LC 76) - the
  same family, and LC 76 is the hardest of them. Worth naming.
- **"Permutation in string" / "find all anagrams"** (LC 567 and 438, at 3.12 and 3.3) -
  fixed-size windows with a frequency match.
- **"What if the alphabet is huge, like full Unicode?"** The dict version is unaffected; a
  fixed-size array would be wasteful. Space is `O(min(n, k))` either way.
- **"Can you do it with O(1) space?"** Only if the alphabet is bounded, in which case a
  128- or 256-element array is `O(1)` by definition. Otherwise no - you must remember the
  window's contents.
- **"What if it were a stream?"** Works as-is: one pass, and memory bounded by the alphabet.
- **"Longest substring where every character appears at least k times"** (LC 395). A window
  does **not** directly apply - the usual solution is divide and conquer on the characters
  that appear fewer than `k` times. A good example of the pattern *not* fitting.

## 9. Pitfalls

- **Omitting the `max` in `left = max(left, last[ch] + 1)`.** `left` moves backwards and the
  window becomes invalid. `"abba"` and `"tmmzuxt"` are the tests. **The defining bug of this
  problem.**
- **Solving for subsequence instead of substring** - `"pwwkew"` returns 4.
- **`if` instead of `while`** in the set version, leaving a duplicate in the window.
- **Forgetting to remove characters from the set** as `left` advances.
- **Updating `last[ch]` before computing the new `left`**, so a character always clashes with
  itself.
- **Computing the length as `right - left`** instead of `right - left + 1`.
- **Returning `left` or `right`** rather than `best`.
- **Not handling the empty string.**
- **Claiming `O(n)` space** when it is bounded by the alphabet.
