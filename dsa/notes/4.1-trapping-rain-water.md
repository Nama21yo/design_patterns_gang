**per-column insight**, because once you have it every solution follows mechanically.

## 1. Problem statement

Given `n` non-negative integers representing an elevation map where the width of each bar is
`1`, compute how much water it can trap after raining.

```
height = [0,1,0,2,1,0,1,3,2,1,2,1]  ->  6
height = [4,2,0,3,2,5]              ->  9
```

## 2. Clarifying questions

1. **Water is trapped above each column up to the lower of the two surrounding maxima?**
   State this back - it is the model, and confirming it early saves the whole round.
2. **Can bar heights be zero?** Yes. Zero-height columns still trap water if flanked.
3. **Does water spill off the ends?** Yes - the outermost columns can never trap anything,
   because there is no wall beyond them.
4. **Return the total volume, or the per-column amounts?** The total.
5. **Constraints?** `n` up to 2·10^4, heights up to 10^5. `O(n^2)` is borderline; aim for
   `O(n)`.
6. **Is this Container With Most Water?** No - **different problem**. There you pick two
   walls and ignore everything between; here every column matters. If the interviewer has
   asked both, be explicit about the distinction.

## 3. Intuition

### The per-column insight - the whole problem

Stop thinking about pools and think about **one column at a time**:

> **The water sitting above column `i` is
> `min(max height to its left, max height to its right) - height[i]`,
> or zero if that is negative.**

Water rises until it would spill over the lower of the two walls that contain it. That is it.
Everything else is bookkeeping about how to compute those two maxima efficiently.

Say this sentence, write the formula on the board, and verify it on one column of the
example before writing any code. On `[0,1,0,2,1,0,1,3,2,1,2,1]`, column 5 has height 0, left
max 2, right max 3, so it holds `min(2,3) - 0 = 2` units.

### Three ways to get the maxima

**(a) Brute force**: for each column, scan left and right for the maxima. `O(n^2)`, `O(1)`
space.

**(b) Precomputed prefix/suffix maxima**: two passes to build `left_max[i]` and
`right_max[i]`, then one pass to sum. `O(n)` time, `O(n)` space. **This is the one to write
first** - it is a direct transcription of the formula and almost impossible to get wrong.

**(c) Two pointers**: `O(n)` time, `O(1)` space. The clever one, and the usual target.

### The two-pointer argument

Keep `left` and `right` at the ends, plus `left_max` and `right_max` seen so far.

The key realisation:

> **If `left_max < right_max`, then the water above the left column is determined by
> `left_max` alone - whatever the true right maximum turns out to be, it is at least
> `right_max`, which already exceeds `left_max`. So the `min` is `left_max` regardless.**

That means you can safely settle the left column and advance, without knowing the global
right maximum. Symmetrically for the other side. Process whichever side has the smaller
maximum.

This is an exchange-style argument like 2.4, and being able to state it is what the
interviewer is listening for. Do not just say "move the smaller side".

### The monotonic-stack solution

There is also a stack solution that computes water in **horizontal layers** rather than
vertical columns: maintain a decreasing stack of bar indices; when a taller bar arrives, it
forms the right wall of a basin whose floor is the popped bar and whose left wall is the new
stack top. It is `O(n)` time and `O(n)` space and is the reason this problem sits in Part 4.
Know it, but do not lead with it - the two-pointer version is shorter and easier to defend.

## 4. Approach

**Two pointers:**
1. `left, right = 0, n-1`; `left_max = right_max = 0`; `total = 0`.
2. While `left < right`:
   - if `height[left] < height[right]`: the left side is the binding constraint.
     Update `left_max`; add `left_max - height[left]`; `left += 1`.
   - else: symmetric on the right.
3. Return `total`.

## 5. Solution

```python
def trap(height):
    """Total trapped water. O(n) time, O(1) space.

    Water above column i is min(max left, max right) - height[i]. When
    height[left] < height[right], the left side is the binding constraint: the true
    right maximum is at least height[right], which already exceeds anything on the
    left, so the min is decided by left_max alone and the column can be settled now.
    """
    if not height:
        return 0

    left, right = 0, len(height) - 1
    left_max = right_max = 0
    total = 0

    while left < right:
        if height[left] < height[right]:
            # Left side is lower, so left_max decides the water here.
            left_max = max(left_max, height[left])
            total += left_max - height[left]
            left += 1
        else:
            right_max = max(right_max, height[right])
            total += right_max - height[right]
            right -= 1

    return total
```

```python
trap([0, 1, 0, 2, 1, 0, 1, 3, 2, 1, 2, 1])      # 6
trap([4, 2, 0, 3, 2, 5])                        # 9
trap([])                                        # 0
trap([1])                                       # 0
trap([1, 2])                                    # 0
trap([2, 0, 2])                                 # 2
trap([3, 0, 0, 2, 0, 4])                        # 10
trap([5, 4, 3, 2, 1])                           # 0
trap([1, 2, 3, 4, 5])                           # 0
trap([0, 0, 0])                                 # 0
```

`[2,0,2]` -> 2 is the minimal non-trivial case, and `[5,4,3,2,1]` / `[1,2,3,4,5]` -> 0 are
the monotonic cases - a strictly increasing or decreasing profile traps nothing. Those three
are the right quick tests.

`[3,0,0,2,0,4]` -> 10 is worth working through: columns 1 and 2 hold 3 each (bounded by
`min(3,4)`), column 3 holds 1, column 4 holds 3. Total 10.

### The prefix/suffix version - write this first

```python
def trap_prefix(height):
    """O(n) time, O(n) space. A direct transcription of the per-column formula."""
    n = len(height)
    if n == 0:
        return 0

    left_max = [0] * n
    right_max = [0] * n

    left_max[0] = height[0]
    for i in range(1, n):
        left_max[i] = max(left_max[i - 1], height[i])

    right_max[-1] = height[-1]
    for i in range(n - 2, -1, -1):
        right_max[i] = max(right_max[i + 1], height[i])

    return sum(min(left_max[i], right_max[i]) - height[i] for i in range(n))


trap_prefix([0, 1, 0, 2, 1, 0, 1, 3, 2, 1, 2, 1])   # 6
trap_prefix([4, 2, 0, 3, 2, 5])                     # 9
trap_prefix([2, 0, 2])                              # 2
trap_prefix([])                                     # 0
trap_prefix([3, 0, 0, 2, 0, 4])                     # 10
```

Note the `min(...) - height[i]` is never negative here, because `left_max[i]` and
`right_max[i]` both include `height[i]` itself. That is a small elegance worth pointing out -
it means no `max(0, ...)` guard is needed.

### The monotonic-stack version

```python
def trap_stack(height):
    """Fills water in horizontal layers. A taller bar closes a basin whose floor is
    the popped bar and whose left wall is the new stack top."""
    stack = []                      # indices, heights decreasing
    total = 0

    for i, h in enumerate(height):
        while stack and height[stack[-1]] < h:
            floor = stack.pop()
            if not stack:
                break               # no left wall, so nothing is trapped
            left = stack[-1]
            width = i - left - 1
            bounded_height = min(height[left], h) - height[floor]
            total += width * bounded_height
        stack.append(i)

    return total


trap_stack([0, 1, 0, 2, 1, 0, 1, 3, 2, 1, 2, 1])    # 6
trap_stack([4, 2, 0, 3, 2, 5])                      # 9
trap_stack([2, 0, 2])                               # 2
trap_stack([3, 0, 0, 2, 0, 4])                      # 10
trap_stack([])                                      # 0
trap_stack([5, 4, 3, 2, 1])                         # 0
```

The `if not stack: break` is essential: a popped bar with nothing to its left has no left
wall, so it cannot hold water.

### The brute force

```python
def trap_brute(height):
    """O(n^2): scan both directions for each column. State it, then improve."""
    total = 0
    for i in range(len(height)):
        left_max = max(height[:i + 1])
        right_max = max(height[i:])
        total += min(left_max, right_max) - height[i]
    return total


trap_brute([0, 1, 0, 2, 1, 0, 1, 3, 2, 1, 2, 1])    # 6
trap_brute([4, 2, 0, 3, 2, 5])                      # 9
trap_brute([2, 0, 2])                               # 2
```

## 6. Complexity

| | Time | Space |
|---|---|---|
| Brute force | `O(n^2)` | `O(1)` |
| Prefix/suffix maxima | `O(n)` | `O(n)` |
| Monotonic stack | `O(n)` | `O(n)` |
| **Two pointers** | **`O(n)`** | **`O(1)`** |

The stack version is `O(n)` by the push-once-pop-once argument. The two-pointer version is a
single pass with the pointers meeting in the middle, so exactly `n` iterations.

## 7. How to present it

1. **Restate the model out loud** before anything else: *"Water above a column rises to the
   lower of the highest bar on its left and the highest on its right."* Write the formula.
2. **Verify it on one column** of the given example. Thirty seconds, and it confirms the
   model with the interviewer.
3. **Distinguish from Container With Most Water** unprompted if you have seen both: *"That
   one picks two walls and ignores the middle; here every column contributes."*
4. **Give the brute force** and its `O(n^2)`.
5. **Give the prefix/suffix solution** - "two passes to precompute the maxima, then one to
   sum" - and write it. You now have a complete, correct `O(n)` answer in hand.
6. **Then offer the `O(1)`-space version**, and **give the argument properly**: *"If the left
   bar is shorter than the right bar, then whatever the true right maximum is, it is at least
   this right bar - which already exceeds the left maximum. So the minimum is decided by the
   left side, and I can settle that column now."* This is the scoring moment.
7. **Write it**, then **trace `[2,0,2]`** to show the pointers meeting.
8. **Test the monotonic profiles** (`[1,2,3,4,5]` and `[5,4,3,2,1]` both give 0) and the
   empty case.
9. **Mention the stack solution exists** and computes water in horizontal layers, if time
   allows.
10. **Close**: `O(n)` time, `O(1)` space.

## 8. Follow-ups and variations

- **"Do it in O(1) space."** The main follow-up - the two-pointer version.
- **"Prove the two-pointer move is safe."** The argument above. Expect to be asked.
- **"Trapping Rain Water II"** (LC 407) - the **2D** version. Completely different: a
  min-heap flood fill from the border inwards, processing the lowest boundary cell first.
  `O(mn log(mn))`. Name it; deriving it in the room is a big ask. It is the natural "harder
  version" and knowing it exists is worth real credit.
- **"Return the water above each column, not the total."** The prefix/suffix version gives
  this directly; the two-pointer version does too, if you record as you go.
- **"What if the bars have varying widths?"** Multiply each column's water by its width; the
  model is unchanged.
- **"Container With Most Water"** (LC 11, at 2.4). Explicitly contrast them.
- **"Largest Rectangle in Histogram"** (LC 84, at 4.9). Same input shape, third technique -
  monotonic stack over spans. Three bar problems, three methods: name all three and you have
  demonstrated the map of this Part.
- **"What if it rains a finite amount?"** Now it is a simulation or a binary search on the
  final water level - a genuinely different problem, and a good one to think aloud about.
- **"Streaming heights."** You cannot answer online: the water above an early column depends
  on bars arbitrarily far in the future.

## 9. Pitfalls

- **Confusing it with Container With Most Water** and computing `min(h[l], h[r]) * width`.
- **Using `height[left]` instead of `left_max`** when adding water - the current bar may be
  shorter than the running maximum, and it is the maximum that bounds the water.
- **Updating `left_max` after adding the water** rather than before, which can add a negative
  contribution.
- **Comparing `left_max < right_max` instead of `height[left] < height[right]`.** Both
  formulations can be made to work, but mixing them is a subtle bug; pick one. The version
  above compares the **bars**.
- **In the stack version, forgetting the `if not stack` guard** after popping.
- **In the stack version, using `height[stack[-1]] <= h`** and double-counting flat regions -
  it happens to still work here because the bounded height becomes zero, but be deliberate.
- **`while left <= right`**, which processes the meeting column twice.
- **Forgetting the empty-array case.**
- **Claiming `O(n^2)` for the stack version** because of the inner `while`.
