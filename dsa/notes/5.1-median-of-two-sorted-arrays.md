## 1. Problem statement

Given two sorted arrays `nums1` and `nums2` of sizes `m` and `n`, return the **median** of
the two sorted arrays combined.

The overall run time complexity should be **`O(log (m+n))`**.

```
nums1 = [1,3], nums2 = [2]      ->  2.00000    merged = [1,2,3]
nums1 = [1,2], nums2 = [3,4]    ->  2.50000    merged = [1,2,3,4], median = (2+3)/2
```

## 2. Clarifying questions

1. **Definition of median for an even total length?** The **average of the two middle
   elements**, hence the `2.5` in example 2. Confirm it.
2. **Can either array be empty?** Yes - and it is the case most solutions break on. LeetCode
   allows `m` or `n` to be 0 (but not both).
3. **Are there duplicates, across and within the arrays?** Yes.
4. **Return a float?** Yes.
5. **Must it really be `O(log(m+n))`?** Stated. **Ask whether they want that or whether the
   `O(m+n)` merge is acceptable** - it is a fair question on a Hard, and the answer tells you
   how to spend the round.
6. **Can the values be negative?** Yes, which matters for the sentinel values in the
   partition solution.

## 3. Intuition

### Level 1: merge (O(m + n)) - write this first

Merge the two arrays and take the middle. You do not even need to materialise the merge -
walk both with two pointers until you reach the middle position, tracking the last two
values seen.

**Do this first.** It is correct, it takes five minutes, and it means you have something
working. Then say: *"that's `O(m+n)`; let me see if I can get logarithmic."*

### Level 2: binary search on the partition

The logarithmic solution searches over **where to cut**, not over values.

The idea: split the combined sorted order into a left half and a right half of the correct
sizes, by choosing how many elements to take from `nums1`. If you take `i` elements from
`nums1`, you must take `j = half - i` from `nums2`, where `half = (m + n + 1) // 2`.

```
      nums1:  A[0] ... A[i-1] | A[i] ... A[m-1]
      nums2:  B[0] ... B[j-1] | B[j] ... B[n-1]
                    left half | right half
```

The cut is **correct** exactly when every element on the left is `<=` every element on the
right. Since each array is internally sorted, that reduces to two conditions:

```
A[i-1] <= B[j]      and      B[j-1] <= A[i]
```

- If `A[i-1] > B[j]`, you took too many from `nums1` - **move `i` left**.
- If `B[j-1] > A[i]`, you took too few - **move `i` right**.

That is a monotone predicate in `i`, so binary search it over `[0, m]`.

Once the cut is correct:
- **odd total**: the median is `max(A[i-1], B[j-1])`, the largest element on the left.
- **even total**: it is the average of `max(A[i-1], B[j-1])` and `min(A[i], B[j])`.

### The two details that make it work

**(a) Always binary search the SHORTER array.** Swap if necessary. This guarantees
`j = half - i` stays within `[0, n]` and makes the complexity `O(log(min(m, n)))` - better
than `O(log(m+n))`. Without the swap, `j` can go out of range and the code needs extra
guards.

**(b) Use infinite sentinels at the boundaries.** When `i == 0` there is no `A[i-1]`, so
treat it as `-infinity`; when `i == m` there is no `A[i]`, so treat it as `+infinity`. The
same for `B`. This is what removes every boundary special case, including the empty-array
case, and it is why the code below has no `if` for them.

Using `float("-inf")` rather than a large constant matters when values can be negative.

`half = (m + n + 1) // 2` with the `+1` puts the extra element on the **left** when the total
is odd, which is why the odd case reads the left side.

## 4. Approach

1. Ensure `nums1` is the shorter array, swapping if needed.
2. `lo, hi = 0, m`; `half = (m + n + 1) // 2`.
3. While `lo <= hi`:
   - `i = (lo + hi) // 2`; `j = half - i`
   - compute the four boundary values with infinite sentinels
   - if `left1 > right2`: `hi = i - 1`
   - elif `left2 > right1`: `lo = i + 1`
   - else: the cut is correct - return the median.

## 5. Solution

```python
def find_median_sorted_arrays(nums1, nums2):
    """Median of two sorted arrays in O(log(min(m, n))).

    Binary search over how many elements to take from the SHORTER array. A cut is
    correct when every element left of it is <= every element right of it, which for
    two sorted arrays reduces to two cross comparisons. Infinite sentinels at the
    boundaries remove every special case, including empty inputs.
    """
    # Always search the shorter array: keeps j in range and makes it O(log min(m, n)).
    if len(nums1) > len(nums2):
        nums1, nums2 = nums2, nums1

    m, n = len(nums1), len(nums2)
    if m + n == 0:
        raise ValueError("both arrays are empty")

    total = m + n
    half = (total + 1) // 2         # +1 puts the extra element on the LEFT when odd

    lo, hi = 0, m
    while lo <= hi:
        i = (lo + hi) // 2          # take i from nums1
        j = half - i                # and the rest from nums2

        # Sentinels: nothing to the left of index 0, nothing to the right of the end.
        left1 = nums1[i - 1] if i > 0 else float("-inf")
        right1 = nums1[i] if i < m else float("inf")
        left2 = nums2[j - 1] if j > 0 else float("-inf")
        right2 = nums2[j] if j < n else float("inf")

        if left1 > right2:
            hi = i - 1              # took too many from nums1
        elif left2 > right1:
            lo = i + 1              # took too few from nums1
        else:
            # Correct cut: everything on the left is <= everything on the right.
            if total % 2 == 1:
                return float(max(left1, left2))
            return (max(left1, left2) + min(right1, right2)) / 2

    raise ValueError("inputs are not sorted")   # unreachable for valid input
```

```python
find_median_sorted_arrays([1, 3], [2])          # 2.0
find_median_sorted_arrays([1, 2], [3, 4])       # 2.5
find_median_sorted_arrays([], [1])              # 1.0
find_median_sorted_arrays([2], [])              # 2.0
find_median_sorted_arrays([], [1, 2])           # 1.5
find_median_sorted_arrays([1, 1], [1, 1])       # 1.0
find_median_sorted_arrays([1, 2, 3], [4, 5, 6]) # 3.5
find_median_sorted_arrays([4, 5, 6], [1, 2, 3]) # 3.5
find_median_sorted_arrays([1], [2, 3, 4, 5, 6]) # 3.5
find_median_sorted_arrays([-5, -3], [-2, -1])   # -2.5
find_median_sorted_arrays([1, 3, 5, 7], [2])    # 3.0
```

The cases to run out loud:

- **`[]` with `[1,2]` -> 1.5.** The empty-array case, handled entirely by the sentinels and
  the swap. It is where most implementations break.
- **`[-5,-3]` and `[-2,-1]` -> -2.5.** Negatives, which is why the sentinels must be
  infinities rather than `0` or a large positive constant.
- **`[1,2,3]` / `[4,5,6]` and its reverse both give 3.5**, confirming the swap does not
  change the answer.
- **`[1,1]` and `[1,1]` -> 1.0.** All duplicates, where several cuts are valid.

### The O(m + n) merge - write this first

```python
def find_median_merge(nums1, nums2):
    """O(m + n) time, O(1) space. Walks to the middle tracking the last two values.

    Correct and much easier to get right - write this before attempting the
    logarithmic version, so there is always something working.
    """
    total = len(nums1) + len(nums2)
    if total == 0:
        raise ValueError("both arrays are empty")

    i = j = 0
    previous = current = 0

    # Walk to the middle position, remembering the last two values seen.
    for _ in range(total // 2 + 1):
        previous = current
        if i < len(nums1) and (j >= len(nums2) or nums1[i] <= nums2[j]):
            current = nums1[i]
            i += 1
        else:
            current = nums2[j]
            j += 1

    if total % 2 == 1:
        return float(current)
    return (previous + current) / 2


find_median_merge([1, 3], [2])          # 2.0
find_median_merge([1, 2], [3, 4])       # 2.5
find_median_merge([], [1, 2])           # 1.5
find_median_merge([-5, -3], [-2, -1])   # -2.5
find_median_merge([1], [2, 3, 4, 5, 6]) # 3.5
find_median_merge([1, 1], [1, 1])       # 1.0
```

### Tracing the partition on `[1,2]` and `[3,4]`

`m = 2`, `n = 2`, `total = 4`, `half = 2`. Searching `i` in `[0, 2]`.

| `i` | `j` | left1 | right1 | left2 | right2 | check |
|---|---|---|---|---|---|---|
| 1 | 1 | 1 | 2 | 3 | 4 | `left2 (3) > right1 (2)` -> too few from nums1, `lo = 2` |
| 2 | 0 | 2 | inf | -inf | 3 | both conditions hold - correct cut |

Median = `(max(2, -inf) + min(inf, 3)) / 2 = (2 + 3) / 2 = 2.5`. Two rows, and it exercises
both sentinels - the best thing to put on the board.

## 6. Complexity

| | Time | Space |
|---|---|---|
| Merge both fully, then index | `O(m + n)` | `O(m + n)` |
| **Two-pointer walk to the middle** | **`O(m + n)`** | **`O(1)`** |
| **Binary search on the partition** | **`O(log(min(m, n)))`** | **`O(1)`** |

The partition version is better than the required `O(log(m+n))`, because it searches only the
shorter array - worth saying, since it is a stronger claim than the problem asks for.

## 7. How to present it

This is a Hard. **Budget your time and secure a partial answer first.**

1. **Restate**, confirm the even-length averaging, and **ask whether `O(m+n)` would be
   acceptable**. If they insist on logarithmic, say you will write the merge first as a
   baseline and then improve it - that framing protects you.
2. **Write the two-pointer merge.** Five minutes, `O(m+n)` time and `O(1)` space. You now
   have a correct solution.
3. **Introduce the partition idea by what you are searching over**: *"instead of searching
   for a value, I'll search for where to cut - how many elements to take from the first
   array. The rest is forced."*
4. **Draw the partition diagram.** Two rows with a vertical bar. It is essential; the code is
   incomprehensible without it.
5. **State the correctness condition**: `A[i-1] <= B[j]` and `B[j-1] <= A[i]`, and explain why
   those two suffice (each array is already internally sorted).
6. **Say the two key details before coding**: search the **shorter** array, and use
   **infinite sentinels** at the boundaries. Explain that the sentinels are what make the
   empty and edge cases disappear.
7. **Explain `half = (m+n+1)//2`** and why the `+1` matters for odd totals.
8. **Write it**, then **trace `[1,2]` / `[3,4]`** with the table above.
9. **Test** the empty array, the negatives, and the all-duplicates case.
10. **Close**: `O(log(min(m,n)))`, `O(1)` space - better than the required bound.

## 8. Follow-ups and variations

- **"Find the k-th smallest element of two sorted arrays."** The generalisation, and often
  asked instead. Recursively discard `k/2` elements from one array each step -
  `O(log k)`. If you know this, the median is the special case `k = (m+n)/2`.
- **"What about `k` sorted arrays?"** A min-heap of the `k` heads, `O(N log k)` - or binary
  search on the value for the median, which is `O(k log(max-min))`.
- **"What if the arrays were not sorted?"** Then it is the selection problem - quickselect
  gives `O(m+n)` average, which is optimal since you must read everything.
- **"What if they are on disk / streamed?"** The merge walk only needs sequential access and
  `O(1)` memory, so it streams. The partition search needs random access, so it does not -
  a genuinely good trade to point out.
- **"Return the median of a running stream"** (LC 295). Completely different: two heaps,
  `O(log n)` per insertion. Name it as the related design question - it is the streaming
  cousin and appears in the Part 10 material.
- **"Why is the shorter array searched?"** To keep `j = half - i` within bounds and to get
  `O(log min(m,n))`. Expect this question.
- **"Can you avoid the sentinels?"** Yes, with explicit boundary branches - but that is four
  more conditions and four more chances to be wrong. The sentinels are the better engineering
  choice and saying so is worth a point.

## 9. Pitfalls

- **Not searching the shorter array**, so `j` goes out of range.
- **Omitting the sentinels** and then missing an edge case - especially an empty array.
- **Using `0` or a large constant as a sentinel** instead of infinity, which breaks on
  negative values.
- **`half = (m+n)//2` without the `+1`**, which puts the extra element on the wrong side for
  odd totals and gives the wrong median.
- **Using `while lo < hi`** here. This problem returns from *inside* the loop when the cut is
  correct, so the inclusive `lo <= hi` form is the right one - a deliberate exception to the
  template used elsewhere in Part 5.
- **Returning an integer** instead of a float. `float(max(...))` for the odd case.
- **Comparing `A[i-1] <= A[i]`** (within one array) rather than across the two. The
  within-array order is already guaranteed; it is the **cross** comparisons that matter.
- **Merging the whole array when only the middle is needed** - correct, but `O(m+n)` space
  for no reason.
- **Spending the entire round on the logarithmic version and delivering nothing.** Write the
  merge first.
