---
title: "23.21 Characters in the first string but not the second"
---

> Reported once in R2 on 2025-10-30, as the warm-up before the harder "remove 3+ consecutive
> characters" problem (`23.5`). Easy questions like this are scored on **what you ask**, not
> on whether you can write it - the specification is genuinely ambiguous and the interviewer
> knows it.

## Prompt as given

```
Given two strings first and second, return the characters that appear in first but do not
appear in second.

  first = "abcdef", second = "bdf"  ->  "ace"
```

Related: [Find the Difference](https://leetcode.com/problems/find-the-difference/),
[Minimum Number of Steps to Make Two Strings Anagram](https://leetcode.com/problems/minimum-number-of-steps-to-make-two-strings-anagram/).

## The ambiguity - this is the question

The single example does not pin down the semantics, because every character is distinct in
both strings. Three readings all produce `"ace"` on the given input:

1. **Set difference.** Characters of `first` not present anywhere in `second`. `"aab"` vs
   `"b"` gives `"a"`.
2. **Multiset difference.** Each occurrence in `second` cancels one occurrence in `first`.
   `"aab"` vs `"ab"` gives `"a"`; `"aab"` vs `"b"` gives `"aa"`.
3. **Positional.** Compare index by index. Nonsense when lengths differ, but worth ruling out.

**Ask which.** The multiset reading is the more interesting one and is what the related
"make two strings anagram" problem uses, so it is a likely intent - but do not guess.
Offer the difference with an example: *"if first is `aab` and second is `b`, do you want `a`
or `aa`?"*

## Clarifying questions to ask first

1. **Set or multiset semantics?** The question above, with a concrete example.
2. **Preserve the order of `first`, or return sorted/any order?** The example is consistent
   with both. Preserving order is the safer default.
3. **Return a string or a list of characters?** A string, per the example.
4. **Character set - lowercase ASCII, full ASCII, or Unicode?** This decides whether the
   "26-slot array" trick is legitimate. Interviewers like this question being asked.
5. **Case sensitive?** Is `"A"` the same as `"a"`?
6. **Can either string be empty?**

## Intuition

Membership testing is the whole problem, and a `set` (or `Counter`) turns `O(n)` scans into
`O(1)` lookups.

- **Set reading:** build `set(second)` once, then filter `first`. One pass each.
- **Multiset reading:** build `Counter(second)`, then walk `first` and decrement - emit the
  character only when the counter for it has run out.

The naive version is `if ch not in second`, where `second` is a **string**. That is an `O(m)`
scan per character, so `O(n*m)` overall. It looks identical to the correct version and is the
bug the question is really checking for. Say the word "set" out loud as you write it.

## Approach

1. Convert `second` to a `set` (or `Counter`).
2. Walk `first` in order, keeping characters that fail the membership (or count) test.
3. `"".join(...)`.

## Solution

```python
from collections import Counter


def chars_in_first_only(first, second):
    """Set semantics: characters of `first` that appear nowhere in `second`,
    in the order they occur in `first`."""
    # A set, not the string: `ch not in second` on a string is an O(len(second)) scan.
    excluded = set(second)
    return "".join(ch for ch in first if ch not in excluded)


def chars_in_first_only_multiset(first, second):
    """Multiset semantics: each occurrence in `second` cancels one occurrence in `first`."""
    remaining = Counter(second)
    out = []
    for ch in first:
        if remaining[ch] > 0:
            remaining[ch] -= 1      # this occurrence is cancelled
        else:
            out.append(ch)
    return "".join(out)
```

```python
chars_in_first_only("abcdef", "bdf")             # 'ace'
chars_in_first_only_multiset("abcdef", "bdf")    # 'ace'

# The two readings agree when `second` shares no character with a repeated run:
chars_in_first_only("aab", "b")                  # 'aa'
chars_in_first_only_multiset("aab", "b")         # 'aa'

# ... and diverge as soon as it does:
chars_in_first_only("aab", "ab")                 # ''
chars_in_first_only_multiset("aab", "ab")        # 'a'
chars_in_first_only("aabb", "ab")                # ''
chars_in_first_only_multiset("aabb", "ab")       # 'ab'
```

The divergence is on `("aab", "ab")`: set semantics removes **every** `a` because `a` occurs
somewhere in `second`, giving `""`; multiset semantics cancels only **one** `a`, giving
`"a"`. That is the example to put in front of the interviewer.

Note `remaining[ch]` on a `Counter` returns `0` for a missing key rather than raising, which
is why there is no `if ch in remaining` guard. It does **not** insert the key on read, unlike
`defaultdict` - worth knowing, and worth saying if they ask.

### The bitmask version, for lowercase ASCII only

```python
def chars_in_first_only_bitmask(first, second):
    """O(1) extra space when the alphabet is 26 lowercase letters: one int as a bit set."""
    mask = 0
    for ch in second:
        mask |= 1 << (ord(ch) - ord("a"))
    return "".join(ch for ch in first if not (mask >> (ord(ch) - ord("a"))) & 1)
```

```python
chars_in_first_only_bitmask("abcdef", "bdf")     # 'ace'
```

Only offer this **after** confirming the alphabet is lowercase ASCII - and say that
constraint as you offer it. Producing it unprompted for arbitrary Unicode input is a bug,
not a flourish.

## Complexity

Let `n = len(first)`, `m = len(second)`, `k` = alphabet size.

| | Time | Space |
|---|---|---|
| `ch not in second` on the raw string | `O(n * m)` | `O(1)` |
| Set / Counter | `O(n + m)` | `O(min(m, k))` |
| Bitmask (lowercase ASCII) | `O(n + m)` | `O(1)` |

The set version is optimal: you must read both strings at least once. Space is bounded by
the alphabet, so for ASCII it is effectively `O(1)` - a nice distinction to draw between
"`O(k)` where `k` is the alphabet" and "`O(m)`".

## How to present it

1. **Spot the ambiguity immediately and name it.** "Your example has no repeated characters,
   so it doesn't tell me what to do with duplicates. If `first` is `aab` and `second` is
   `ab`, do you want `a` or nothing?" On an easy question this is the entire differentiator.
2. **Ask about order** and about the alphabet.
3. **State the naive `O(n*m)`** and why it is wrong: `in` on a string is a scan.
4. **Write the set version** and say "set, so membership is `O(1)` average".
5. **Write the multiset version too** if they wanted that reading - it is four extra lines.
6. **Test on the divergent case** to show the two semantics behave as specified.
7. **Offer the bitmask** only if the alphabet was confirmed small, and say the constraint.

## Follow-ups and variations

- **"What about multiplicities?"** The multiset version. This is the follow-up most likely to
  come, and pre-empting it in your clarifying questions is better than answering it later.
- **"Preserve the order of `first`, or return sorted?"** The generator preserves order;
  `sorted(set(...))` if they want it canonical. Note that sorting changes the complexity to
  `O(n log n)`.
- **"Unicode rather than lowercase ASCII - does your 26-slot array still work?"** No. A fixed
  26-element array or a 26-bit mask assumes the alphabet; `set`/`Counter` do not. This is
  exactly why the general solution should be your default and the bitmask an optimisation
  offered under a stated constraint.
- **"Do it with O(1) extra space."** The bitmask, under the ASCII assumption. For general
  input, `O(1)` extra space is not achievable without modifying the inputs.
- **"Return the symmetric difference"** - characters in exactly one of the two. Two passes,
  or `set(first) ^ set(second)`; ask about order again, since a symmetric difference has no
  natural order.
- **"How many characters must be changed to make them anagrams?"** That is
  [LC 1347](https://leetcode.com/problems/minimum-number-of-steps-to-make-two-strings-anagram/),
  and it is `sum((Counter(first) - Counter(second)).values())` - `Counter` subtraction drops
  non-positive counts, which is exactly the multiset difference. Worth knowing, because that
  problem was *also* reported in this loop (2025-11-08).
- **"The strings are huge / streamed."** Build the `Counter` for `second` first (it must fit
  in memory, bounded by the alphabet), then stream `first`.

## Pitfalls

- **`if ch not in second` with `second` as a string.** Quietly `O(n*m)`. The single most
  common miss on this question.
- **Answering with set semantics when the interviewer meant multiset** (or the reverse)
  because you never asked.
- **Deduplicating the output** when they wanted every surviving occurrence - `"aab"` vs
  `"b"` should give `"aa"`, not `"a"`, under both readings.
- **Using a `set` for `first` as well**, which destroys the order and the multiplicities.
- **Assuming lowercase ASCII** and hard-coding `ord(ch) - ord('a')`, which produces a
  negative shift and a wrong answer (or an exception) on any other input.
- **Using `defaultdict(int)` and reading missing keys**, silently growing the dict. `Counter`
  does not do this on read.
- **Returning a list when they asked for a string**, or forgetting the `"".join`.
