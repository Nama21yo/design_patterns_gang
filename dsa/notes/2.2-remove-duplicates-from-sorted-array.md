**Link:** https://leetcode.com/problems/remove-duplicates-from-sorted-array
**Difficulty:** Easy | **LeetCode #26**
**Bloomberg frequency:** 62% in the **30-day** window, 50% at three months.

The purest example of the **read/write pointer** shape. Easy in itself; the value is in the
invariant, which transfers directly to 2.7 Move Zeroes, 2.9 Remove Element, and the "at most
k duplicates" follow-up.

## 1. Problem statement

Given an integer array `nums` **sorted in non-decreasing order**, remove the duplicates
**in place** so that each unique element appears only once, keeping the relative order.

Return `k`, the number of unique elements. The first `k` positions of `nums` must hold those
unique elements; what lies beyond position `k` does not matter.

```
nums = [1,1,2]          ->  k = 2, nums = [1,2,_]
nums = [0,0,1,1,1,2,2,3,3,4] -> k = 5, nums = [0,1,2,3,4,_,_,_,_,_]
```

## 2. Clarifying questions

1. **Is the array definitely sorted?** Yes - and it is essential. Duplicates are adjacent
   only because of that, which is what makes a single pass work. On unsorted input you would
   need a hash set (Part 1) or a sort first.
2. **In place, or may I allocate?** In place, `O(1)` extra space. Returning a new list is the
   thing the question is designed to forbid.
3. **What should be beyond index `k`?** Anything - "it does not matter". You do not need to
   truncate or pad.
4. **Return the count or the array?** The count `k`; the array is mutated as a side effect.
5. **Can the array be empty?** Then `k = 0`.
6. **Non-decreasing or strictly increasing?** Non-decreasing, so duplicates genuinely occur.

## 3. Intuition

Because the array is sorted, **every duplicate sits immediately next to its twin**. So you
never need to remember what you have seen - only whether the current element differs from
the last one you kept.

Use two pointers moving in the same direction:

> **`write` marks where the next unique value goes; `read` scans. Everything before `write`
> is the finished, deduplicated prefix.**

That invariant is the answer, and it is worth saying in exactly those words. It tells you
immediately:
- start `write` at `1`, because `nums[0]` is trivially unique and already in place;
- compare `nums[read]` against `nums[write - 1]`, the last value you **kept** - not against
  `nums[read - 1]`, the last value you **saw**.

Those two comparisons happen to be equivalent here, but they diverge in the "keep at most
two" follow-up, so anchoring on `nums[write - 1]` is the habit that generalises.

## 4. Approach

1. If the array is empty, return 0.
2. `write = 1`.
3. For `read` from `1` to `n-1`:
   - if `nums[read] != nums[write - 1]`: `nums[write] = nums[read]`, `write += 1`
4. Return `write`.

Elements that are duplicates are simply skipped - no shifting, no deletion, which is why it
is `O(n)` rather than `O(n^2)`.

## 5. Solution

```python
def remove_duplicates(nums):
    """Deduplicate a sorted array in place. Returns the number of unique elements.

    Invariant: nums[0:write] is the finished, deduplicated prefix, and nums[write-1]
    is the last value kept. Comparing against the last KEPT value (not the last value
    seen) is the habit that generalises to the 'at most k duplicates' variant.
    """
    if not nums:
        return 0

    write = 1                       # nums[0] is always unique, so start writing at 1
    for read in range(1, len(nums)):
        if nums[read] != nums[write - 1]:
            nums[write] = nums[read]
            write += 1
    return write
```

```python
data = [1, 1, 2]
remove_duplicates(data)             # 2
data[:2]                            # [1, 2]

data = [0, 0, 1, 1, 1, 2, 2, 3, 3, 4]
remove_duplicates(data)             # 5
data[:5]                            # [0, 1, 2, 3, 4]

remove_duplicates([])               # 0
remove_duplicates([7])              # 1

data = [2, 2, 2, 2]
remove_duplicates(data)             # 1
data[:1]                            # [2]

data = [1, 2, 3]
remove_duplicates(data)             # 3
data[:3]                            # [1, 2, 3]
```

`[2,2,2,2]` returning 1 and `[1,2,3]` returning 3 are the two extremes - all duplicates and
no duplicates - and they are the pair to check aloud.

### The "keep at most two" variant (LC 80)

This is the follow-up that shows why the invariant was phrased around `write`:

```python
def remove_duplicates_at_most_two(nums, k=2):
    """Allow each value to appear at most k times. Same invariant, one comparison changed.

    Compare against nums[write - k]: if the incoming value differs from the element k
    positions back in the KEPT prefix, fewer than k copies are present so far.
    """
    write = 0
    for x in nums:
        if write < k or x != nums[write - k]:
            nums[write] = x
            write += 1
    return write


data = [1, 1, 1, 2, 2, 3]
remove_duplicates_at_most_two(data)     # 5
data[:5]                                # [1, 1, 2, 2, 3]

data = [0, 0, 1, 1, 1, 1, 2, 3, 3]
remove_duplicates_at_most_two(data)     # 7
data[:7]                                # [0, 0, 1, 1, 2, 3, 3]

data = [1, 1, 1]
remove_duplicates_at_most_two(data, 1)  # 1
data[:1]                                # [1]
```

Note that `k = 1` reduces exactly to the original problem - a good sanity check to state.
The generalisation is three characters different from the specific case, which is the reward
for anchoring on `write` rather than on `read - 1`.

## 6. Complexity

| | Time | Space |
|---|---|---|
| Naive: build a new list | `O(n)` | `O(n)` - and it is disallowed |
| Naive: `del nums[i]` inside a loop | `O(n^2)` | `O(1)` |
| **Read/write pointers** | **`O(n)`** | **`O(1)`** |

One pass, each element read once and written at most once. The `del`-in-a-loop version is the
trap: every deletion shifts the tail, so it is quadratic *and* it corrupts your index.

## 7. How to present it

1. **Restate**, stressing in place, return the count, and that elements past `k` are
   irrelevant.
2. **Say why sorted matters**: "Because it is sorted, duplicates are adjacent, so I only need
   to compare with the last value I kept - I do not need a set."
3. **State the invariant** before writing anything: *"everything before `write` is the
   finished deduplicated prefix."* This is the whole solution and interviewers score it.
4. **Announce**: "A write pointer starting at 1 and a read pointer scanning; I copy forward
   only when the value differs from `nums[write - 1]`."
5. **Write it**, and explain why `write` starts at 1.
6. **Trace `[0,0,1,1,1,2,2,3,3,4]`**, showing `write` advancing only on a change.
7. **Test** the extremes: all-same, all-distinct, empty, single.
8. **Close**: `O(n)` time, `O(1)` space; then volunteer the LC 80 variant - *"if you allowed
   each value up to twice, I'd compare against `nums[write - 2]` instead"* - which is a
   strong finish.

## 8. Follow-ups and variations

- **"Allow each element at most twice."** LC 80, shown above. The one-parameter
  generalisation is the good answer.
- **"What if the array is not sorted?"** Then adjacency fails. Either sort first
  (`O(n log n)`, and order changes) or use a `set` while compacting (`O(n)` time, `O(n)`
  space, preserves first-occurrence order). Ask which constraint matters more - this is the
  Part 1 versus Part 2 trade from the primer.
- **"Remove all elements equal to a given value."** LC 27, which is 2.9 here - same skeleton,
  different predicate.
- **"Move all zeroes to the end."** LC 283, which is 2.7 - same skeleton plus a fill or swap
  phase.
- **"Return the removed elements too."** Collect them in a separate list, which costs `O(n)`
  space.
- **"Do it on a sorted linked list."** LC 83. The same idea with pointer relinking instead of
  overwriting; no `write` index, you just skip nodes.
- **"Count the distinct elements without modifying the array."** One pass comparing
  neighbours, `O(1)` space and no mutation.
- **"What if duplicates should be removed entirely, not reduced to one?"** LC 82 on lists -
  now you must look ahead to know whether a value repeats, which is a genuinely different
  scan.

## 9. Pitfalls

- **Deleting inside the loop** (`nums.pop(i)` / `del nums[i]`), which is `O(n^2)` and skips
  elements because the indices shift under you.
- **Starting `write` at 0**, which duplicates the first element.
- **Comparing `nums[read]` with `nums[read - 1]`** instead of `nums[write - 1]`. Equivalent
  here, but wrong for the "at most k" variant, and it shows the invariant was not understood.
- **Truncating the array** with `del nums[write:]` - harmless but unnecessary, and the
  problem explicitly says the tail does not matter.
- **Returning the array instead of the count.**
- **Forgetting the empty-array guard**, so `nums[0]` raises.
- **Using a `set`** on a sorted array - correct but `O(n)` space for nothing, and it discards
  the one property you were given.
- **Assuming sortedness when it was not stated.** Ask.
