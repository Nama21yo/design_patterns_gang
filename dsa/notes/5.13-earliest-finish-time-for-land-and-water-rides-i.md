**Link:** https://leetcode.com/problems/earliest-finish-time-for-land-and-water-rides-i
**Difficulty:** Easy | **LeetCode #3633**
**Bloomberg frequency:** 38% at three months.

A **very recent** problem, which makes it more likely to be asked cold and less likely to be
memorised. The naive `O(n*m)` solution passes at the stated limits, but the `O(n + m)`
reduction is short and is the reason to understand it rather than brute-force it.

## 1. Problem statement

You are given two categories of theme park attractions.

- **Land rides:** `landStartTime[i]` is the earliest time ride `i` can be boarded, and
  `landDuration[i]` is how long it lasts.
- **Water rides:** `waterStartTime[j]` and `waterDuration[j]` likewise.

A tourist must experience **exactly one ride from each category, in either order**.

- A ride may be started at its opening time or any later moment.
- A ride started at time `t` finishes at `t + duration`.
- Immediately after finishing one ride, the tourist may board the other **if it is already
  open**, or **wait** until it opens.

Return the **earliest possible time** at which the tourist can finish both rides.

```
landStartTime  = [2,8], landDuration  = [4,1]
waterStartTime = [6],   waterDuration = [3]
->  9
    land ride 0: start at 2, finish at 6. Water ride 0 opens at 6, so start at 6, finish at 9.
```

## 2. Clarifying questions

1. **Exactly one from each category?** Yes - not one total, not any number.
2. **Either order?** Yes, land-then-water **or** water-then-land, and the answer is the best
   over both. Missing one direction is the most likely error.
3. **Can the tourist wait?** Yes. So the second ride starts at
   `max(finish of the first, its own opening time)`.
4. **Is there any travel or queueing time between rides?** No - boarding is immediate once
   both conditions are met.
5. **Can a ride be started before its opening time?** No.
6. **Sizes?** Small on LeetCode (a few hundred), so `O(n*m)` passes. The linear solution is
   still worth deriving.

## 3. Intuition

### The cost of a pair

Fix a first ride finishing at time `f`, and a second ride with opening time `s` and duration
`d`. The second starts at `max(f, s)` and finishes at:

```
max(f, s) + d
```

That is the whole model, and writing it down is the first step.

### The key observation

For a **fixed** second ride, `max(f, s) + d` is **non-decreasing in `f`**. So among all
possible first rides, the best one is simply the one with the **smallest finish time** -
regardless of which second ride you pair it with.

> **You do not need to try every pair. Compute the earliest finish time over all first rides
> once, then try each possible second ride against that single value.**

So:

1. `best_land_finish = min(landStartTime[i] + landDuration[i])` over all land rides.
2. For each water ride `j`: candidate is `max(best_land_finish, waterStartTime[j]) +
   waterDuration[j]`.
3. Repeat symmetrically with water first.
4. Answer is the minimum over both directions.

That reduces `O(n*m)` to `O(n + m)`.

**Both directions are genuinely necessary.** In the example, land-first gives 9, but
water-first gives 10 - and there are inputs where the reverse holds. Computing only one
direction is the defining bug.

### Why this is not a binary search problem

It is filed in Part 5 by tag, but the technique here is **greedy plus a single minimum**.
Worth saying so plainly rather than forcing a binary search onto it - recognising that a
problem does *not* need the Part's headline technique is a legitimate and useful skill.

## 4. Approach

1. Write a helper `best(first_start, first_dur, second_start, second_dur)` that computes the
   minimum finish time when a ride from the first category is taken first.
2. Inside it: take the minimum finish over the first category, then minimise
   `max(that, s) + d` over the second category.
3. Return the minimum of the helper called both ways round.

## 5. Solution

```python
def earliest_finish_time(land_start, land_duration, water_start, water_duration):
    """Earliest time to finish exactly one land ride and one water ride, in either order.

    For a fixed second ride, max(first_finish, open) + duration is non-decreasing in
    first_finish - so only the EARLIEST finishing first ride ever matters. That turns
    the O(n*m) pairwise search into two linear passes per direction.
    """
    def best(first_start, first_dur, second_start, second_dur):
        # The earliest any ride in the first category can finish.
        earliest_first = min(s + d for s, d in zip(first_start, first_dur))
        # Pair it against every possible second ride, waiting if it is not open yet.
        return min(max(earliest_first, s) + d
                   for s, d in zip(second_start, second_dur))

    return min(
        best(land_start, land_duration, water_start, water_duration),   # land first
        best(water_start, water_duration, land_start, land_duration),   # water first
    )
```

```python
earliest_finish_time([2, 8], [4, 1], [6], [3])          # 9
earliest_finish_time([5], [1], [1], [1])                # 6
earliest_finish_time([1], [1], [5], [1])                # 6
earliest_finish_time([0], [5], [0], [5])                # 10
earliest_finish_time([10], [1], [1], [1])               # 11
earliest_finish_time([1, 2, 3], [1, 1, 1], [1], [1])    # 3
earliest_finish_time([100], [1], [1], [100])            # 102
```

Two worth narrating:

- **`[5],[1]` land and `[1],[1]` water -> 6.** Water first: start at 1, finish at 2; land
  opens at 5, so wait, start at 5, finish at 6. Land first would give: start at 5, finish at
  6; water already open, finish at 7. So **water-first wins** - and this is the case that
  proves both directions must be tried.
- **`[1],[1]` land and `[5],[1]` water -> 6.** The mirror image, where land-first wins. The
  pair of them together is the strongest test you can run in ten seconds.

`[1,2,3],[1,1,1]` with one water ride shows the `min` over the first category doing its work:
only the land ride finishing earliest (at time 2) matters.

`[100],[1]` land and `[1],[100]` water -> **102** is the most dramatic case, and it is worth
computing both ways: land-first gives `max(101, 1) + 100 = 201`, while water-first gives
`max(101, 100) + 1 = 102`. A solution that only tries land-first is off by 99 here.

### The brute force

```python
def earliest_finish_time_brute(land_start, land_duration, water_start, water_duration):
    """O(n*m): try every pair in both orders. Correct, and the validation oracle."""
    best = float("inf")
    for ls, ld in zip(land_start, land_duration):
        for ws, wd in zip(water_start, water_duration):
            # land first, then water
            land_finish = ls + ld
            best = min(best, max(land_finish, ws) + wd)
            # water first, then land
            water_finish = ws + wd
            best = min(best, max(water_finish, ls) + ld)
    return best


earliest_finish_time_brute([2, 8], [4, 1], [6], [3])    # 9
earliest_finish_time_brute([5], [1], [1], [1])          # 6
earliest_finish_time_brute([1], [1], [5], [1])          # 6
earliest_finish_time_brute([100], [1], [1], [100])      # 102
```

Write this first in an interview - it is obviously correct, it passes the stated limits, and
it gives you something to optimise.

## 6. Complexity

Let `n` be the number of land rides and `m` the water rides.

| | Time | Space |
|---|---|---|
| Brute force over all pairs | `O(n * m)` | `O(1)` |
| **Minimum-finish reduction** | **`O(n + m)`** | **`O(1)`** |

Two linear passes per direction, four in total. Constant extra space.

## 7. How to present it

1. **Restate**, and **confirm both orders are allowed**. That is the constraint most likely
   to be skipped, and it doubles the work.
2. **Write the cost model on the board**: a second ride opening at `s` with duration `d`,
   started after a first ride finishing at `f`, ends at `max(f, s) + d`. Everything follows
   from that line.
3. **Give the brute force** and its `O(n*m)`, and note it would pass - then say you can do
   better.
4. **State the observation**: *"`max(f, s) + d` is non-decreasing in `f`, so for any fixed
   second ride the best first ride is just the one that finishes earliest. I only need one
   number from the first category, not all of them."* **This is the insight.**
5. **Announce** the four-pass structure, then write the helper and call it both ways.
6. **Emphasise the symmetry** - writing one helper and calling it twice avoids duplicating
   the logic and halves the chance of a bug.
7. **Test the pair** `[5],[1]` / `[1],[1]` and its mirror, showing each direction winning
   once.
8. **Close**: `O(n + m)` time, `O(1)` space - and note this is a greedy argument rather than
   a binary search, despite the Part.

## 8. Follow-ups and variations

- **"What if the tourist must take `k` rides from each category?"** The single-minimum
  argument breaks, because the rides interact. It becomes a scheduling problem, likely a DP
  over `(rides taken, current time)`.
- **"What if there were three categories?"** Try all `3! = 6` orders, taking the minimum
  finish greedily at each stage - still linear per order, so `O(6(n+m+p))`. The same argument
  extends because each stage only needs the earliest finish so far.
- **"Return which rides to take."** Record the argmin alongside each minimum.
- **"What if there were a travel time between categories?"** Add it to the finish time before
  the `max`; the structure is unchanged. A good check that you understood the model.
- **"What if a ride also has a closing time?"** Now a ride may become unavailable, so the
  earliest-finishing first ride is no longer necessarily usable - the greedy breaks and you
  would need to consider more candidates.
- **"Minimise the total waiting time instead of the finish time."** A different objective,
  and the greedy no longer applies.
- **"What if rides can be taken in parallel?"** Then the answer is just the maximum of the two
  individual minima - much easier.

## 9. Pitfalls

- **Trying only one order.** Land-first and water-first can each win; `[5],[1]` versus
  `[1],[1]` demonstrates it.
- **Forgetting the wait**, i.e. computing `f + d` instead of `max(f, s) + d`. Then a ride is
  started before it opens.
- **Taking the minimum *start* time rather than the minimum *finish* time** for the first
  category. It is the finish that matters.
- **Assuming the earliest-opening ride is the best first ride.** A ride opening at 2 with
  duration 4 finishes at 6; one opening at 8 with duration 1 finishes at 9 - but reverse the
  durations and the conclusion flips. Only the sum matters.
- **Pairing the minimum finish with the minimum opening time** of the second category instead
  of minimising over all second rides. `max` is not distributive like that.
- **Forcing a binary search** because the problem is filed under Part 5.
- **Using `float("inf")` and forgetting to handle empty categories** - the constraints
  guarantee at least one of each, but `min()` on an empty sequence raises.
