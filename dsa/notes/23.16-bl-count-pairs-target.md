---
title: "23.16 Count unique index pairs summing to a target"
---

> Reported once in R1 on 2025-10-20, as the first of two questions. The same interviewer
> then asked the tsunami grid problem (`23.15`).

## Prompt as given

```
Given an array of numbers and a target, count the number of unique pairs that sum to the
target, where uniqueness is by INDEX.

  arr = [0, 1, 2, 3, 4, 5, 5], target = 5   ->   4

  (indices (0,5), (0,6), (1,4) and (2,3))
```

Related: [Two Sum](https://leetcode.com/problems/two-sum/),
[Count Number of Pairs With Absolute Difference K](https://leetcode.com/problems/count-number-of-pairs-with-absolute-difference-k/).

## Read the example carefully

`arr = [0, 1, 2, 3, 4, 5, 5]`, target 5. The pairs are:

| indices | values | sum |
|---|---|---|
| (0, 5) | 0 + 5 | 5 |
| (0, 6) | 0 + 5 | 5 |
| (1, 4) | 1 + 4 | 5 |
| (2, 3) | 2 + 3 | 5 |

Answer 4. Note `(0,5)` and `(0,6)` are **both counted** even though the value pair `(0,5)` is
the same - because uniqueness is by index, not by value. That is the entire specification
and it is the thing to confirm out loud. Note also that `(5,6)` is not a pair: `5 + 5 = 10`.

If uniqueness were by *value*, the answer would be 3.

## Clarifying questions to ask first

1. **Unique by index or by value?** The prompt says index; the example proves it. Say both
   answers so they can pick: "by index I get 4, by value I get 3."
2. **Is `(i, j)` the same pair as `(j, i)`?** Yes - unordered pairs, count once. The example
   confirms: `(0,5)` appears, `(5,0)` does not.
3. **Can an element pair with itself** (`i == j`)? No.
4. **Can values be negative? Zero?** Matters for the `target = 2*x` self-pair case below.
5. **Do I need the pairs, or just the count?** The count. If they want the pairs, the answer
   can be quadratic in size and no counting trick helps.
6. **Is the array sorted?** In the example it happens to be. **Do not assume it** - ask,
   because a sorted array unlocks the `O(1)`-space two-pointer solution.

## Intuition

The brute force is every pair: `O(n^2)`. Fine to state, then improve.

The complement trick: as you scan left to right, for each element `x` the number of valid
partners already seen is `count_so_far[target - x]`. Add that to the total, then record `x`.

> **One pass, a running frequency map, and you count each pair exactly once - at the moment
> you meet its second element.**

Counting at the second element is what makes it correct *and* dedup-free. You never ask "have
I counted this pair already", because a pair `(i, j)` with `i < j` is counted exactly once,
when the scan reaches `j`. That reasoning is the thing to say aloud, and it is also why the
awkward `x == target - x` self-pairing case needs no special handling: when you reach the
second `5`, the map already contains one `5`, so it contributes 1, which is correct.

Contrast with the naive "count `freq[x] * freq[target-x]` over all distinct `x`" approach,
which double counts and needs a `//2` and a separate branch for `x == target - x`. The
one-pass version has neither. Say that.

## Approach

1. `counts = Counter()`, `total = 0`.
2. For each `x` in the array:
   - `total += counts[target - x]` (partners already seen)
   - `counts[x] += 1`
3. Return `total`.

## Solution

```python
from collections import Counter


def count_pairs(arr, target):
    """Number of index pairs (i, j) with i < j and arr[i] + arr[j] == target.

    Each pair is counted exactly once, at the moment the scan reaches its SECOND element,
    so no deduplication and no special case for x == target - x is needed.
    """
    counts = Counter()
    total = 0
    for x in arr:
        total += counts[target - x]     # every earlier element that completes the sum
        counts[x] += 1                  # record x only after counting, so i < j holds
    return total
```

```python
count_pairs([0, 1, 2, 3, 4, 5, 5], 5)    # 4
count_pairs([1, 1, 1, 1], 2)             # 6   -- all C(4,2) pairs
count_pairs([0, 0, 0], 0)                # 3
count_pairs([3, -1, 4, 1], 3)            # 1   -- (-1, 4)
count_pairs([1, 2, 3], 100)              # 0
```

The order of the two lines in the loop is the whole correctness argument. Incrementing
`counts[x]` *before* the lookup would let an element pair with itself when
`target == 2 * x` - `[3]` with target 6 would return 1 instead of 0. Point at those two
lines and say why they are in that order.

### Unique by value instead

```python
def count_pairs_by_value(arr, target):
    """Distinct VALUE pairs {a, b} with a + b == target, counted once each."""
    counts = Counter(arr)
    pairs = set()
    for x in counts:
        y = target - x
        # {x, x} is only a real pair if x occurs at least twice.
        if y in counts and not (x == y and counts[x] < 2):
            pairs.add((min(x, y), max(x, y)))   # canonical order, so {a,b} == {b,a}
    return len(pairs)
```

```python
count_pairs_by_value([0, 1, 2, 3, 4, 5, 5], 5)   # 3   -- {0,5}, {1,4}, {2,3}
```

A `Counter` rather than a `set` here, because the `x == y` case needs the multiplicity -
`arr.count(x)` would be an `O(n)` scan inside the loop and quietly makes it quadratic.

### If the array is sorted: O(1) extra space

```python
def count_pairs_sorted(arr, target):
    """Two pointers on a sorted array. O(1) extra space, still O(n).
    Counts index pairs, handling duplicate blocks combinatorially."""
    lo, hi = 0, len(arr) - 1
    total = 0
    while lo < hi:
        current = arr[lo] + arr[hi]
        if current < target:
            lo += 1
        elif current > target:
            hi -= 1
        elif arr[lo] == arr[hi]:
            # Everything between lo and hi is the same value: all C(k, 2) pairs count.
            k = hi - lo + 1
            total += k * (k - 1) // 2
            break
        else:
            # Count the duplicate block at each end and multiply.
            left_block = 1
            while lo + left_block < hi and arr[lo + left_block] == arr[lo]:
                left_block += 1
            right_block = 1
            while hi - right_block > lo and arr[hi - right_block] == arr[hi]:
                right_block += 1
            total += left_block * right_block
            lo += left_block
            hi -= right_block
    return total
```

```python
count_pairs_sorted([0, 1, 2, 3, 4, 5, 5], 5)   # 4
count_pairs_sorted([1, 1, 1, 1], 2)            # 6
```

Offer this only if they say the array is sorted or ask for `O(1)` space - the duplicate
bookkeeping is easy to get wrong under pressure and the hash version is the better default.

## Complexity

| | Time | Space |
|---|---|---|
| Brute force, all pairs | `O(n^2)` | `O(1)` |
| One-pass counter | `O(n)` | `O(n)` |
| Two pointers, sorted input | `O(n)` | `O(1)` |
| Sort first, then two pointers | `O(n log n)` | `O(1)` or `O(n)` depending on the sort |

The one-pass version is `O(n)` **average**, because it rests on hashing - and this
interviewer is known to follow up with "how does hashing work", so use the word *average*.

## How to present it

1. **Verify the example by listing the four pairs.** Then say: "`(0,5)` and `(0,6)` are both
   counted even though the values are identical, so uniqueness is by index. If it were by
   value the answer would be 3 - which one do you want?" This single observation shows you
   read the example rather than pattern-matched to Two Sum.
2. **State the brute force and its cost.**
3. **State the complement idea**: for each element, its partner is `target - x`.
4. **Say the counting-at-the-second-element argument** and why it removes all dedup logic.
   This is the strongest sentence available in this question.
5. **Code it**, and explicitly justify the order of the two lines.
6. **Test out loud** on `[1,1,1,1]` with target 2, which should give 6, and on `[3]` with
   target 6, which should give 0.
7. **Close** with `O(n)` average, and offer the sorted two-pointer variant for `O(1)` space.

## Follow-ups and variations

- **"Unique by value instead of by index."** Shown above; answer 3 on their example.
- **"Count pairs whose DIFFERENCE is the target."** Asked separately by the same loop - see
  `23.17`. The complement becomes `x - target` **and** `x + target`, and order now matters.
- **"Count triplets summing to the target."** Sort, then for each `i` run the two-pointer
  scan on the remainder - `O(n^2)`. This is 3Sum, and the dedup rules are different (by
  value) so be careful which counting rule applies.
- **"Return the pairs, not the count."** The output can be `O(n^2)` large (e.g. all zeros
  with target 0), so no sub-quadratic algorithm exists. Say that - it is output-bound.
- **"The array is a stream."** The one-pass version already works: it never revisits an
  element, and memory is `O(distinct values)`.
- **"Memory is tight."** Sort in place and use two pointers, `O(1)` extra.
- **"How does hashing work in a set and a hash map?"** Asked verbatim in the neighbouring
  question. Have the answer ready: a hash function maps the key to a bucket index; collisions
  are resolved by chaining or open addressing; the load factor triggers a resize and rehash;
  amortised `O(1)`, worst case `O(n)` when everything collides. CPython uses open addressing
  with a perturbation probe sequence and resizes at two-thirds full.
- **"What if there are many queries with different targets?"** Sort once, then two pointers
  per query at `O(n)` each, or precompute a `Counter` once and answer each query in
  `O(distinct values)`.

## Pitfalls

- **Incrementing the counter before looking up the complement**, letting an element pair with
  itself. Test `[3]` with target 6.
- **Double counting** by iterating over distinct values and multiplying frequencies without
  halving, or halving without special-casing `x == target - x`.
- **Answering the by-value question when they asked by index** (or the reverse). The example
  distinguishes them; use it.
- **Assuming the array is sorted** because it happens to be in the example.
- **Using a `set` instead of a `Counter`**, which loses multiplicity and breaks `[1,1,1,1]`.
- **Returning ordered pairs**, doubling the answer.
- **`arr.count(x)` inside a loop** - `O(n)` each call, quietly quadratic.
