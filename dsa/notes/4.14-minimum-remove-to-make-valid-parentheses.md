## 1. Problem statement

Given a string `s` of `'('`, `')'` and lowercase English characters, remove the **minimum
number** of parentheses (at any positions) so that the resulting string is valid.

A string is valid if it is empty, contains only lowercase letters, or can be written as `AB`
or `(A)` where `A` and `B` are valid.

Return **any** valid result.

```
s = "lee(t(c)o)de)"   ->  "lee(t(c)o)de"   (removing the last ')')
s = "a)b(c)d"         ->  "ab(c)d"
s = "))(("            ->  ""
```

## 2. Clarifying questions

1. **Only round brackets?** Yes, plus lowercase letters. Letters are never removed.
2. **Any valid answer, or a specific one?** **Any** - `"lee(t(c)o)de"` and `"lee(t(co)de"`
   are both accepted for example 1. That freedom is what makes a greedy approach sound; say
   it out loud.
3. **Minimum number of removals?** Yes, and the greedy below achieves it - every character it
   removes is one that *cannot* appear in any valid result.
4. **Can the answer be empty?** Yes - `"))(("` removes everything.
5. **Are there other bracket types?** No. With several types the problem is harder and a
   single counter would not suffice.
6. **Sizes?** Up to 10^5, so `O(n)` is expected.

## 3. Intuition

There are exactly **two** kinds of bad parenthesis:

1. A `)` that arrives when nothing is open - it can never be matched by anything to its left,
   and nothing to its right can help, so it must go.
2. A `(` that is still unmatched when the string ends - nothing to its right closes it, so it
   must go.

Everything else is part of a matched pair and can stay.

> **Scan once with a stack of indices of unmatched `(`. A `)` either pops a match or is
> itself unmatched. Whatever remains on the stack at the end is the second kind of bad
> character. Delete exactly those two sets.**

This is minimal because each removed character is *individually* impossible: it has no
possible partner in any valid rearrangement (and we may not reorder). So no valid result can
keep it, and we keep everything else.

That minimality argument is the thing to say - "greedy" without justification is weaker.

### Contrast with 4.5

| | 4.5 Valid Parentheses | 4.14 this problem |
|---|---|---|
| Stack holds | characters | **indices** |
| On a bad closer | return `False` immediately | **mark it and continue** |
| At the end | `return not stack` | **mark everything left on the stack** |

The move from "fail fast" to "record and continue" is the whole upgrade, and storing indices
is what makes the marking possible.

### The two-pass, O(1)-space alternative

Worth knowing because the follow-up usually asks for it:

- **Pass 1, left to right**: keep a counter; drop any `)` that would make it negative. This
  removes exactly the first kind of bad character.
- **Pass 2, right to left** on the survivors: the surplus `(` are now exactly the **last**
  `open - close` of them, so drop from the right.

No stack, `O(1)` extra space beyond the output.

## 4. Approach

1. `chars = list(s)`; `stack = []`.
2. For each `i`, `ch`:
   - `(` -> `stack.append(i)`
   - `)` -> if `stack`, `stack.pop()`; else `chars[i] = ""`
3. For each leftover index in `stack`: `chars[index] = ""`.
4. Return `"".join(chars)`.

Blanking with `""` rather than deleting avoids shifting indices mid-scan.

## 5. Solution

```python
def min_remove_to_make_valid(s):
    """Remove the fewest parentheses to make s valid; letters are never removed.

    Two kinds of parenthesis are impossible in any valid result: a ')' with nothing
    open to its left, and a '(' still unmatched at the end. The stack of indices
    identifies both. Every other character is part of a matched pair, so keeping
    them all is minimal.
    """
    chars = list(s)
    stack = []                      # indices of '(' still waiting for a match

    for i, ch in enumerate(chars):
        if ch == "(":
            stack.append(i)
        elif ch == ")":
            if stack:
                stack.pop()         # matched
            else:
                chars[i] = ""       # unmatched closer: blank it out

    # Anything still open at the end can never be closed.
    for index in stack:
        chars[index] = ""

    return "".join(chars)
```

```python
min_remove_to_make_valid("lee(t(c)o)de)")   # 'lee(t(c)o)de'
min_remove_to_make_valid("a)b(c)d")         # 'ab(c)d'
min_remove_to_make_valid("))((")            # ''
min_remove_to_make_valid("")                # ''
min_remove_to_make_valid("abc")             # 'abc'
min_remove_to_make_valid("(a(b(c)d)")       # 'a(b(c)d)'
min_remove_to_make_valid("((((")            # ''
min_remove_to_make_valid("))))")            # ''
min_remove_to_make_valid("()")              # '()'
min_remove_to_make_valid("(()")             # '()'
min_remove_to_make_valid("())")             # '()'
```

`"(a(b(c)d)"` -> `"a(b(c)d)"` is the one to trace. There are three `(` and two `)`, so
exactly one opener must go; the stack finds that the **first** `(` is the unmatched one and
removes it, leaving the two later pairs intact. It shows the stack identifies a specific
position rather than just counting.

`"(()"` -> `"()"` and `"())"` -> `"()"` are the minimal pair worth running - one removal each,
one from each of the two categories.

### The O(1)-space two-pass version

```python
def min_remove_two_pass(s):
    """No stack. Pass 1 drops closers that would go negative; pass 2 drops the
    surplus openers from the right. O(1) extra space beyond the output."""
    # Pass 1: left to right, drop unmatched ')'.
    kept = []
    open_count = 0
    for ch in s:
        if ch == "(":
            open_count += 1
        elif ch == ")":
            if open_count == 0:
                continue            # nothing to match: drop it
            open_count -= 1
        kept.append(ch)

    # Pass 2: right to left, drop the surplus '(' - the LAST `open_count` of them.
    result = []
    surplus = open_count
    for ch in reversed(kept):
        if ch == "(" and surplus > 0:
            surplus -= 1
            continue
        result.append(ch)

    return "".join(reversed(result))


min_remove_two_pass("lee(t(c)o)de)")    # 'lee(t(c)o)de'
min_remove_two_pass("a)b(c)d")          # 'ab(c)d'
min_remove_two_pass("))((")             # ''
min_remove_two_pass("(a(b(c)d)")        # '(a(bc)d)'
min_remove_two_pass("(()")              # '()'
min_remove_two_pass("())")              # '()'
min_remove_two_pass("")                 # ''
```

Note this version removes the **last** surplus `(` rather than the first, so it can produce
a different string from the stack version. On `"(a(b(c)d)"` they genuinely diverge:

| version | output | length |
|---|---|---|
| stack of indices | `'a(b(c)d)'` | 8 |
| two-pass counter | `'(a(bc)d)'` | 8 |

Both are valid and both removed exactly one character, so both are correct - **the problem
permits any valid answer**. If an interviewer's expected output differs from yours, this is
the sentence to reach for, after checking your result really is valid and the same length.

### Counting the removals

```python
def count_removals(s):
    """How many parentheses must be removed - the minimum, without building the result."""
    open_unmatched = 0
    close_unmatched = 0
    for ch in s:
        if ch == "(":
            open_unmatched += 1
        elif ch == ")":
            if open_unmatched:
                open_unmatched -= 1
            else:
                close_unmatched += 1
    return open_unmatched + close_unmatched


count_removals("lee(t(c)o)de)")     # 1
count_removals("))((")              # 4
count_removals("(a(b(c)d)")         # 1
count_removals("abc")               # 0
```

This is LC 921 *Minimum Add to Make Parentheses Valid* with "add" replaced by "remove" - the
count is identical, which is a nice observation to offer.

## 6. Complexity

| | Time | Space |
|---|---|---|
| **Stack of indices** | **`O(n)`** | `O(n)` for the stack and the char list |
| **Two-pass counter** | **`O(n)`** | `O(1)` extra beyond the output |
| Count only | `O(n)` | `O(1)` |

The output is `O(n)` either way, so the two-pass version's advantage is the `O(n)` stack, not
the result. Worth stating precisely rather than claiming `O(1)` total.

## 7. How to present it

1. **Restate**, and confirm **any** valid answer is acceptable. That freedom is what licenses
   the greedy, so get it explicitly.
2. **Characterise the bad characters** before touching code: *"Only two things can be wrong -
   a closer with nothing open, and an opener never closed. Everything else is in a matched
   pair."*
3. **Give the minimality argument**: *"each character I remove has no possible partner
   anywhere, so no valid result could keep it - therefore removing exactly those is
   minimal."* This is the scoring sentence; do not just say "greedy".
4. **Connect to 4.5**: *"same scan as Valid Parentheses, but instead of failing on a bad
   closer I record its index and carry on, and the stack holds indices so I can mark the
   leftovers."*
5. **Announce**, then write it. Explain blanking with `""` rather than deleting: *"deleting
   would shift the indices I still have on the stack."*
6. **Test** `"(()"`, `"())"`, `"))(("`, and the letters-only case.
7. **Close**: `O(n)` time and space - then **offer the two-pass version** for `O(1)` extra
   space, and mention that it may produce a different (equally valid) string.

## 8. Follow-ups and variations

- **"Do it in O(1) extra space."** The two-pass counter version. Note the output is still
  `O(n)`.
- **"Minimum Add to Make Parentheses Valid"** (LC 921). The same count, but you insert rather
  than delete. `count_removals` above is literally the answer.
- **"Minimum Insertions to Balance a Parentheses String"** (LC 1541), where `)` must be
  doubled. Same counter idea with different arithmetic - a good test of whether you
  generalised.
- **"Remove Invalid Parentheses"** (LC 301) - return **all** distinct valid results with the
  minimum removals. Much harder: BFS by removal count, or DFS with careful deduplication.
  This is the natural "now make it hard" follow-up and is worth naming precisely.
- **"Longest Valid Parentheses"** (LC 32) - the longest valid *substring*. Stack of indices
  with a sentinel base, or DP. Different problem, same toolbox.
- **"What if there were several bracket types?"** A counter no longer suffices, but the
  index-stack version extends naturally: on a mismatched closer, mark it; keep per-type
  stacks or one stack of `(type, index)`.
- **"Check validity of a string with wildcards `*`"** (LC 678) - track a **range** of
  possible open counts rather than one number.
- **"Return the positions removed rather than the string."** The stack already has them.

## 9. Pitfalls

- **Deleting characters during the scan**, which shifts the indices held on the stack.
  Blank them out and join at the end.
- **Storing characters instead of indices**, so you cannot say *which* opener to remove.
- **Removing letters.** Only parentheses are ever removed.
- **Returning early on the first bad closer**, as in 4.5 - here you must continue.
- **Forgetting the leftover stack**, so unmatched openers survive. `"(()"` is the test.
- **Removing too much** - e.g. dropping every parenthesis when the string is unbalanced -
  which is valid but not minimal.
- **In the two-pass version, removing the surplus openers from the left** on the second pass.
  Both are valid outputs, but be deliberate about which you are doing.
- **Claiming `O(1)` total space** for the two-pass version; the output is `O(n)`.
