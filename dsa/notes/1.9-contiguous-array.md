**Difficulty:** Medium | **LeetCode #525**
**Bloomberg frequency:** 50% at three months.

The `+1/-1` transformation - the single most reusable trick in Part 1. Once you see it, a
whole family of "equal numbers of X and Y" problems collapses into "subarray summing to
zero".

## 1. Problem statement

Given a binary array `nums`, return the **maximum length** of a contiguous subarray with an
equal number of `0`s and `1`s.

```
nums = [0,1]        ->  2     [0,1] has one of each
nums = [0,1,0]      ->  2     [0,1] or [1,0]
nums = [0,1,1,1,0,0] -> 6     the whole array: three 0s and three 1s
```

## 2. Clarifying questions

1. **Contiguous subarray, not subsequence?** Contiguous.
2. **Strictly binary?** Only `0` and `1`.
3. **Length or the subarray itself?** Length. If they want the subarray, track the indices
   too - cheap.
4. **What if no such subarray exists?** Return `0`. `[0,0,0]` has no balanced subarray.
5. **Array size?** Up to 10^5, so `O(n^2)` will time out. Aim for linear.
6. **Can the whole array qualify?** Yes - example 3.

## 3. Intuition

The brute force checks every subarray and counts: `O(n^2)`.

Now the transformation. "Equal numbers of 0s and 1s" is awkward because it involves two
quantities. Replace each `0` with `-1`:

```
nums    =  [0,  1,  1,  1,  0,  0]
mapped  =  [-1, 1,  1,  1, -1, -1]
```

A subarray has equal counts of `0` and `1` **exactly when** the mapped values sum to zero -
because each `1` contributes `+1`, each `0` contributes `-1`, and they cancel one-for-one.

> **"Equal numbers of X and Y" becomes "sums to zero" under the `+1/-1` map.**

And "subarray summing to zero" is the prefix-sum identity from the primer:

```
sum(nums[i..j)) == 0      <=>      prefix[i] == prefix[j]
```

So: **find two positions with the same running sum, as far apart as possible.** Keep a map
from each running-sum value to the **earliest index** at which it occurred; when you see a
value again, the span between them is balanced.

### Earliest index, not a count

This is the one place to be careful, and it is the deliberate contrast with 1.2 Subarray
Sum Equals K. There you *counted* how many prefixes matched, because you wanted the number
of subarrays. Here you want the **longest** one, so you keep only the first occurrence of
each prefix value and never overwrite it - a later occurrence would only ever give a shorter
span.

Getting these two backwards is the classic error in this pattern. Say which you are doing
and why.

### The sentinel

Seed the map with `{0: -1}`: running sum `0` "occurred" at index `-1`, the empty prefix.
Without it, a balanced subarray starting at index 0 is missed. For `[0,1]` the running sum
returns to 0 at index 1, and `1 - (-1) == 2` is the correct answer; with no sentinel you
would get nothing.

## 4. Approach

1. `first_seen = {0: -1}` - running sum to its earliest index.
2. `running = 0`, `best = 0`.
3. For each index `i` with value `x`:
   - `running += 1 if x == 1 else -1`
   - if `running` is in `first_seen`: `best = max(best, i - first_seen[running])`
   - else: `first_seen[running] = i` **(only when absent)**
4. Return `best`.

## 5. Solution

```python
def find_max_length(nums):
    """Longest contiguous subarray with equal numbers of 0s and 1s.

    Map 0 -> -1, so 'equal counts' becomes 'sums to zero', which by the prefix-sum
    identity means two positions share the same running sum. Keep the EARLIEST index
    for each running sum, because that yields the longest span.
    """
    # Running sum 0 occurs at the empty prefix, index -1. Without this sentinel a
    # balanced subarray starting at index 0 is never found.
    first_seen = {0: -1}

    running = 0
    best = 0
    for i, x in enumerate(nums):
        running += 1 if x == 1 else -1

        if running in first_seen:
            # Same running sum seen before, so everything between cancels out.
            best = max(best, i - first_seen[running])
        else:
            # Record only the FIRST time, never overwrite - a later index is shorter.
            first_seen[running] = i

    return best
```

```python
find_max_length([0, 1])                     # 2
find_max_length([0, 1, 0])                  # 2
find_max_length([0, 1, 1, 1, 0, 0])         # 6
find_max_length([0, 0, 0])                  # 0
find_max_length([1, 1, 1, 1])               # 0
find_max_length([0, 0, 1, 0, 0, 0, 1, 1])   # 6
find_max_length([1, 0, 1, 0, 1])            # 4
find_max_length([])                         # 0
```

Trace `[0,1,1,1,0,0]`, which returns the whole array:

| i | x | running | in map? | action | best |
|---|---|---|---|---|---|
| - | - | 0 | - | seeded `{0: -1}` | 0 |
| 0 | 0 | -1 | no | record `-1 -> 0` | 0 |
| 1 | 1 | 0 | **yes** (at -1) | `1 - (-1) = 2` | 2 |
| 2 | 1 | 1 | no | record `1 -> 2` | 2 |
| 3 | 1 | 2 | no | record `2 -> 3` | 2 |
| 4 | 0 | 1 | **yes** (at 2) | `4 - 2 = 2` | 2 |
| 5 | 0 | 0 | **yes** (at -1) | `5 - (-1) = 6` | **6** |

The final row is the payoff of the sentinel, and the row at `i = 4` shows why you must not
overwrite `1 -> 2` with `1 -> 4`: doing so would have given a span of 0 there and, worse,
broken any later match.

### The brute force, to state first

```python
def find_max_length_brute(nums):
    """O(n^2): every subarray, with a running balance."""
    best = 0
    for i in range(len(nums)):
        balance = 0
        for j in range(i, len(nums)):
            balance += 1 if nums[j] == 1 else -1
            if balance == 0:
                best = max(best, j - i + 1)
    return best


find_max_length_brute([0, 1, 1, 1, 0, 0])   # 6
find_max_length_brute([0, 0, 0])            # 0
```

## 6. Complexity

| Approach | Time | Space |
|---|---|---|
| Brute force | `O(n^2)` | `O(1)` |
| Prefix sum + hash map | **`O(n)` average** | `O(n)` |

Space is `O(n)` because the running sum ranges over `[-n, n]`, so up to `2n + 1` distinct
values. If the interviewer pushes on space, note that you could use an **array of size
`2n+1`** indexed by `running + n` instead of a dict - same asymptotic space but no hashing,
and it removes the "average" qualifier from the time bound. That is a genuinely good answer.

## 7. How to present it

1. **Restate** and confirm contiguous, and that the answer is a length.
2. **State the brute force** and its `O(n^2)`.
3. **Make the transformation explicit on the board.** Write the array, write the mapped
   array underneath, and say: *"equal counts of 0 and 1 is the same as the mapped values
   summing to zero."* This is the insight and it deserves to be written, not just said.
4. **Connect to prefix sums**: "a subarray sums to zero exactly when the running sum at its
   two ends is equal - so I need two equal prefix values, as far apart as possible."
5. **Announce**: "One pass, a dict from running sum to its earliest index."
6. **As you write the `else`, say why it is an `else`**: *"I only record the first occurrence
   - overwriting would give me a shorter span."* Contrast with Subarray Sum Equals K where
   you count instead. This contrast is the best thing you can say on this question.
7. **Explain the `{0: -1}` sentinel** as you type it.
8. **Trace `[0,1,1,1,0,0]`** with the table above.
9. **Close**: `O(n)` / `O(n)`, and offer the array-instead-of-dict space refinement.

## 8. Follow-ups and variations

- **"Return the subarray, not its length."** Track the best start index alongside `best`.
- **"Equal numbers of 0s, 1s and 2s."** The single running sum no longer suffices. Use a
  **tuple key** of the pairwise differences, e.g. `(count1 - count0, count2 - count0)`, and
  look for a repeated tuple. Same idea, one more dimension - a strong follow-up answer.
- **"Longest subarray summing to k"** (LC 325). Identical structure: `first_seen` keyed by
  running sum, look up `running - k`, keep earliest indices.
- **"Count the balanced subarrays instead of the longest."** Now switch to a **counting** map
  (`defaultdict(int)` seeded with `{0: 1}`) and accumulate - this is 1.2 exactly. Being able
  to state both versions and when each applies is the point of this pair of questions.
- **"Contiguous subarray with equal numbers of 0s and 1s, but 0s count double."** Map `0` to
  `-2`; the method is unchanged, which shows the transformation is the general tool.
- **"Subarray sum divisible by k"** (LC 974). Key on `running % k`.
- **"What if the array is a stream?"** Works as-is - one pass, no lookback - but memory grows
  with the number of distinct running sums.
- **"Reduce space below O(n)."** Use the `2n+1` array. True `O(1)` is not possible: you must
  remember where each running-sum value was first seen.

## 9. Pitfalls

- **Overwriting `first_seen[running]`** with a later index, which silently shortens answers.
  The `else` is load-bearing.
- **Forgetting the `{0: -1}` sentinel**, missing any balanced subarray that starts at index 0.
  `[0,1]` returns 0 instead of 2.
- **Seeding with `{0: 0}` instead of `{0: -1}`**, which is off by one in every span.
- **Counting instead of keeping earliest indices** - that answers a different question.
- **Mapping `0` to `0`** rather than `-1`, so nothing ever cancels.
- **Using `defaultdict(int)`**, which makes `running in first_seen` behave oddly and quietly
  records index 0 for everything. Use a plain `dict` with an explicit membership test.
- **Returning the running sum or an index** instead of the length.
- **Confusing this with 1.2** and reaching for the counting map. Both are prefix-sum-plus-map;
  the difference is *earliest index* versus *count*.
