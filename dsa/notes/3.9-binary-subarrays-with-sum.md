**Difficulty:** Medium | **LeetCode #930**
**Bloomberg frequency:** 38% at three months.

The best question in the course for understanding the **at-most-K trick** and the
**counting idiom**. It is also the one place where the Part 1 approach (prefix sums plus a
hash map) and the Part 3 approach (sliding window) are both valid, so it is ideal for
demonstrating that you know which tool applies and why.

## 1. Problem statement

Given a **binary** array `nums` and an integer `goal`, return the number of **non-empty
subarrays** with a sum equal to `goal`.

A subarray is a contiguous part of the array.

```
nums = [1,0,1,0,1], goal = 2  ->  4
    the subarrays are [1,0,1]_0..2, [1,0,1,0]_0..3, [0,1,0,1]_1..4, [1,0,1]_2..4

nums = [0,0,0,0,0], goal = 0  ->  15
```

## 2. Clarifying questions

1. **Binary, so only 0s and 1s?** Yes - and that means all values are **non-negative**, which
   is what permits a sliding window. Say this; it is the hinge of the problem.
2. **Count the subarrays, or list them?** Count. Listing could be `O(n^2)`.
3. **Can `goal` be 0?** Yes - example 2, and it is the tricky case. `[0,0,0,0,0]` has
   `5*6/2 = 15` non-empty subarrays, all summing to 0.
4. **Non-empty subarrays only?** Yes.
5. **Sizes?** Up to 3·10^4, so `O(n^2)` is borderline and `O(n)` is expected.

## 3. Intuition

Two genuinely different solutions. Know both and be able to say when each applies.

### (a) Prefix sums plus a hash map - the Part 1 approach

`sum(i..j) == goal` becomes `prefix[j] - prefix[i] == goal`, so count how many earlier
prefixes equal `prefix[j] - goal`. This is **exactly 1.2 Subarray Sum Equals K**, and it
works for **any** values, negative included.

```
counts = {0: 1}; running = 0; total = 0
for x in nums:
    running += x
    total += counts[running - goal]
    counts[running] += 1
```

Say up front: *"this is just Subarray Sum Equals K - I can reuse that directly."*

### (b) Sliding window with the at-most trick - the Part 3 approach

A window cannot directly count subarrays with sum **exactly** `goal`, because "sum equals
goal" is not monotonic in the window size - growing past a `1` overshoots, but growing past
a `0` does not, so there is no single shrink rule.

But **at most `goal`** *is* monotonic when values are non-negative. So:

> **exactly(goal) = atMost(goal) - atMost(goal - 1)**

And inside `atMost`, the **counting idiom**:

> **`total += right - left + 1`** - every subarray ending at `right` and starting anywhere
> from `left` to `right` is valid, and there are `right - left + 1` of them.

That one line is what turns a "longest window" into a "how many windows", and it is the
single most transferable idea in this note.

### Which to present

Lead with (a) because it is shorter and more general, then offer (b) because it demonstrates
the window machinery and uses `O(1)` space. Explicitly note that (b) **only works because
the values are non-negative** - which is precisely the distinction 1.2 is built to teach.

## 4. Approach

**Prefix + map:** one pass, `counts` seeded with `{0: 1}`, `total += counts[running - goal]`
before recording.

**At-most window:**
1. `at_most(limit)`: standard window; grow right adding to `total`; while `total > limit`,
   shrink; `count += right - left + 1`.
2. Answer is `at_most(goal) - at_most(goal - 1)`.
3. Guard `goal = 0`, where `at_most(-1)` must return 0 - the loop handles it naturally, since
   the window shrinks to empty and `right - left + 1` becomes 0.

## 5. Solution

```python
from collections import defaultdict


def num_subarrays_with_sum(nums, goal):
    """Number of subarrays summing to goal, via prefix sums and a hash map.

    Identical to Subarray Sum Equals K: prefix[j] - prefix[i] == goal means the
    number of subarrays ending at j is the count of earlier prefixes equal to
    running - goal. Works for any values, not only binary ones.
    """
    counts = defaultdict(int)
    counts[0] = 1               # the empty prefix
    running = 0
    total = 0

    for x in nums:
        running += x
        total += counts[running - goal]     # counted before recording
        counts[running] += 1

    return total
```

```python
num_subarrays_with_sum([1, 0, 1, 0, 1], 2)      # 4
num_subarrays_with_sum([0, 0, 0, 0, 0], 0)      # 15
num_subarrays_with_sum([1, 1, 1], 2)            # 2
num_subarrays_with_sum([0, 1, 0], 1)            # 4
num_subarrays_with_sum([], 0)                   # 0
num_subarrays_with_sum([1], 0)                  # 0
num_subarrays_with_sum([0], 0)                  # 1
num_subarrays_with_sum([1, 0, 1], 0)            # 1
```

`[0,1,0]` with `goal = 1` giving **4** is the case to work through: the subarrays are
`[1]`, `[0,1]`, `[1,0]` and `[0,1,0]`. The surrounding zeros multiply the count, which is
exactly why the answer is larger than intuition suggests.

### The sliding-window version

```python
def num_subarrays_with_sum_window(nums, goal):
    """exactly(goal) = atMost(goal) - atMost(goal - 1).

    'At most' is monotonic in the window size because the values are non-negative;
    'exactly' is not, which is why the subtraction is needed.
    """
    def at_most(limit):
        if limit < 0:
            return 0
        left = 0
        total = 0
        count = 0
        for right, x in enumerate(nums):
            total += x
            while total > limit:
                total -= nums[left]
                left += 1
            # Every subarray ending at `right` and starting at left..right is valid.
            count += right - left + 1
        return count

    return at_most(goal) - at_most(goal - 1)


num_subarrays_with_sum_window([1, 0, 1, 0, 1], 2)   # 4
num_subarrays_with_sum_window([0, 0, 0, 0, 0], 0)   # 15
num_subarrays_with_sum_window([1, 1, 1], 2)         # 2
num_subarrays_with_sum_window([0, 1, 0], 1)         # 4
num_subarrays_with_sum_window([1], 0)               # 0
num_subarrays_with_sum_window([0], 0)               # 1
num_subarrays_with_sum_window([], 0)                # 0
```

The explicit `if limit < 0: return 0` guard makes the `goal = 0` case obvious. Without it the
loop still returns 0, because `total > limit` is always true and the window shrinks to
`left = right + 1`, making `right - left + 1` equal 0 - but relying on that is subtle, so
guard it and say why.

### The brute force

```python
def num_subarrays_with_sum_brute(nums, goal):
    """O(n^2) with a running inner sum."""
    total = 0
    for i in range(len(nums)):
        running = 0
        for j in range(i, len(nums)):
            running += nums[j]
            if running == goal:
                total += 1
    return total


num_subarrays_with_sum_brute([1, 0, 1, 0, 1], 2)    # 4
num_subarrays_with_sum_brute([0, 0, 0, 0, 0], 0)    # 15
num_subarrays_with_sum_brute([0, 1, 0], 1)          # 4
```

## 6. Complexity

| | Time | Space |
|---|---|---|
| Brute force | `O(n^2)` | `O(1)` |
| Prefix sums + hash map | `O(n)` average | `O(n)` |
| **At-most sliding window** | **`O(n)`** | **`O(1)`** |

The window version wins on space - `O(1)` versus `O(n)` - and it is deterministic rather than
average-case, since it does not hash. That is a real argument for it and worth stating, since
otherwise the prefix-sum version looks strictly simpler.

The window runs twice over the array, so `2n` steps - still `O(n)`.

## 7. How to present it

1. **Restate**, confirm counting rather than listing, and confirm `goal` can be 0.
2. **Note that the array is binary**, hence all values are non-negative - *"which matters,
   because it means a sliding window is valid here."*
3. **Give the prefix-sum solution immediately** and name it: *"this is Subarray Sum Equals K;
   I can count prefixes equal to `running - goal`."* Write it - six lines.
4. **Then offer the window version** and explain why it is not the obvious first choice:
   *"'Sum exactly goal' isn't monotonic in the window size, so a single window can't express
   it. But 'at most goal' is, so I compute at-most(goal) minus at-most(goal-1)."*
5. **Explain the counting idiom** as you write it: *"once the window is valid, every subarray
   ending here and starting anywhere from `left` onwards is valid - that's `right - left + 1`
   of them."*
6. **Contrast the two**: prefix sums work with negatives and cost `O(n)` space; the window
   needs non-negativity but costs `O(1)`. That comparison is the best thing you can say here.
7. **Test** `goal = 0` on `[0,0,0,0,0]` (15) and the `[0,1,0]` case (4).
8. **Close**: both `O(n)`; pick the window if space matters, the prefix map if values might
   go negative.

## 8. Follow-ups and variations

- **"What if the values were not binary - say arbitrary non-negative integers?"** Both
  solutions still work unchanged. Good check that you understood the actual precondition.
- **"What if values can be negative?"** The window breaks; only the prefix-sum version
  survives. This is 1.2 exactly.
- **"Subarrays with exactly k distinct values"** (LC 992). Same at-most trick, different
  invariant (`len(counts) > k` instead of `total > limit`).
- **"Count subarrays with sum at most goal."** Just `at_most(goal)` - and note it is the
  easier half of what you already wrote.
- **"Number of subarrays with at most k odd numbers"** (LC 1248, *Count Number of Nice
  Subarrays*). Map odd to 1, even to 0, and it becomes this exact problem.
- **"Return the subarrays."** Output can be `O(n^2)`; output-bound.
- **"Longest subarray with sum equal to goal."** A different question - prefix map storing
  the **earliest** index, as in 1.9. Note the contrast: counting needs counts, longest needs
  earliest indices.
- **"2D version."** Fix a row pair, compress, and run this - `O(rows^2 * cols)`.

## 9. Pitfalls

- **Trying to use a single window for "exactly goal"** without the at-most subtraction. It
  cannot work, and saying why is worth credit.
- **Forgetting `counts[0] = 1`** in the prefix version, missing subarrays that start at
  index 0.
- **Mishandling `goal = 0`** - `at_most(-1)` must be 0.
- **Recording `counts[running] += 1` before the lookup**, which counts a phantom empty
  subarray when `goal == 0`.
- **Using `right - left` instead of `right - left + 1`** in the counting idiom.
- **Applying the window to arrays with negative values.**
- **Counting subarrays with `<=` instead of `==`** and forgetting the subtraction.
- **Claiming `O(n)` space is required.** The window version is `O(1)`.
