title: "2.15 Rearrange Array Elements by Sign"
---

**Link:** https://leetcode.com/problems/rearrange-array-elements-by-sign
**Difficulty:** Medium | **LeetCode #2149**
**Bloomberg frequency:** 38% at three months.

A two-pointer question whose difficulty lives entirely in the **guarantees you are given**.
With the equal-count guarantee it is a clean one-pass fill; without it, it becomes a
genuinely harder problem. Recognising that distinction is the interview.

## 1. Problem statement

You are given a **0-indexed** integer array `nums` of **even** length, consisting of an
**equal** number of positive and negative integers.

Rearrange it so that:
1. Every **consecutive pair** has opposite signs.
2. For all integers with the same sign, the **order in which they appeared is preserved**.
3. The rearranged array begins with a **positive** integer.

```
nums = [3,1,-2,-5,2,-4]  ->  [3,-2,1,-5,2,-4]
nums = [-1,1]            ->  [1,-1]
```

## 2. Clarifying questions

1. **Are the counts of positives and negatives guaranteed equal?** Yes - and this is the
   guarantee that makes the problem easy. **Ask explicitly**, because without it the answer
   changes completely (see the follow-ups).
2. **Must the relative order within each sign be preserved?** Yes. This rules out any
   swap-based in-place partition, which is the trap.
3. **Does it start with a positive?** Yes, always.
4. **Are zeros possible?** The constraints say non-zero. Ask, because `0` has no sign and
   would need a rule.
5. **May I allocate an output array?** The natural solution does. A true `O(1)`-space
   solution preserving order is much harder - see the follow-ups.
6. **Is the length guaranteed even?** Yes, implied by the equal counts.

## 3. Intuition

Because the counts are equal and the result starts positive, the output pattern is fixed:

```
index:  0    1    2    3    4    5
sign:   +    -    +    -    +    -
```

Positives go to the **even** indices in their original order; negatives go to the **odd**
indices in their original order.

> **The destination of each element is determined by its sign and by how many of that sign
> you have already placed. So one pass with two write pointers is enough.**

Keep `pos = 0` and `neg = 1`. For each element, write it to `result[pos]` or `result[neg]`
and advance that pointer by **two**.

That is it. The order-preservation requirement is satisfied automatically, because you visit
the input left to right and each sign's write pointer only moves forward.

### Why not swap in place?

The tempting `O(1)`-space idea is to partition in place, like Dutch national flag. But
**partitioning is not stable** - moving an element to its side disturbs the relative order of
the others. Requirement 2 explicitly forbids that, so the swap approach is simply wrong here.

Say this out loud. "Order must be preserved, so I can't do an in-place partition - I'll use
an output array" is the correct trade and shows you read the constraint.

## 4. Approach

1. `result = [0] * n`.
2. `pos, neg = 0, 1`.
3. For each `x` in `nums`:
   - if `x > 0`: `result[pos] = x`, `pos += 2`
   - else: `result[neg] = x`, `neg += 2`
4. Return `result`.

## 5. Solution

```python
def rearrange_array(nums):
    """Alternate signs starting positive, preserving each sign's relative order.

    With equal counts guaranteed, every element's destination is determined: positives
    fill the even indices in order, negatives fill the odd indices in order. One pass,
    two write pointers.
    """
    result = [0] * len(nums)
    pos, neg = 0, 1             # next free even slot, next free odd slot

    for x in nums:
        if x > 0:
            result[pos] = x
            pos += 2
        else:
            result[neg] = x
            neg += 2

    return result
```

```python
rearrange_array([3, 1, -2, -5, 2, -4])      # [3, -2, 1, -5, 2, -4]
rearrange_array([-1, 1])                    # [1, -1]
rearrange_array([1, -1])                    # [1, -1]
rearrange_array([])                         # []
rearrange_array([1, 2, -3, -4])             # [1, -3, 2, -4]
rearrange_array([-1, -2, 3, 4])             # [3, -1, 4, -2]
```

`[-1,-2,3,4]` is worth narrating: the negatives come first in the input but the output must
start positive, and the relative order within each sign is preserved - `3` before `4`, `-1`
before `-2`. It confirms both requirements at once.

### Splitting into two lists, for comparison

```python
def rearrange_array_two_lists(nums):
    """Equivalent, and arguably clearer: separate, then interleave."""
    positives = [x for x in nums if x > 0]
    negatives = [x for x in nums if x < 0]
    result = []
    for p, q in zip(positives, negatives):
        result.append(p)
        result.append(q)
    return result


rearrange_array_two_lists([3, 1, -2, -5, 2, -4])    # [3, -2, 1, -5, 2, -4]
rearrange_array_two_lists([-1, 1])                  # [1, -1]
rearrange_array_two_lists([])                       # []
```

Same `O(n)` time and space, two passes instead of one, and it makes the structure obvious.
Either is a fine answer; the two-pointer version is one pass and does not build intermediate
lists, so prefer it and mention this one as the readable alternative.

Note that `zip` truncates to the shorter list, which **silently drops elements** if the
counts are not equal. That is fine under the guarantee and dangerous without it - a good
reason to ask the clarifying question.

## 6. Complexity

| | Time | Space |
|---|---|---|
| **Two write pointers** | **`O(n)`** | `O(n)` output, `O(1)` extra |
| Split then interleave | `O(n)` | `O(n)` output plus `O(n)` intermediates |
| In-place stable rearrange | `O(n log n)` or `O(n^2)` | `O(1)` |

One pass, and each output slot is written exactly once. The output array is required, so
`O(1)` *auxiliary* space is the honest claim - but note that a genuine `O(1)`-total-space
solution is not achievable in linear time while preserving order.

## 7. How to present it

1. **Restate all three requirements**, and note that requirement 2 (order preservation) is
   the one that constrains the approach.
2. **Ask about the equal-count guarantee.** Then say what it buys you: *"Given equal counts
   and a positive start, the sign at every output index is fixed - positives go to even
   indices, negatives to odd."* That sentence is the solution.
3. **Reject the in-place swap explicitly**: "An in-place partition would be `O(1)` space, but
   partitioning isn't stable and the problem requires preserving order within each sign - so
   I'll use an output array."
4. **Announce** the two write pointers stepping by two.
5. **Write it.** It is seven lines.
6. **Test** `[-1,-2,3,4]`, which exercises both the "starts negative in the input" case and
   order preservation.
7. **Close**: `O(n)` time, `O(1)` auxiliary space - then **volunteer the harder version**:
   "If the counts weren't equal, this breaks, and the problem gets considerably harder."
   That invites the follow-up you are prepared for.

## 8. Follow-ups and variations

- **"What if the counts are NOT equal?"** The main follow-up, and a genuinely different
  problem. The usual rule becomes: alternate as long as both signs remain, then append the
  remainder of whichever is left. The fixed even/odd mapping no longer works, so you fall
  back to two lists and a merge:
  ```python
  def rearrange_unequal(nums):
      """Alternate while both signs remain, then append the leftover run."""
      positives = [x for x in nums if x > 0]
      negatives = [x for x in nums if x < 0]
      result = []
      i = j = 0
      while i < len(positives) and j < len(negatives):
          result.append(positives[i])
          result.append(negatives[j])
          i += 1
          j += 1
      result.extend(positives[i:])
      result.extend(negatives[j:])
      return result


  rearrange_unequal([1, 2, 3, -1])        # [1, -1, 2, 3]
  rearrange_unequal([-1, -2, -3, 1])      # [1, -1, -2, -3]
  rearrange_unequal([1, 2, 3])            # [1, 2, 3]
  ```
  **Confirm the intended rule first** - "append the leftovers" is only one possible
  specification, and the interviewer may want something else.
- **"Do it with O(1) extra space, preserving order."** This is stable in-place partitioning,
  which is hard: the standard solutions are an `O(n log n)` divide-and-conquer with rotations,
  or an `O(n^2)` insertion-style shift. Name them and say that the linear-time stable version
  needs `O(n)` space - that is a real theoretical boundary, not a gap in your knowledge.
- **"What if zeros are allowed?"** They have no sign; ask where they go. Any rule is
  implementable, but the question has no default answer.
- **"Start with a negative instead."** Swap the initial pointers to `pos = 1, neg = 0`.
- **"Rearrange by some predicate rather than sign."** Identical code with `predicate(x)` in
  place of `x > 0`.
- **"Sort by parity"** (LC 905) - same shape, and there order does **not** need preserving,
  so the in-place two-pointer swap is allowed. The contrast between the two problems is the
  best way to remember why stability matters.

## 9. Pitfalls

- **Swapping in place**, breaking the order-preservation requirement.
- **Starting `neg` at 0** or both pointers at 0.
- **Incrementing by 1 instead of 2.**
- **Using `zip` on unequal-length lists** and silently dropping elements - safe here only
  because of the guarantee.
- **Treating `0` as positive** without asking.
- **Assuming the input starts with a positive.** It need not; only the *output* must.
- **Claiming `O(1)` space** while allocating the output - say *auxiliary*.
- **Not noticing that the equal-count guarantee is doing the work**, and therefore having
  nothing to say when the follow-up removes it.
