---
title: "23.19 Chess board: add a bishop only if no bishop attacks that cell"
---

> Reported once in R1 on 2025-11-18. A small design question: the naive answer is obvious
> and `O(n)`, and the whole interview is getting to `O(1)` by finding the right key.

## Prompt as given

```
You are given a chess board and add_bishop(row, col) is called on it. You add a bishop on
that cell, but you must return False if there is already another bishop along either of the
two diagonals passing through that cell.
```

Follow-up as given: *instead of returning a boolean, return the cell of the existing bishop.*

Related: [N-Queens](https://leetcode.com/problems/n-queens/) - the diagonal-indexing trick
is the same one.

## Clarifying questions to ask first

1. **Do other bishops block the line of sight?** On a real board a bishop between two others
   blocks the attack. The prompt says "if there are other bishops along the two diagonals",
   which reads as *any* bishop on the diagonal, blocked or not. **Ask** - it changes the
   answer from `O(1)` to needing an ordered structure.
2. **Board size - fixed 8x8, or n x n?** If it is 8x8, everything is `O(1)` trivially and the
   question is not interesting; assume `n x n` (or unbounded) and say so.
3. **What happens when the placement fails - is the bishop still added?** No: return False
   and leave the board unchanged.
4. **Can the same cell be added twice?** Return False.
5. **Is there a `remove_bishop`?** Ask - it decides between a `set` of occupied diagonals and
   a `dict`/counter.
6. **Do I need the attacking bishop's identity?** That is the follow-up; ask early so you
   store the cell rather than just a flag from the start.

## Intuition

The naive approach walks the four diagonal rays from the cell, `O(n)` per call.

The trick that makes it `O(1)` is the standard chess-diagonal indexing:

> **Every cell on the same "down-right" diagonal has the same `row - col`.
> Every cell on the same "down-left" diagonal has the same `row + col`.**

Check it: `(0,0)`, `(1,1)`, `(2,2)` all have `row - col == 0`. And `(0,2)`, `(1,1)`, `(2,0)`
all have `row + col == 2`.

So a bishop at `(r, c)` attacks exactly the cells sharing its `r - c` or its `r + c`. Keep
two dictionaries keyed by those two values, and the whole question becomes two hash lookups.

That is the entire insight, and it is worth drawing a small grid with the two values written
in each cell - it makes the claim self-evident and takes twenty seconds.

Since the follow-up asks for the *cell* of the blocking bishop, store the cell as the value
rather than using a set. Costs nothing, and you get the follow-up for free.

## Approach

1. `self.diag`: `dict[row - col] -> (row, col)` of the bishop occupying that diagonal.
2. `self.anti`: `dict[row + col] -> (row, col)`.
3. `add_bishop(r, c)`: if `r - c` or `r + c` is present, return the stored cell (or False).
   Otherwise record the cell in both dicts and return True.

## Solution

```python
class BishopBoard:
    """Place bishops, rejecting any placement attacked by an existing bishop.

    Two cells share a down-right diagonal iff row - col is equal,
    and share a down-left (anti) diagonal iff row + col is equal.
    So each check is two dictionary lookups rather than a walk along the board.
    """

    def __init__(self, size=8):
        self.size = size
        self.diag = {}        # row - col  -> the (row, col) of the bishop on it
        self.anti = {}        # row + col  -> the (row, col) of the bishop on it
        self.bishops = set()

    def add_bishop(self, row, col):
        """True if the bishop was placed, False if some existing bishop attacks the cell."""
        if not (0 <= row < self.size and 0 <= col < self.size):
            raise ValueError(f"({row}, {col}) is off the board")
        if (row, col) in self.bishops:
            return False

        if row - col in self.diag or row + col in self.anti:
            return False

        self.diag[row - col] = (row, col)
        self.anti[row + col] = (row, col)
        self.bishops.add((row, col))
        return True

    def attacker(self, row, col):
        """Follow-up: the cell of an existing bishop attacking (row, col), or None."""
        return self.diag.get(row - col) or self.anti.get(row + col)

    def add_bishop_or_attacker(self, row, col):
        """Follow-up form: returns (True, None) on success, or (False, attacking_cell)."""
        blocker = self.attacker(row, col)
        if blocker is not None:
            return False, blocker
        self.add_bishop(row, col)
        return True, None
```

```python
b = BishopBoard(8)

b.add_bishop(0, 0)     # True    r-c= 0, r+c=0;  board was empty
b.add_bishop(2, 2)     # False   r-c= 0, r+c=4;  (0,0) owns diagonal 0
b.add_bishop(1, 3)     # True    r-c=-2, r+c=4;  neither -2 nor 4 taken yet
b.add_bishop(3, 1)     # False   r-c= 2, r+c=4;  (1,3) owns anti-diagonal 4
b.add_bishop(0, 5)     # True    r-c=-5, r+c=5
b.add_bishop(4, 4)     # False   r-c= 0, r+c=8;  (0,0) again
```

Follow-up form on the same board state:

```python
b2 = BishopBoard(8)
b2.add_bishop(0, 0)
b2.add_bishop(1, 3)

b2.add_bishop_or_attacker(3, 1)   # (False, (1, 3))   blocked on the anti-diagonal
b2.add_bishop_or_attacker(2, 2)   # (False, (0, 0))   blocked on the main diagonal
b2.add_bishop_or_attacker(0, 5)   # (True, None)      placed
```

The `(1,3)` line is the one to check slowly. It has `row - col == -2` and `row + col == 4`,
and after `(0,0)` only diagonal `0` and anti-diagonal `0` are taken - so it **succeeds**,
even though it looks like it ought to clash. Then `(3,1)` shares anti-diagonal `4` with it
and fails. Writing both key values next to each placement, as above, is how you avoid
asserting a result you have not actually checked.

### If bishops DO block line of sight

Then "is there a bishop on my diagonal" is not enough - you need the *nearest* one in each of
the four directions, and whether anything sits between. Keep a **sorted list per diagonal**
and binary search for the neighbours:

```python
import bisect
from collections import defaultdict


class BishopBoardBlocking:
    """Variant where a bishop between two others blocks the attack, so only the
    nearest bishop in each of the four directions matters.

    Cells on one diagonal are totally ordered by row, so a sorted list per diagonal
    plus a binary search finds the immediate neighbours in O(log n).
    """

    def __init__(self, size=8):
        self.size = size
        self.diag = defaultdict(list)     # row - col -> sorted list of rows
        self.anti = defaultdict(list)     # row + col -> sorted list of rows

    def _neighbours(self, line, row):
        """The nearest occupied rows below and above `row` on this diagonal."""
        i = bisect.bisect_left(line, row)
        before = line[i - 1] if i > 0 else None
        after = line[i] if i < len(line) else None
        return before, after

    def attacker(self, row, col):
        for line, key in ((self.diag, row - col), (self.anti, row + col)):
            before, after = self._neighbours(line[key], row)
            for r in (before, after):
                if r is not None:
                    # Recover the column from the diagonal identity.
                    c = r - (row - col) if line is self.diag else (row + col) - r
                    return (r, c)
        return None

    def add_bishop(self, row, col):
        if self.attacker(row, col) is not None:
            return False
        bisect.insort(self.diag[row - col], row)
        bisect.insort(self.anti[row + col], row)
        return True
```

Note that with *no* blocking, "nearest neighbour exists" and "any bishop exists" are the same
condition, so this version is a strict generalisation - it just costs `O(log n)` instead of
`O(1)`. Offer it when you ask the blocking question.

## Complexity

| | `add_bishop` | space |
|---|---|---|
| Walk the four rays | `O(n)` | `O(bishops)` |
| Two diagonal dicts (no blocking) | `O(1)` average | `O(bishops)` |
| Sorted list per diagonal (blocking) | `O(log n)` search, `O(n)` insert (list shift) | `O(bishops)` |

For the blocking variant, `bisect.insort` is `O(n)` because of the list shift; if insert cost
matters, a balanced BST or skip list per diagonal gives `O(log n)`. Worth one sentence.

## How to present it

1. **Draw a 4x4 grid and write `r-c` in each cell, then `r+c`.** The two diagonal families
   become visually obvious and you have justified the key without any algebra.
2. **State the naive `O(n)` ray walk** and its cost, so the improvement has something to
   improve on.
3. **State the key**: "two cells are on the same diagonal exactly when `r-c` matches, or
   `r+c` matches - so I can index diagonals directly."
4. **Ask the blocking question** before coding. It is the one genuine ambiguity, and asking
   it shows you know how bishops actually move.
5. **Ask whether they will want the attacking bishop**, and store cells rather than booleans
   from the start. Then the follow-up costs you nothing.
6. **Code it**, then **trace two or three placements out loud**, including one rejection.
7. **Mention `remove_bishop`** and what would change (dicts of sets, or counters).

## Follow-ups and variations

- **"Return the cell of the existing bishop instead of a boolean."** The stated follow-up -
  already handled by storing the cell as the dictionary value. Say that you chose the value
  type with this in mind.
- **"Make `add_bishop` O(1)."** The two-dict solution. If they ask "why is that O(1)?", it is
  two hash lookups and two hash inserts, average `O(1)`.
- **"Support `remove_bishop`."** Now one diagonal may hold several bishops over time, so the
  dict value must become a **set** of cells (or a count). `add` then checks emptiness rather
  than membership. Note that with the no-blocking rule at most one bishop can ever be on a
  diagonal anyway, so the set has size 0 or 1 - but writing it as a set makes `remove`
  obviously correct.
- **"Extend to rooks and queens."** Rooks: index by `row` and by `col` - two more dicts,
  same pattern. Queens: all four dicts at once. This is exactly the N-Queens constraint
  encoding, and saying so connects it to a problem they know.
- **"Bishops block each other's line of sight."** The sorted-list variant above.
- **"Place the maximum number of non-attacking bishops on an n x n board."** The answer is
  `2n - 2` for `n >= 2`; the diagonals decompose into two independent rook problems on
  rotated boards. A nice thing to know but do not derive it unless asked.
- **"Count how many cells are currently under attack."** Union of the occupied diagonals;
  inclusion-exclusion over their intersections.
- **"The board is huge / sparse."** The dict solution already never allocates the board -
  point out that `self.size` is only used for bounds checking and memory is `O(bishops)`.

## Pitfalls

- **Walking the diagonals cell by cell** and calling it done. Correct but `O(n)`; the
  question is about the key.
- **Using `row + col` for both diagonals**, or getting the two backwards. Draw the grid.
- **Forgetting that `row - col` can be negative.** Fine as a dict key; it is only a problem
  if you tried to use it as an array index, where you would need the `+ n - 1` offset.
- **Adding the bishop before the check**, so a rejected placement still mutates the board.
- **Returning `False` from `attacker`** rather than `None`, then writing
  `if self.attacker(...)` and having `(0, 0)` - a legitimate cell - test falsy. `(0,0)` is a
  truthy tuple, so this particular case is safe, but `or` chaining in `attacker` would break
  if a value could be falsy. Prefer explicit `is not None` checks.
- **Not asking about blocking**, then confidently giving the `O(1)` answer to a question that
  needed the `O(log n)` one.
