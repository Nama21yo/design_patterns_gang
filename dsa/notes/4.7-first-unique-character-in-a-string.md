title: "4.7 First Unique Character in a String"
---

**Link:** https://leetcode.com/problems/first-unique-character-in-a-string
**Difficulty:** Easy | **LeetCode #387**
**Bloomberg frequency:** 50% at three months.

Not really a stack problem - it is filed here because of its **streaming follow-up**, which
is a genuine queue question (LC 387's cousin, *First Unique Number*). The base problem is two
passes with a counter; the interview is the follow-up.

## 1. Problem statement

Given a string `s`, find the **first non-repeating character** in it and return its **index**.
If it does not exist, return `-1`.

```
s = "leetcode"       ->  0    'l'
s = "loveleetcode"   ->  2    'v'
s = "aabb"           ->  -1
```

## 2. Clarifying questions

1. **Return the index or the character?** The **index**. Easy to misread.
2. **"First" means leftmost in the string, not first encountered as unique?** Leftmost.
3. **Case sensitive?** Assume yes - `'A'` and `'a'` differ. Ask if the input might be mixed.
4. **Character set?** Lowercase English on LeetCode, which licenses a 26-element array.
5. **What if the string is empty?** Return `-1`.
6. **Is this a one-shot query, or will characters keep arriving?** **The important one** -
   the streaming version is a different and better question. Ask it.

## 3. Intuition

Count every character, then scan left to right for the first with a count of one.

> **Two passes: one to count, one to find. `O(n)` time, `O(alphabet)` space.**

The key point to state is why **two** passes are needed and not one: on the first pass you
cannot know whether the character you are looking at will reappear later. The information
simply is not available yet. So a single pass is impossible for this formulation - and saying
that pre-empts "can you do it in one pass?".

The second pass scans the **string**, not the counter, because you need the leftmost
*position*, and a dict iterated in insertion order would also work in Python 3.7+ but is a
weaker thing to rely on. Say which you are doing and why.

### The variant that makes it interesting

If characters arrive one at a time and you must answer "what is the first unique so far?"
**after every arrival**, two passes are not available. That needs a **queue of candidates**
plus a count map, with **lazy deletion** - pop from the front while the front is no longer
unique. That is the design question, and it is where a stack/queue actually appears.

## 4. Approach

1. `counts = Counter(s)`.
2. For each `i`, `ch`: if `counts[ch] == 1`, return `i`.
3. Return `-1`.

## 5. Solution

```python
from collections import Counter


def first_uniq_char(s):
    """Index of the first non-repeating character, or -1.

    Two passes are necessary, not lazy: on a single pass you cannot know whether the
    current character reappears later. The second pass walks the STRING so that the
    leftmost position is found directly.
    """
    counts = Counter(s)
    for i, ch in enumerate(s):
        if counts[ch] == 1:
            return i
    return -1
```

```python
first_uniq_char("leetcode")     # 0
first_uniq_char("loveleetcode") # 2
first_uniq_char("aabb")         # -1
first_uniq_char("")             # -1
first_uniq_char("z")            # 0
first_uniq_char("aabbc")        # 4
first_uniq_char("abcabc")       # -1
first_uniq_char("dddccdbba")    # 8
```

`"dddccdbba"` -> 8 is the good test: the unique character is the **last** one, so the second
pass runs to the end. `"aabbc"` -> 4 is the same idea shorter.

### The fixed-array version

```python
def first_uniq_char_array(s):
    """Lowercase ASCII only: a 26-element array instead of a dict. No hashing."""
    counts = [0] * 26
    for ch in s:
        counts[ord(ch) - 97] += 1
    for i, ch in enumerate(s):
        if counts[ord(ch) - 97] == 1:
            return i
    return -1


first_uniq_char_array("leetcode")       # 0
first_uniq_char_array("loveleetcode")   # 2
first_uniq_char_array("aabb")           # -1
first_uniq_char_array("")               # -1
```

Only valid because the problem guarantees lowercase English. Say the constraint aloud as you
use it.

### The first-and-last-index trick

Occasionally offered as a "one structure" alternative - a character is unique exactly when
its first and last occurrence coincide:

```python
def first_uniq_char_index_scan(s):
    """Uses str.index and str.rindex semantics: unique iff first == last occurrence.
    Elegant-looking, but each call scans the string, so it is O(n * alphabet)."""
    seen = set(s)
    best = len(s)
    for ch in seen:
        first = s.find(ch)
        if first == s.rfind(ch):
            best = min(best, first)
    return best if best < len(s) else -1


first_uniq_char_index_scan("leetcode")      # 0
first_uniq_char_index_scan("loveleetcode")  # 2
first_uniq_char_index_scan("aabb")          # -1
first_uniq_char_index_scan("")              # -1
```

`O(n * alphabet)` rather than `O(n)`. Mention it only to reject it - it looks clever and is
strictly worse, which is a useful thing to be able to say.

## The streaming follow-up - the real question

Characters arrive one at a time; after each, report the first unique **so far**.

```python
from collections import Counter, deque


class FirstUnique:
    """Streaming first-unique, with a queue of candidates and lazy deletion.

    The queue holds characters in arrival order that were unique when added. A
    character already in the queue may stop being unique later, so stale entries are
    discarded lazily from the FRONT when queried - never searched for in the middle.
    """

    def __init__(self):
        self.counts = Counter()
        self.queue = deque()

    def add(self, ch):
        self.counts[ch] += 1
        if self.counts[ch] == 1:
            self.queue.append(ch)       # a new candidate

    def first_unique(self):
        # Discard from the front anything that is no longer unique.
        while self.queue and self.counts[self.queue[0]] > 1:
            self.queue.popleft()
        return self.queue[0] if self.queue else None


stream = FirstUnique()
for ch in "loveleetcode":
    stream.add(ch)
stream.first_unique()       # 'v'

s2 = FirstUnique()
s2.add("a")
s2.first_unique()           # 'a'
s2.add("a")
s2.first_unique()           # None
s2.add("b")
s2.first_unique()           # 'b'
```

**Lazy deletion is the idea worth taking away.** Removing a character from the middle of a
queue is `O(n)`; instead you let stale entries sit there and skip them when they reach the
front. Each character is enqueued at most once and dequeued at most once, so every operation
is `O(1)` amortised.

This is the same technique as the lazy-deletion heap in 3.2, and it recurs in cache and
scheduler design. Naming it is worth real credit.

## 6. Complexity

Let `n` be the string length and `k` the alphabet size.

| | Time | Space |
|---|---|---|
| **Counter, two passes** | **`O(n)`** | `O(k)` |
| Fixed 26-array | `O(n)` | `O(1)` |
| first/last index scan | `O(n * k)` | `O(k)` |
| Streaming `add` / `first_unique` | `O(1)` amortised | `O(k)` |

Space is bounded by the **alphabet**, not the string, so `O(1)` for lowercase ASCII. Saying
`O(min(n, k))` or "O(1) for a fixed alphabet" is more precise than `O(n)`.

## 7. How to present it

This is a two-minute question. Solve it, then drive to the follow-up.

1. **Restate**, and confirm you return the **index**, and `-1` when none exists.
2. **Ask whether it is a one-shot query or a stream.** That single question is the difference
   between a trivial answer and a design conversation, and it is the reason this problem is
   on a Bloomberg list.
3. **State the approach**: count, then scan for the first count of one.
4. **Justify two passes**: *"one pass can't work - when I'm at a character I don't yet know
   whether it reappears."* This pre-empts the obvious probe.
5. **Say why the second pass walks the string**, not the counter: you need the leftmost
   position.
6. **Write it.** Four lines.
7. **Test** `""`, `"aabb"` (none), and `"dddccdbba"` (the last character).
8. **Offer the streaming version unprompted**, and explain **lazy deletion**: *"I keep a
   queue of candidates and discard stale ones from the front when queried, because deleting
   from the middle would be O(n)."*
9. **Close**: `O(n)` time, `O(1)` space for a bounded alphabet; `O(1)` amortised per
   operation in the streaming version.

## 8. Follow-ups and variations

- **"Now it's a stream"** (LC 1429, *First Unique Number*). The queue with lazy deletion.
  **This is the real question** - prepare it.
- **"Return the character rather than the index."** `s[i]`.
- **"First unique *word* in a document."** Same structure with words as the alphabet; space
  becomes `O(distinct words)`.
- **"First character that repeats"** - the mirror problem, and it *can* be done in one pass,
  because you know as soon as you see a repeat. Good contrast: it shows exactly why this one
  needs two.
- **"Last unique character."** Scan the second pass from the right.
- **"k-th unique character."** Same counter, count unique ones as you scan.
- **"What if the alphabet is Unicode?"** The dict version is unaffected; the 26-array is
  invalid.
- **"Can you do it in one pass?"** No, for this formulation - and explaining *why* is the
  better answer than attempting it. (You can do it in one pass over a *stream* if you are
  allowed to answer with a delay, which is essentially the queue version.)
- **"Memory is tight and the string is huge."** Space is already bounded by the alphabet; if
  the alphabet is huge, a Count-Min Sketch gives approximate counts, with false "not unique"
  results.

## 9. Pitfalls

- **Returning the character instead of the index.**
- **Returning the first character whose count you have not yet finished computing** - i.e.
  trying to do it in one pass.
- **Scanning the counter instead of the string** for the second pass. In Python 3.7+ dict
  order would save you, but it is the wrong reason to be right, and it breaks if you ever
  sort or use a plain `set`.
- **Using a `set` of seen characters** without counts, which cannot distinguish "seen once"
  from "seen twice".
- **Forgetting `-1`** for the no-unique case.
- **Assuming lowercase ASCII** without checking, then using `ord(ch) - 97`.
- **In the streaming version, searching the queue** to remove a character. Use lazy deletion
  from the front.
- **In the streaming version, enqueuing on every add** rather than only on the first
  occurrence, which breaks the ordering guarantee.
