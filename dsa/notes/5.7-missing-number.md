**Link:** https://leetcode.com/problems/missing-number
**Difficulty:** Easy | **LeetCode #268**
**Bloomberg frequency:** 50% at six months.

A question with **four genuinely different solutions**, which is why it is asked: the
interviewer wants to see how many you can produce and whether you can compare them. The best
answers are `O(n)` time and `O(1)` space, and there are two of those - **XOR** and **Gauss's
sum** - with a real trade-off between them.

Binary search appears only in the sorted variant, which is why it is filed here.

## 1. Problem statement

Given an array `nums` containing `n` **distinct** numbers in the range `[0, n]`, return the
**only number in the range that is missing** from the array.

```
nums = [3,0,1]              ->  2      n = 3, range is [0,3]
nums = [0,1]                ->  2      n = 2, range is [0,2]
nums = [9,6,4,2,3,5,7,0,1]  ->  8      n = 9
```

Follow-up: can you do it in `O(n)` time with `O(1)` extra space?

## 2. Clarifying questions

1. **The range is `[0, n]` inclusive, with `n = len(nums)`?** Yes - so there are `n + 1`
   possible values and `n` present, leaving exactly one missing. Confirm this; the
   off-by-one in the range is the usual misreading.
2. **Are the numbers distinct?** Yes, guaranteed.
3. **Is the array sorted?** **No** - and that matters. If it were, binary search would apply
   (see below).
4. **Exactly one missing?** Yes.
5. **May I modify the input?** Relevant for the in-place marking solution; ask.
6. **Could `n` be large enough for `n*(n+1)/2` to overflow?** In a fixed-width language with
   `n` near 10^5, the sum is about 5·10^9, which **exceeds 32-bit**. Python is immune. This
   is the argument for XOR over summation.

## 3. Intuition

### Solution 1: Gauss's sum

The numbers `0..n` sum to `n * (n + 1) / 2`. Subtract the actual sum and what remains is the
missing value.

`O(n)` time, `O(1)` space, one pass, and it is the shortest to write. The only concern is
**overflow** in a fixed-width language.

### Solution 2: XOR

XOR everything in `0..n` together with everything in the array. Every present value appears
exactly twice and cancels (`a ^ a = 0`), leaving the missing one.

`O(n)` time, `O(1)` space, **and no overflow at all** - which is the argument for preferring
it. Mention both and say why you would ship XOR in C++ or Java.

A neat way to write it is to fold the index and the value together in a single pass:

```
missing = n
for i, x in enumerate(nums):  missing ^= i ^ x
```

Starting at `n` supplies the one index that `enumerate` never reaches.

### Solution 3: sorting or a set

Sort and scan for the first mismatch (`O(n log n)`), or build a set and probe `0..n`
(`O(n)` time **and** `O(n)` space). Both work; both are dominated. State them and move on.

### Solution 4: binary search - only if sorted

**If the array were sorted**, the predicate *"is `nums[i] > i`?"* is `F F F T T T`: before
the gap each value equals its index, after it each value exceeds its index by one. The first
`True` is the missing number.

That is the lower-bound template again, `O(log n)`. It is the reason this problem is filed
under Part 5, and it is worth showing - but **only after asking whether the array is
sorted**. Applying it to unsorted input is simply wrong.

## 4. Approach

1. **Unsorted (the actual problem):** XOR fold, or Gauss's sum.
2. **Sorted variant:** binary search for the first index where `nums[i] != i`.

## 5. Solution

```python
def missing_number(nums):
    """The single missing value from 0..n. O(n) time, O(1) space, no overflow.

    XOR of 0..n together with every element cancels each present value (a ^ a = 0),
    leaving only the absent one. Seeding with n supplies the index enumerate never
    reaches, so index and value can be folded in a single pass.
    """
    missing = len(nums)             # the index 0..n-1 never produces
    for i, x in enumerate(nums):
        missing ^= i ^ x            # every present value cancels with its own index
    return missing
```

```python
missing_number([3, 0, 1])                       # 2
missing_number([0, 1])                          # 2
missing_number([9, 6, 4, 2, 3, 5, 7, 0, 1])     # 8
missing_number([0])                             # 1
missing_number([1])                             # 0
missing_number([])                              # 0
missing_number([1, 2])                          # 0
missing_number([0, 1, 2])                       # 3
```

The three single-element and boundary cases matter: `[0]` -> 1 (the missing value is at the
top of the range), `[1]` -> 0 (at the bottom), and `[0,1,2]` -> 3 (the whole range present
except the last). Together they confirm the range is `[0, n]` inclusive and not `[0, n-1]`.

### Gauss's sum

```python
def missing_number_sum(nums):
    """Shortest to write. Watch for overflow in fixed-width languages: for n near
    10^5 the expected sum is about 5e9, which exceeds a signed 32-bit int."""
    n = len(nums)
    expected = n * (n + 1) // 2
    return expected - sum(nums)


missing_number_sum([3, 0, 1])                   # 2
missing_number_sum([0, 1])                      # 2
missing_number_sum([9, 6, 4, 2, 3, 5, 7, 0, 1]) # 8
missing_number_sum([1])                         # 0
missing_number_sum([])                          # 0
```

### The sorted variant - binary search

```python
def missing_number_sorted(nums):
    """O(log n), but ONLY valid if nums is sorted ascending.

    In a sorted array, nums[i] == i before the gap and nums[i] == i + 1 after it, so
    "nums[i] > i" is False then True - the lower-bound shape.
    """
    lo, hi = 0, len(nums)           # hi = n: the missing value may be n itself
    while lo < hi:
        mid = (lo + hi) // 2
        if nums[mid] > mid:
            hi = mid                # the gap is at or before mid
        else:
            lo = mid + 1            # everything up to mid is in place
    return lo


missing_number_sorted([0, 1, 3])        # 2
missing_number_sorted([0, 1])           # 2
missing_number_sorted([1, 2, 3])        # 0
missing_number_sorted([0, 1, 2])        # 3
missing_number_sorted([0])              # 1
missing_number_sorted([1])              # 0
```

Note `hi = len(nums)`, not `len(nums) - 1` - the missing value can be `n` itself, one past the
last index, exactly as in 5.4.

### The set version, to state and reject

```python
def missing_number_set(nums):
    """O(n) time but O(n) space - the follow-up explicitly asks for O(1)."""
    present = set(nums)
    for v in range(len(nums) + 1):
        if v not in present:
            return v
    return -1


missing_number_set([3, 0, 1])           # 2
missing_number_set([0])                 # 1
missing_number_set([])                  # 0
```

## 6. Complexity

| | Time | Space | Overflow risk |
|---|---|---|---|
| Set | `O(n)` | `O(n)` | none |
| Sort then scan | `O(n log n)` | `O(1)` or `O(n)` | none |
| **Gauss's sum** | **`O(n)`** | **`O(1)`** | **yes**, in fixed-width languages |
| **XOR** | **`O(n)`** | **`O(1)`** | **none** |
| Binary search (**sorted input only**) | `O(log n)` | `O(1)` | none |

Both `O(1)`-space solutions are single passes. **XOR is the better default** purely because
it cannot overflow - that is the distinction worth drawing, and it is the substance of the
comparison.

## 7. How to present it

This is a five-minute question where the value is in the **comparison**, so produce several
solutions rather than one.

1. **Restate**, and pin down the range: *"`n` numbers drawn from `0..n` inclusive, so `n+1`
   candidates and exactly one missing."*
2. **Ask whether the array is sorted.** If yes, binary search in `O(log n)`; if no, the
   linear solutions. Asking first is what makes the binary-search answer legitimate rather
   than a misapplication.
3. **Offer the set solution in one sentence**, with its `O(n)` space, then say the follow-up
   rules it out.
4. **Give Gauss's sum**, then **immediately raise overflow**: *"for `n` near 10^5 the expected
   sum is about 5 billion, which overflows a 32-bit int - so in C++ or Java I'd use a wider
   type, or prefer XOR."*
5. **Give the XOR solution** and explain the cancellation, plus why seeding with `n` lets you
   fold index and value in one pass.
6. **State which you would ship and why**: XOR, because it is `O(1)` space *and* has no
   overflow failure mode.
7. **Test** `[0]`, `[1]`, `[]`, and `[0,1,2]` - the range boundaries.
8. **Close**: `O(n)` time, `O(1)` space; and if sorted, `O(log n)` by binary search.

## 8. Follow-ups and variations

- **"O(n) time and O(1) space."** XOR or Gauss. Both; compare them.
- **"What if the array were sorted?"** Binary search, `O(log n)` - shown above.
- **"What if two numbers were missing?"** Sum and sum-of-squares give two equations in two
  unknowns; or XOR everything, isolate a set bit of the result with `x & -x`, partition the
  values by that bit and XOR each group separately. That second technique is LC 260 and is
  worth naming - it is the standard "two singles among pairs" trick.
- **"Find All Numbers Disappeared in an Array"** (LC 448) - values in `[1, n]` with
  duplicates, several missing. The classic `O(1)`-space answer is **in-place negation
  marking**: use the sign of `nums[abs(v)-1]` as a present flag. Mention it if asked to avoid
  extra space while finding many.
- **"Find the Duplicate Number"** (LC 287) - the mirror problem, and much harder with the
  `O(1)`-space constraint: Floyd's cycle detection on the value-as-pointer graph. A good one
  to name.
- **"Single Number"** (LC 136) - XOR again, and the reason to know the identity `a ^ a = 0`.
- **"What if the range were `[1, n]` instead of `[0, n]`?"** Adjust the expected sum and the
  XOR seed. Check the boundary carefully - it is where the off-by-one lives.
- **"Numbers arrive as a stream."** XOR works online with `O(1)` state, which a set or a sort
  could not do. A genuinely good property to point out.

## 9. Pitfalls

- **Assuming the range is `[0, n-1]`**, which makes `[0,1,2]` return nothing. The range is
  inclusive of `n`.
- **Overflow in `n * (n + 1) // 2` or `sum(nums)`** in a fixed-width language.
- **Applying binary search to unsorted input.** Ask first.
- **In the sorted variant, `hi = len(nums) - 1`**, so the answer `n` is unreachable.
- **Using a set or a sort** after the follow-up has asked for `O(1)` space.
- **Forgetting to seed the XOR with `n`**, so the top of the range is never considered.
- **Not handling the empty array**, where the answer is 0.
- **Producing one solution and stopping.** This question is asked to elicit several.
