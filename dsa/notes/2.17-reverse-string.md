**Bloomberg frequency:** 38% at six months.

The smallest opposite-ends two-pointer problem there is. Four lines. It is on the list
because it is a **warm-up before a harder question** and because it opens onto a set of
follow-ups (reverse words, reverse in k-groups, Unicode) that are much more interesting than
the base problem.

Solve it in ninety seconds, then invite the follow-up.

## 1. Problem statement

Write a function that reverses a string. The input is given as an array of characters `s`.

You must do this by modifying the input array **in place** with `O(1)` extra memory.

```
s = ["h","e","l","l","o"]          ->  ["o","l","l","e","h"]
s = ["H","a","n","n","a","h"]      ->  ["h","a","n","n","a","H"]
```

## 2. Clarifying questions

1. **Why is the input a character array rather than a string?** Because Python strings are
   immutable, so "in place" would be impossible. Saying this shows you understand the
   constraint rather than just obeying it.
2. **May I use `s.reverse()` or `s[::-1]`?** Almost certainly not - the question is to
   implement it. Ask, then implement, then mention the built-ins exist.
3. **Really `O(1)` extra memory?** Yes; that rules out building a new list.
4. **ASCII or Unicode?** Matters more than it seems - see the follow-ups. Ask if the input
   were a real string.
5. **Can it be empty or a single character?** Both should work with no special case.

## 3. Intuition

Swap the first and last characters, then the second and second-to-last, and so on, stopping
when the pointers meet.

> **Two pointers from the ends, swap, move inward. Stop at `lo >= hi`.**

The middle element of an odd-length array never needs moving - it is already in its final
position - and the `lo < hi` condition handles that without a special case. That is the only
"insight" here, and it is worth one sentence.

The recursive version exists and is worth knowing for the follow-up discussion, but it uses
`O(n)` stack space, which violates the constraint. Mention it and reject it.

## 4. Approach

1. `lo, hi = 0, len(s) - 1`.
2. While `lo < hi`: swap `s[lo]` and `s[hi]`; `lo += 1`; `hi -= 1`.

## 5. Solution

```python
def reverse_string(s):
    """Reverse a list of characters in place, O(1) extra space."""
    lo, hi = 0, len(s) - 1
    while lo < hi:
        s[lo], s[hi] = s[hi], s[lo]
        lo += 1
        hi -= 1
    return s
```

```python
reverse_string(["h", "e", "l", "l", "o"])           # ['o', 'l', 'l', 'e', 'h']
reverse_string(["H", "a", "n", "n", "a", "h"])      # ['h', 'a', 'n', 'n', 'a', 'H']
reverse_string([])                                  # []
reverse_string(["a"])                               # ['a']
reverse_string(["a", "b"])                          # ['b', 'a']
reverse_string(list("abc"))                         # ['c', 'b', 'a']
```

The odd-length case `["h","e","l","l","o"]` never touches the middle `l`: `lo` and `hi` meet
at index 2 and the loop exits. Point that out rather than adding a branch for it.

### The built-ins, for completeness

```python
def reverse_string_builtin(s):
    """What you would actually write in production."""
    s.reverse()                     # in place, O(1) extra space
    return s


def reverse_string_slice(s):
    """s[::-1] builds a NEW list, so this is O(n) space - and plain `s = s[::-1]`
    would rebind the local name without mutating the caller's list at all."""
    s[:] = s[::-1]                  # slice assignment writes back into the same object
    return s


reverse_string_builtin(list("hello"))       # ['o', 'l', 'l', 'e', 'h']
reverse_string_slice(list("hello"))         # ['o', 'l', 'l', 'e', 'h']
```

The `s[:] = ...` versus `s = ...` distinction is worth ten seconds: the latter is a
classic Python bug in any "modify in place" question, and it silently does nothing from the
caller's point of view.

### The recursive version, and why not

```python
def reverse_string_recursive(s, lo=0, hi=None):
    """O(n) stack space, so it violates the O(1) constraint. Included because
    'could you do it recursively?' is a common follow-up."""
    if hi is None:
        hi = len(s) - 1
    if lo >= hi:
        return s
    s[lo], s[hi] = s[hi], s[lo]
    return reverse_string_recursive(s, lo + 1, hi - 1)


reverse_string_recursive(list("hello"))     # ['o', 'l', 'l', 'e', 'h']
reverse_string_recursive([])                # []
```

Note the mutable-default trap avoided: `hi=None` then computed inside, rather than
`hi=len(s)-1` in the signature, which would be evaluated once at definition time. That is the
same hazard as mutable default arguments (see [[0.6 Python toolkit for interviews]]).

Also note Python has no tail-call optimisation, so a 10,000-character string would exceed the
recursion limit. Say that.

## 6. Complexity

| | Time | Space |
|---|---|---|
| **Two pointers** | **`O(n)`** | **`O(1)`** |
| `s[:] = s[::-1]` | `O(n)` | `O(n)` for the temporary |
| Recursive | `O(n)` | `O(n)` stack |

`n/2` swaps, so `O(n)` with a small constant. Optimal - every character must move except a
middle one.

## 7. How to present it

1. **Restate**, and note the reason the input is a char array: Python strings are immutable,
   so in-place reversal needs a mutable sequence.
2. **Ask whether built-ins are allowed**, then implement regardless.
3. **Announce**: "Two pointers from the ends, swap and move inward, stop when they meet."
4. **Write it** - four lines - and mention that the middle element of an odd-length array
   needs no special case.
5. **Test** empty, one character, two characters, odd and even lengths. This takes fifteen
   seconds and is the whole "edge cases" section.
6. **Close**: `O(n)` time, `O(1)` space, `n/2` swaps.
7. **Immediately offer a follow-up** rather than waiting: *"Would you like the version that
   reverses the words in a sentence, or handles Unicode properly?"* On a question this small,
   driving to the next thing is the best use of the time.

## 8. Follow-ups and variations

- **"Reverse the words in a string"** (LC 151). `"the sky is blue"` -> `"blue is sky the"`.
  In place: reverse the whole thing, then reverse each word. The same two-step trick as
  2.16 Rotate Array. Watch for multiple spaces and leading/trailing whitespace - that is
  where the marks are.
- **"Reverse only the vowels"** (LC 345). Same two pointers, but each skips forward to the
  next vowel before swapping. A direct analogue of the skipping in 2.3 Valid Palindrome.
- **"Reverse Words in a String III"** (LC 557). Reverse each word, keep the word order.
- **"Reverse Nodes in k-Group"** (LC 25) - the linked-list version, and genuinely hard.
  Part 7.
- **"Reverse in place in a language without tuple assignment."** Three-line swap with a
  temporary, or the XOR swap trick - and note the XOR trick **fails when `lo == hi`**,
  zeroing the element. That is a real interview gotcha.
- **"What about Unicode?"** The important follow-up. Reversing a list of code points breaks
  **combining characters** - `"e" + U+0301` (combining acute) is one perceived character but
  two code points, and reversing separates them. Correct text reversal operates on **grapheme
  clusters**, not code points. Also, Python 3 strings are sequences of code points, so
  surrogate pairs are not an issue, but they would be in Java or JavaScript where strings are
  UTF-16. Being able to say this distinguishes you sharply on an otherwise trivial question.
- **"Reverse a number, not a string"** (LC 7). Arithmetic with `divmod`, plus a 32-bit
  overflow check - see 2.14 for the same overflow theme.
- **"Check if a string is a palindrome."** 2.3 - the same pointers, comparing instead of
  swapping.

## 9. Pitfalls

- **`s = s[::-1]`**, which rebinds the local name and leaves the caller's list untouched.
  Use `s[:] = ...` or swap in place.
- **`while lo <= hi`**, which performs one pointless self-swap at the middle. Harmless for a
  plain swap, but **destructive** with the XOR trick.
- **Building a new list** and claiming `O(1)` space.
- **Recursing** when `O(1)` space was required, or hitting the recursion limit on a long
  string.
- **`hi = len(s) - 1` as a default argument** in the recursive version - evaluated once at
  definition time.
- **Off-by-one with `hi = len(s)`** instead of `len(s) - 1`.
- **Spending five minutes on it.** Solve it, test it, and drive to a follow-up.
