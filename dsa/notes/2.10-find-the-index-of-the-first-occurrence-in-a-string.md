**Link:** https://leetcode.com/problems/find-the-index-of-the-first-occurrence-in-a-string
**Difficulty:** Easy | **LeetCode #28**
**Bloomberg frequency:** 50% at three months, 50% at six months.

Formerly "implement strStr()". Marked Easy because the naive solution is short, but the
**interesting answer is KMP**, and whether you can at least explain it is what separates
responses. Know the naive version cold and be able to describe KMP's prefix function even if
you do not write it perfectly.

## 1. Problem statement

Given two strings `haystack` and `needle`, return the index of the **first occurrence** of
`needle` in `haystack`, or `-1` if it is not present.

```
haystack = "sadbutsad", needle = "sad"  ->  0
haystack = "leetcode",  needle = "leeto" ->  -1
```

## 2. Clarifying questions

1. **What if `needle` is empty?** LeetCode's constraints say length >= 1, but the classic C
   `strstr` returns 0 for an empty needle. **Ask** - it is the single most common edge-case
   disagreement on this problem.
2. **First occurrence, or all of them?** First.
3. **May I use the built-in `find` / `index`?** Almost certainly not - the question is asking
   you to implement it. Ask, then implement.
4. **Case sensitive?** Yes, unless told otherwise.
5. **Character set?** Lowercase English on LeetCode. Matters for Rabin-Karp's alphabet size.
6. **String lengths?** Up to 10^4, so naive `O(n*m)` passes. Say you know the linear
   algorithm regardless.

## 3. Intuition

### Naive

For each starting position `i` in `haystack`, check whether the next `m` characters match.
Stop at the first success.

The only refinement worth making is the loop bound: `i` need only run to `n - m`, because
past that there are not enough characters left. Getting that bound right is most of the
naive solution.

Worst case is `O(n * m)`, achieved by inputs like `haystack = "aaaaaaab"`,
`needle = "aaab"` - every start position matches almost entirely before failing.

### Why KMP is faster

The naive approach throws away information. When a match fails at offset `j`, you already
know that the previous `j` characters of `haystack` matched `needle[0:j]`. Restarting at
`i + 1` re-reads them for nothing.

> **KMP precomputes, for each prefix of `needle`, the length of the longest proper prefix
> that is also a suffix of it. On a mismatch you jump the needle forward by that amount
> instead of restarting.**

That table is the **prefix function** (also called the failure function or LPS - longest
proper prefix which is also a suffix).

For `needle = "aabaaac"`:

| index | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|---|
| char | a | a | b | a | a | a | c |
| lps | 0 | 1 | 0 | 1 | 2 | 2 | 0 |

`lps[4] = 2` because `"aabaa"` has `"aa"` as both a proper prefix and a suffix. So if a match
fails after matching five characters, you can resume assuming two are already matched.

The key property: **the haystack pointer never moves backwards**. Each character of
`haystack` is examined at most a constant number of times amortised, giving `O(n + m)`.

## 4. Approach

**Naive:** for `i` in `0..n-m`, compare `haystack[i:i+m]` with `needle`; return `i` on a
match.

**KMP:**
1. Build `lps` for `needle` in `O(m)`.
2. Walk `haystack` with pointer `i` and `needle` with pointer `j`.
   - characters match -> advance both; if `j == m`, report `i - m`.
   - mismatch and `j > 0` -> `j = lps[j-1]` (slide the needle, do **not** move `i`).
   - mismatch and `j == 0` -> advance `i`.

## 5. Solution

### Naive - write this first

```python
def str_str(haystack, needle):
    """Index of the first occurrence of needle in haystack, or -1.

    The loop bound n - m + 1 is the whole subtlety: past that there are not enough
    characters left for a match.
    """
    n, m = len(haystack), len(needle)
    if m == 0:
        return 0                    # convention: the empty needle matches at 0
    if m > n:
        return -1

    for i in range(n - m + 1):
        if haystack[i:i + m] == needle:
            return i
    return -1
```

```python
str_str("sadbutsad", "sad")         # 0
str_str("leetcode", "leeto")        # -1
str_str("hello", "ll")              # 2
str_str("aaaaa", "bba")             # -1
str_str("", "")                     # 0
str_str("abc", "")                  # 0
str_str("a", "a")                   # 0
str_str("mississippi", "issip")     # 4
str_str("abc", "abcd")              # -1
```

Note `haystack[i:i+m] == needle` allocates a slice each iteration. An interviewer may ask you
to avoid that; the explicit inner loop does:

```python
def str_str_no_slice(haystack, needle):
    """Same, without allocating a slice per position."""
    n, m = len(haystack), len(needle)
    if m == 0:
        return 0
    for i in range(n - m + 1):
        j = 0
        while j < m and haystack[i + j] == needle[j]:
            j += 1
        if j == m:
            return i
    return -1


str_str_no_slice("sadbutsad", "sad")        # 0
str_str_no_slice("mississippi", "issip")    # 4
str_str_no_slice("leetcode", "leeto")       # -1
```

### KMP - the linear answer

```python
def build_lps(pattern):
    """lps[i] = length of the longest proper prefix of pattern[:i+1] that is also
    a suffix of it. Built in O(m) by the same sliding trick the search uses."""
    lps = [0] * len(pattern)
    length = 0                      # length of the current matching prefix
    i = 1
    while i < len(pattern):
        if pattern[i] == pattern[length]:
            length += 1
            lps[i] = length
            i += 1
        elif length > 0:
            length = lps[length - 1]    # fall back to the next shorter candidate
        else:
            lps[i] = 0
            i += 1
    return lps


def str_str_kmp(haystack, needle):
    """O(n + m). The haystack pointer never moves backwards."""
    n, m = len(haystack), len(needle)
    if m == 0:
        return 0
    if m > n:
        return -1

    lps = build_lps(needle)
    i = j = 0                       # i indexes haystack, j indexes needle
    while i < n:
        if haystack[i] == needle[j]:
            i += 1
            j += 1
            if j == m:
                return i - m
        elif j > 0:
            j = lps[j - 1]          # slide the needle; i stays put
        else:
            i += 1
    return -1
```

```python
build_lps("aabaaac")                # [0, 1, 0, 1, 2, 2, 0]
build_lps("aaaa")                   # [0, 1, 2, 3]
build_lps("abcd")                   # [0, 0, 0, 0]

str_str_kmp("sadbutsad", "sad")     # 0
str_str_kmp("leetcode", "leeto")    # -1
str_str_kmp("hello", "ll")          # 2
str_str_kmp("mississippi", "issip") # 4
str_str_kmp("aaaaaaab", "aaab")     # 4
str_str_kmp("", "")                 # 0
str_str_kmp("abc", "abcd")          # -1
```

`"aaaaaaab"` with needle `"aaab"` is the adversarial case for the naive version and the one
to mention: naive does roughly `n * m` character comparisons, KMP does `O(n + m)`.

## 6. Complexity

| | Time | Space |
|---|---|---|
| Naive with slicing | `O(n * m)` time, plus `O(m)` allocation per position | `O(m)` |
| Naive without slicing | `O(n * m)` | `O(1)` |
| **KMP** | **`O(n + m)`** | `O(m)` for the table |
| Rabin-Karp | `O(n + m)` average, `O(n * m)` worst | `O(1)` |

KMP's linearity rests on the amortised argument: `i` only ever increases, and `j` increases
at most once per increment of `i`, so `j` can decrease at most `n` times in total. State that
if asked why the inner fallback does not make it quadratic.

## 7. How to present it

1. **Ask about the empty needle first.** It is the classic disagreement and it takes five
   seconds.
2. **Write the naive version** and get the loop bound right out loud: "`i` only goes up to
   `n - m`, because past that there aren't enough characters left."
3. **State its complexity and the adversarial case**: `"aaaaaaab"` / `"aaab"`. Do not just
   say `O(n*m)` - show the input that achieves it.
4. **Then say what is being wasted**: "When a match fails partway, I already know what those
   characters were. Restarting one position later re-reads them."
5. **Introduce KMP by its idea, not its code**: "I'd precompute, for each prefix of the
   needle, the longest proper prefix that's also a suffix. On a mismatch I slide the needle
   by that amount instead of restarting, and the haystack pointer never goes backwards -
   that gives `O(n + m)`."
6. **Draw the `lps` table for a short needle** like `"aabaaac"`. This is far more convincing
   than code and is usually enough.
7. **Write KMP if there is time**, or offer to. Many interviewers are satisfied with the
   explanation plus the naive implementation.
8. **Close**: `O(n + m)` time, `O(m)` space, and note Rabin-Karp as the alternative.

## 8. Follow-ups and variations

- **"Find all occurrences, not just the first."** In KMP, on a match set `j = lps[j-1]` and
  continue instead of returning. Still `O(n + m)`.
- **"Explain Rabin-Karp."** Rolling hash: hash the needle, roll a window hash across the
  haystack, and verify on a hash match. `O(n + m)` average, `O(n * m)` worst case if hashes
  collide adversarially. The advantage is `O(1)` space and easy extension to **multiple
  patterns**.
- **"Multiple needles at once."** Aho-Corasick - a trie of the patterns with failure links,
  which is KMP generalised to many patterns. Name it.
- **"Is one string a rotation of another?"** `b in (a + a)` and `len(a) == len(b)`. A nice
  one-line application of substring search.
- **"Repeated Substring Pattern"** (LC 459). `lps[-1]` gives the answer directly: the string
  is a repetition iff `n % (n - lps[-1]) == 0` and `lps[-1] > 0`. This is the reason to know
  the prefix function - it answers several problems.
- **"Shortest palindrome"** (LC 214). Also solved with the prefix function on
  `s + "#" + reversed(s)`.
- **"Case-insensitive search."** Lowercase both, or compare with a case-folding comparator.
- **"What if the haystack is streamed?"** KMP is perfect for it - the haystack pointer never
  moves backwards, so it needs no buffering. That is a genuinely good point to make.
- **"Why not just use `str.find`?"** Because the question is to implement it. Note that
  CPython's `find` uses a hybrid of Crochemore-Perrin and Boyer-Moore-Horspool, not naive
  scanning.

## 9. Pitfalls

- **Loop bound `range(n)` instead of `range(n - m + 1)`**, producing short slices that never
  match (harmless) or an index error in the no-slice version (not harmless).
- **Not deciding the empty-needle convention.**
- **Returning `True`/`False` instead of the index.**
- **In `build_lps`, advancing `i` in the fallback branch.** The `length = lps[length-1]`
  branch must **not** advance `i` - that is the analogue of the same trap in 2.9.
- **Using `lps[j]` instead of `lps[j-1]`** in the search fallback. Off by one and it silently
  misses matches.
- **Initialising the `lps` loop at `i = 0`** rather than `i = 1`; `lps[0]` is always 0 by
  definition since a proper prefix must be shorter than the string.
- **Claiming KMP is `O(n*m)`** because of the inner `while`. Give the amortised argument.
- **Slicing in the inner loop** and then claiming `O(1)` space.
