**Bloomberg frequency:** 38% at three months, 62% at six months.

3Sum with one more loop. Read 2.1 first - everything here is the same idea, so this note
concentrates on what is genuinely different: **two layers of deduplication**, **pruning**
(which matters much more at `O(n^3)`), and the **general kSum** recursion that makes the
whole family one function.

## 1. Problem statement

Given an array `nums` and a `target`, return all **unique** quadruplets
`[nums[a], nums[b], nums[c], nums[d]]` with distinct indices such that they sum to `target`.

```
nums = [1,0,-1,0,-2,2], target = 0  ->  [[-2,-1,1,2],[-2,0,0,2],[-1,0,0,1]]
nums = [2,2,2,2,2],     target = 8  ->  [[2,2,2,2]]
```

Note: `-10^9 <= target <= 10^9` and values are up to `10^9` in magnitude, so in a
fixed-width language **the sum of four elements can overflow a 32-bit int**. Python is fine;
say it anyway.

## 2. Clarifying questions

1. **Unique by value or by index?** By **value**, as in 3Sum - `[2,2,2,2,2]` yields
   `[2,2,2,2]` once despite five ways to choose the indices.
2. **Arbitrary target, not zero?** Yes, unlike 3Sum. That matters: the `nums[i] > 0` early
   break from 3Sum is **invalid here**, and substituting it is a real bug.
3. **Can I modify the input?** Sorting mutates it - ask or copy.
4. **Array size?** Up to 200 on LeetCode, so `O(n^3)` passes comfortably.
5. **Overflow?** Not in Python. Mention it for C++/Java.
6. **Are negative values allowed?** Yes.

## 3. Intuition

Same reduction, one level deeper:

> **Fix two elements, and the rest is Two Sum on the remainder.**

Sort, loop `i` over the first element, loop `j` over the second, then two-pointer the range
`(j, n)` for the remaining pair summing to `target - nums[i] - nums[j]`.

`O(n^3)` overall. The structure is mechanical; the two things worth real attention are:

### Deduplication at two levels

- **`i`**: skip if `i > 0 and nums[i] == nums[i-1]`.
- **`j`**: skip if `j > i + 1 and nums[j] == nums[j-1]`. Note the guard is `j > i + 1`,
  **not** `j > 0` - the first `j` of each new `i` must always be considered, even if it
  equals `nums[i]`. Getting this wrong silently drops quadruplets such as `[2,2,2,2]`.
- **After recording**, skip equal values on both pointers, as in 3Sum.

That `j > i + 1` guard is the single most common bug in this problem, and it is exactly the
kind of detail an interviewer probes with `[2,2,2,2,2]`.

### Pruning matters here

At `O(n^3)`, cheap bounds checks earn their keep. Because the array is sorted, for a fixed
`i` (and similarly for `j`):

- the **smallest** achievable sum is `nums[i] + nums[i+1] + nums[i+2] + nums[i+3]`. If that
  already exceeds `target`, no later `i` can help either - **break**.
- the **largest** achievable sum with this `i` is
  `nums[i] + nums[n-3] + nums[n-2] + nums[n-1]`. If that is below `target`, this `i` is
  hopeless but a larger one might work - **continue**.

The same pair of checks applies inside the `j` loop. These turn a slow `O(n^3)` into
something that finishes fast on real inputs, and stating them shows you thought past the
skeleton.

## 4. Approach

1. Sort `nums`.
2. For `i` in `0..n-4`: dedup; prune (break / continue).
3. For `j` in `i+1..n-3`: dedup with the `j > i + 1` guard; prune.
4. Two pointers `lo = j+1`, `hi = n-1` seeking `target - nums[i] - nums[j]`.
5. On a hit: record, move both, skip duplicates on both sides.

## 5. Solution

```python
def four_sum(nums, target):
    """All unique quadruplets summing to target.

    Fix two elements, two-pointer the rest. Deduplication happens at three places:
    the i loop, the j loop (guarded by j > i + 1, not j > 0), and after each hit.
    """
    nums.sort()
    n = len(nums)
    result = []

    for i in range(n - 3):
        if i > 0 and nums[i] == nums[i - 1]:
            continue
        # Smallest possible sum with this i already too big: no later i can be smaller.
        if nums[i] + nums[i + 1] + nums[i + 2] + nums[i + 3] > target:
            break
        # Largest possible sum with this i still too small: try a bigger i.
        if nums[i] + nums[n - 3] + nums[n - 2] + nums[n - 1] < target:
            continue

        for j in range(i + 1, n - 2):
            # j > i + 1, NOT j > 0: the first j for each i must always be considered,
            # otherwise quadruplets like [2,2,2,2] are lost.
            if j > i + 1 and nums[j] == nums[j - 1]:
                continue
            if nums[i] + nums[j] + nums[j + 1] + nums[j + 2] > target:
                break
            if nums[i] + nums[j] + nums[n - 2] + nums[n - 1] < target:
                continue

            need = target - nums[i] - nums[j]
            lo, hi = j + 1, n - 1
            while lo < hi:
                total = nums[lo] + nums[hi]
                if total < need:
                    lo += 1
                elif total > need:
                    hi -= 1
                else:
                    result.append([nums[i], nums[j], nums[lo], nums[hi]])
                    lo += 1
                    hi -= 1
                    while lo < hi and nums[lo] == nums[lo - 1]:
                        lo += 1
                    while lo < hi and nums[hi] == nums[hi + 1]:
                        hi -= 1

    return result
```

```python
four_sum([1, 0, -1, 0, -2, 2], 0)       # [[-2, -1, 1, 2], [-2, 0, 0, 2], [-1, 0, 0, 1]]
four_sum([2, 2, 2, 2, 2], 8)            # [[2, 2, 2, 2]]
four_sum([], 0)                         # []
four_sum([1, 2, 3], 6)                  # []
four_sum([0, 0, 0, 0], 0)               # [[0, 0, 0, 0]]
four_sum([1, 1, 1, 1, 1], 4)            # [[1, 1, 1, 1]]
four_sum([-3, -1, 0, 2, 4, 5], 2)       # [[-3, -1, 2, 4]]
four_sum([1000000000] * 4, 4000000000)  # [[1000000000, 1000000000, 1000000000, 1000000000]]
```

`[2,2,2,2,2]` with target 8 is the test for the `j > i + 1` guard. With `j > 0` instead, the
inner loop skips `j = 1` (since `nums[1] == nums[0]`) for `i = 0`, and the quadruplet is
never formed - the function returns `[]`. **Check this case explicitly in the interview.**

The last example is the overflow demonstration: four values of `10^9` sum to `4 * 10^9`,
which exceeds the signed 32-bit range. Python handles it; C++ with `int` would not.

### The general kSum recursion

Worth knowing, because it collapses 2Sum, 3Sum, 4Sum and beyond into one function - and
because "how would you generalise this?" is the standard follow-up.

```python
def k_sum(nums, target, k):
    """All unique k-tuples summing to target. Recurses down to a two-pointer base case."""
    nums = sorted(nums)

    def solve(start, target, k):
        result = []
        if k == 2:
            lo, hi = start, len(nums) - 1
            while lo < hi:
                total = nums[lo] + nums[hi]
                if total < target:
                    lo += 1
                elif total > target:
                    hi -= 1
                else:
                    result.append([nums[lo], nums[hi]])
                    lo += 1
                    hi -= 1
                    while lo < hi and nums[lo] == nums[lo - 1]:
                        lo += 1
            return result

        for i in range(start, len(nums) - k + 1):
            if i > start and nums[i] == nums[i - 1]:
                continue                        # dedup relative to THIS level's start
            # Pruning: the smallest and largest sums reachable from here.
            if nums[i] * k > target:
                break
            if nums[-1] * k < target:
                break
            for rest in solve(i + 1, target - nums[i], k - 1):
                result.append([nums[i]] + rest)
        return result

    return solve(0, target, k)
```

```python
k_sum([1, 0, -1, 0, -2, 2], 0, 4)       # [[-2, -1, 1, 2], [-2, 0, 0, 2], [-1, 0, 0, 1]]
k_sum([2, 2, 2, 2, 2], 8, 4)            # [[2, 2, 2, 2]]
k_sum([-1, 0, 1, 2, -1, -4], 0, 3)      # [[-1, -1, 2], [-1, 0, 1]]
k_sum([2, 7, 11, 15], 9, 2)             # [[2, 7]]
k_sum([1, 2, 3, 4, 5], 15, 5)           # [[1, 2, 3, 4, 5]]
```

Note the dedup guard is `i > start`, which is the general form of `j > i + 1` - the same
idea expressed once instead of at every level. That is the cleanest way to explain why the
guard is what it is.

## 6. Complexity

Let `n = len(nums)`.

| | Time | Space |
|---|---|---|
| Brute force, four loops | `O(n^4)` | `O(1)` plus output |
| **Sort + two fixed + two pointers** | **`O(n^3)`** | `O(1)` extra, `O(log n)` sort stack |
| kSum recursion | `O(n^(k-1))` | `O(k)` recursion depth |

The sort is `O(n log n)`, dominated. Output can be `O(n^2)` quadruplets in adversarial cases
(many duplicates of a few values), so total space including the result is `O(n^2)`.

## 7. How to present it

1. **Say immediately that it is 3Sum with one more loop.** There is no reason to pretend
   otherwise, and it gets you to the interesting parts faster.
2. **Ask about the target** - it is arbitrary here, unlike 3Sum. Then say explicitly: *"that
   means the `nums[i] > 0` early break from 3Sum doesn't apply; I need bound-based pruning
   instead."* That single observation is the best differentiator on this question.
3. **Confirm uniqueness is by value.**
4. **Announce the structure** - sort, two nested loops, two pointers.
5. **Write it**, calling out the `j > i + 1` guard as you type it and explaining the failure
   it prevents. Offer `[2,2,2,2,2]` as the test.
6. **Add the pruning** and explain each of the two checks in one sentence.
7. **Trace the given example** at least through `i = 0`.
8. **Offer the kSum generalisation** as a close: "this recurses naturally - kSum fixes one
   element and calls (k-1)Sum, bottoming out at the two-pointer case."
9. **Close**: `O(n^3)` time, `O(1)` extra space, output can be `O(n^2)`, and note overflow in
   fixed-width languages.

## 8. Follow-ups and variations

- **"Generalise to kSum."** The recursion above. Name the complexity `O(n^(k-1))`.
- **"4Sum II"** (LC 454) - *four separate arrays*, count tuples rather than list them. This
  is a **different technique**: hash all pairwise sums of the first two arrays into a
  counter, then look up the negation for each pair from the other two. `O(n^2)` time and
  space. It is a Part 1 problem wearing a Part 2 name, and knowing the distinction is worth
  real credit.
- **"Count the quadruplets instead of listing them."** Handle duplicate blocks
  combinatorially rather than skipping them.
- **"Closest 4Sum."** Track the minimum `|sum - target|`; no dedup needed.
- **"What if the same index may be reused?"** Then it is unbounded and becomes a
  coin-change-style DP.
- **"Can you beat O(n^3)?"** Not by a known general method - 3SUM-hardness suggests 3Sum
  needs `O(n^2)`, and 4Sum inherits. You can get `O(n^2 log n)` by hashing all pairwise sums
  and sorting them, but the deduplication becomes unpleasant. Worth naming as a real trade.
- **"Overflow."** `nums[i] + nums[j] + nums[lo] + nums[hi]` overflows 32-bit signed
  arithmetic with values near `10^9`. Use 64-bit; Python is unaffected.

## 9. Pitfalls

- **`j > 0` instead of `j > i + 1`** in the inner dedup. Drops `[2,2,2,2]`. The defining bug
  of this problem.
- **Carrying over `nums[i] > 0` from 3Sum.** Only valid when the target is zero.
- **Skipping duplicates before recording a quadruplet.**
- **`range(n)` rather than `range(n - 3)` / `range(i + 1, n - 2)`**, leaving too few elements
  for the two pointers.
- **`lo <= hi`**, reusing an element.
- **Recomputing `target - nums[i] - nums[j]` inside the while loop** - harmless but noisy.
- **Sorting when indices are required.**
- **Assuming no overflow** in a fixed-width language.
- **Confusing this with 4Sum II**, which has four arrays and a completely different solution.
