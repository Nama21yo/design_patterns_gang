**Link:** https://leetcode.com/problems/squares-of-a-sorted-array
**Difficulty:** Easy | **LeetCode #977**
**Bloomberg frequency:** 50% at three months.

A small, elegant question. The `O(n log n)` answer is one line; the `O(n)` answer requires
one observation about where the **largest** squares live, and it is a good miniature of
"fill the output from the end" (which also drives 2.6).

## 1. Problem statement

Given an integer array `nums` **sorted in non-decreasing order**, return an array of the
squares of each number, also sorted in non-decreasing order.

```
nums = [-4,-1,0,3,10]  ->  [0,1,9,16,100]
nums = [-7,-3,2,3,11]  ->  [4,9,9,49,121]
```

Follow-up: an `O(n)` solution.

## 2. Clarifying questions

1. **Can the array contain negatives?** Yes - and that is the whole problem. If everything
   were non-negative, squaring preserves the order and you just map.
2. **Is it definitely sorted to begin with?** Yes, non-decreasing.
3. **In place, or may I allocate the output?** A new array is fine; the output does not count
   against space.
4. **Duplicates possible?** Yes. `[-3,3]` squares to `[9,9]`.
5. **Can it be empty?** Should return `[]`.
6. **Overflow?** Squaring values near `10^4` is fine; in a fixed-width language with values
   near `10^9` the square overflows 64-bit. Worth a sentence.

## 3. Intuition

The one-liner is `sorted(x*x for x in nums)`: `O(n log n)`. Say it, then improve.

The observation that gives linear time:

> **Squaring makes the array V-shaped.** Negatives square to large values in *decreasing*
> order as you move right; non-negatives square to increasing values. So the array of
> squares decreases to a minimum somewhere and then increases.

That means the **largest** square is always at one of the two **ends** - never in the middle.
So compare the two ends, take the bigger, and place it at the back of the output. Then move
that pointer inward and repeat.

This is a merge of two sorted sequences:
- the negatives, read right to left, give increasing squares;
- the non-negatives, read left to right, give increasing squares.

You are merging them in **descending** order into the output filled from the back, which is
exactly the 2.6 trick.

An alternative framing that some find clearer: binary search for the split point between
negatives and non-negatives, then merge the two halves forwards. Same complexity, more code,
and it needs care when all values share a sign. The two-pointers-from-the-ends version has
no special cases, which is why it is preferred.

## 4. Approach

1. `result = [0] * n`.
2. `lo, hi = 0, n - 1`; `write = n - 1`.
3. While `lo <= hi`:
   - compare `abs(nums[lo])` and `abs(nums[hi])` - or, avoiding `abs`, compare the squares
   - take the larger, square it, place at `result[write]`, move that pointer inward
   - `write -= 1`
4. Return `result`.

Note `lo <= hi`, not `lo < hi` - the middle element must be placed too.

## 5. Solution

```python
def sorted_squares(nums):
    """Squares of a sorted array, sorted, in O(n).

    Squaring makes the sequence V-shaped, so the largest square is always at one end.
    Compare the ends, take the larger, and fill the output from the back.
    """
    n = len(nums)
    result = [0] * n
    lo, hi = 0, n - 1
    write = n - 1

    while lo <= hi:                 # '<=' so the middle element is placed too
        left_sq = nums[lo] * nums[lo]
        right_sq = nums[hi] * nums[hi]
        if left_sq > right_sq:
            result[write] = left_sq
            lo += 1
        else:
            result[write] = right_sq
            hi -= 1
        write -= 1

    return result
```

```python
sorted_squares([-4, -1, 0, 3, 10])      # [0, 1, 9, 16, 100]
sorted_squares([-7, -3, 2, 3, 11])      # [4, 9, 9, 49, 121]
sorted_squares([])                      # []
sorted_squares([0])                     # [0]
sorted_squares([-5])                    # [25]
sorted_squares([1, 2, 3])               # [1, 4, 9]
sorted_squares([-3, -2, -1])            # [1, 4, 9]
sorted_squares([-3, 3])                 # [9, 9]
sorted_squares([-2, -1, 0, 1, 2])       # [0, 1, 1, 4, 4]
```

Three worth calling out:

- `[1,2,3]` - all non-negative, so `hi` does all the moving and the output is just the
  squares in order.
- `[-3,-2,-1]` - all negative, so `lo` does all the moving and the order reverses.
- `[-3,3]` - a tie. The `else` branch takes the right one; either is correct since the values
  are equal, but the tie must not cause both pointers to move or neither.

The two all-one-sign cases are exactly what the "binary search for the split point" approach
gets wrong if you are careless, which is a reason to prefer this version.

### The one-line version, to state first

```python
def sorted_squares_sorting(nums):
    """O(n log n). Correct and short - say it, then improve it."""
    return sorted(x * x for x in nums)


sorted_squares_sorting([-4, -1, 0, 3, 10])      # [0, 1, 9, 16, 100]
sorted_squares_sorting([-7, -3, 2, 3, 11])      # [4, 9, 9, 49, 121]
```

Do not skip this step. Giving the trivially correct answer first, stating its complexity, and
then improving it is the sequence interviewers want - and it guarantees you have *something*
if you run out of time.

## 6. Complexity

| | Time | Space |
|---|---|---|
| Map then sort | `O(n log n)` | `O(n)` output |
| **Two pointers from the ends** | **`O(n)`** | `O(n)` output, `O(1)` extra |

One pass: each iteration writes exactly one output slot and moves exactly one input pointer,
so it runs exactly `n` times. The output array is required by the problem, so `O(1)`
*auxiliary* space is the honest claim.

## 7. How to present it

1. **Restate**, and immediately identify why it is not trivial: "If everything were
   non-negative I could just square in place. The negatives are the problem, because squaring
   reverses their order."
2. **Give the `O(n log n)` one-liner** and its complexity.
3. **State the V-shape observation** - this is the insight and it should be said in one
   sentence: *"After squaring, the array decreases then increases, so the largest value is
   always at one of the two ends."*
4. **Derive the consequence**: "So I compare the ends, take the larger, and fill the output
   from the back - it's a merge of two sorted runs."
5. **Announce**, then write it. Call out `lo <= hi` and why.
6. **Test the sign cases out loud**: all positive, all negative, mixed, single element,
   empty, and a tie like `[-3,3]`.
7. **Close**: `O(n)` time, `O(1)` auxiliary space, and note that squaring can overflow in a
   fixed-width language.

## 8. Follow-ups and variations

- **"Do it in O(n)."** The stated follow-up - the two-pointer version.
- **"Can you do it in place?"** Not straightforwardly: writing a large square into the front
  destroys a value you still need, and the output is not a permutation of the input's
  positions. You would need `O(n)` scratch or an in-place merge with rotations - say this
  rather than attempting it.
- **"What about cubes instead of squares?"** Cubing **preserves** sign and order, so the
  array is already sorted after mapping - `O(n)` with no cleverness at all. A good check that
  you understood *why* squares are special.
- **"What about `|x - k|` for some `k`?"** Same V-shape, centred at `k` instead of `0`. The
  identical two-pointer approach works, which shows the technique generalises to any convex
  function of the value.
- **"Find the k closest elements to zero."** Two pointers from the ends taking the **smaller**
  absolute value `k` times, or binary search for the insertion point of 0 and expand
  outwards. LC 658 is the general version.
- **"Merge two sorted arrays."** LC 88, at 2.6 - the same fill-from-the-back idea.
- **"Overflow."** With `|x| <= 10^4` the square fits easily. With values near `10^9`, `x*x`
  exceeds 64-bit signed range; you would need a wider type. Python is unaffected.
- **"The input is a stream."** You cannot, without buffering - the answer depends on both
  ends simultaneously.

## 9. Pitfalls

- **Assuming squaring preserves order.** It does not, and that is the entire question.
- **`while lo < hi`**, which drops the middle element and leaves a `0` in the output.
- **Filling the output from the front**, which requires the *smallest* square - and that one
  is in the middle, where you are not looking.
- **Using `abs()` and then forgetting to square**, or squaring twice.
- **Moving both pointers on a tie**, which writes one slot but consumes two inputs and leaves
  a hole.
- **Using `sorted()` and calling it `O(n)`.**
- **Breaking on the all-negative or all-positive case**, which happens with the
  binary-search-for-the-split framing if the split index is at an end.
- **Claiming `O(1)` total space** - the output is `O(n)`; say *auxiliary*.
