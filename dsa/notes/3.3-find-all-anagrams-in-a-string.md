title: "3.3 Find All Anagrams in a String"

**Link:** https://leetcode.com/problems/find-all-anagrams-in-a-string
**Difficulty:** Medium | **LeetCode #438**
**Bloomberg frequency:** 62% in the **30-day** window.

The canonical **fixed-size window with a frequency match**. Its twin, 3.12 *Permutation in
String*, is literally the same algorithm returning a boolean - learn them together. The
interesting content is how you check "do these two frequency maps agree?" in `O(1)` instead
of `O(26)`.

## 1. Problem statement

Given two strings `s` and `p`, return an array of all the **start indices** of `p`'s
anagrams in `s`. You may return the answer in any order.

```
s = "cbaebabacd", p = "abc"  ->  [0,6]     "cba" at 0, "bac" at 6
s = "abab",       p = "ab"   ->  [0,1,2]   "ab", "ba", "ab"
```

Both strings consist of lowercase English letters.

## 2. Clarifying questions

1. **An anagram means the same multiset of characters?** Yes - same characters with the same
   counts, in any order.
2. **Start indices, not the substrings?** Indices.
3. **Can `p` be longer than `s`?** Then there are no answers; guard it.
4. **Lowercase English only?** Stated, and it licenses a 26-element array instead of a dict.
   **Ask**, because if it is Unicode the fixed array is wrong.
5. **Can windows overlap?** Yes - example 2 has three overlapping answers.
6. **Are duplicates within `p` possible?** Yes, e.g. `p = "aab"`. That is why a `set` is not
   enough; you need counts.

## 3. Intuition

The window size is **fixed** at `len(p)`, since an anagram of `p` has exactly `p`'s length.
So this is the simpler of the two window shapes - no shrink decision, just slide.

Naive: for each of the `n - m + 1` positions, build a frequency map of the window and compare
with `p`'s. That is `O(n * m)` or `O(n * 26)` depending on how you compare.

The window improvement: as the window slides by one, exactly one character enters and one
leaves, so update the counts in `O(1)` rather than rebuilding.

That leaves the comparison. Three levels, worth knowing all three:

**(a) Compare the whole `Counter`** each step - `O(26)` per position, so `O(26n)`. Perfectly
acceptable and the easiest to write correctly.

**(b) Maintain a `matches` counter** - the number of distinct characters whose window count
equals the target count. The window is an anagram exactly when `matches == 26` (or equals
the number of distinct characters in `p`). Updating `matches` on each entry/exit is `O(1)`.

**(c) Maintain a `missing` counter** - the total number of characters still needed. Simplest
to reason about for this specific problem, and the one used below.

For the interview, **write (a) first and say it is `O(26n)` which is effectively linear**,
then offer (b) or (c) if they want a strict `O(1)` per step. Do not open with the clever
version; the comparison being `O(26)` is not actually a problem, and claiming otherwise
suggests you cannot tell a constant from a variable.

### The "missing" formulation

Start with `need = Counter(p)` and `missing = len(p)`.

For each entering character `ch`:
- if `need[ch] > 0`, this character was genuinely wanted, so `missing -= 1`
- `need[ch] -= 1` (it may go negative, meaning the window has a surplus)

For each leaving character `ch`:
- `need[ch] += 1`
- if `need[ch] > 0`, we are now short of it again, so `missing += 1`

`missing == 0` exactly when the window contains every character of `p` with the right counts.
Because the window size is fixed at `len(p)`, "contains at least" and "contains exactly" are
the same thing - which is the small insight that makes this work. Say that; it is why no
surplus check is needed.

## 4. Approach

1. If `len(p) > len(s)`, return `[]`.
2. `need = Counter(p)`, `missing = len(p)`, `result = []`.
3. For each `right`, `ch`:
   - consume `ch` into the window
   - if `right >= len(p)`, release `s[right - len(p)]`
   - if `missing == 0`, record `right - len(p) + 1`
4. Return `result`.

## 5. Solution

```python
from collections import Counter


def find_anagrams(s, p):
    """Start indices of every anagram of p in s.

    Fixed-size window of len(p). `missing` counts how many of p's characters the
    window still lacks; because the window size is fixed, "has at least all of p"
    and "is exactly an anagram of p" coincide.
    """
    m, n = len(p), len(s)
    if m > n:
        return []

    need = Counter(p)
    missing = m                     # characters of p still unmatched by the window
    result = []

    for right in range(n):
        ch = s[right]
        # Consume the entering character.
        if need[ch] > 0:
            missing -= 1            # it was genuinely wanted
        need[ch] -= 1               # may go negative: a surplus of this character

        # Release the character sliding out, once the window is full-size.
        if right >= m:
            left_ch = s[right - m]
            need[left_ch] += 1
            if need[left_ch] > 0:
                missing += 1        # back to being short of it

        if missing == 0:
            result.append(right - m + 1)

    return result
```

```python
find_anagrams("cbaebabacd", "abc")      # [0, 6]
find_anagrams("abab", "ab")             # [0, 1, 2]
find_anagrams("a", "ab")                # []
find_anagrams("aa", "bb")               # []
find_anagrams("baa", "aa")              # [1]
find_anagrams("aaaaaaaaaa", "aaaaaaaaaaaaa")    # []
find_anagrams("abc", "abc")             # [0]
find_anagrams("", "a")                  # []
find_anagrams("aabc", "abc")            # [1]
```

`"baa"` with `p = "aa"` is a good small trace: at `right = 1` the window is `"ba"`, which is
not an anagram; at `right = 2` the window is `"aa"` and `missing` reaches 0, so index 1 is
recorded.

### The straightforward Counter-comparison version

```python
from collections import Counter


def find_anagrams_counter(s, p):
    """O(26n). Rebuilds nothing, but compares the whole Counter each step.
    Write this first - it is obviously correct and fast enough."""
    m, n = len(p), len(s)
    if m > n:
        return []

    need = Counter(p)
    window = Counter(s[:m])
    result = [0] if window == need else []

    for right in range(m, n):
        window[s[right]] += 1               # entering
        out = s[right - m]
        window[out] -= 1                    # leaving
        if window[out] == 0:
            del window[out]                 # keep the Counter clean so == works
        if window == need:
            result.append(right - m + 1)

    return result


find_anagrams_counter("cbaebabacd", "abc")      # [0, 6]
find_anagrams_counter("abab", "ab")             # [0, 1, 2]
find_anagrams_counter("baa", "aa")              # [1]
find_anagrams_counter("a", "ab")                # []
```

A note on the `del`: it is **not** strictly required for the `==` test, because `Counter`
equality ignores zero counts - `Counter({'a': 1, 'b': 0}) == Counter({'a': 1})` is `True`.
But keep it anyway, and say why: the moment you switch from comparing the whole Counter to
testing `len(window)` (a distinct-character count), stale zero entries make the answer
silently wrong. That is the bug described in the Part 3 primer, and the `del` is the habit
that prevents it.

### The fixed-array version

```python
def find_anagrams_array(s, p):
    """Lowercase ASCII only: two 26-element arrays, no hashing at all."""
    m, n = len(p), len(s)
    if m > n:
        return []

    need = [0] * 26
    window = [0] * 26
    for ch in p:
        need[ord(ch) - 97] += 1

    result = []
    for right in range(n):
        window[ord(s[right]) - 97] += 1
        if right >= m:
            window[ord(s[right - m]) - 97] -= 1
        if right >= m - 1 and window == need:
            result.append(right - m + 1)
    return result


find_anagrams_array("cbaebabacd", "abc")    # [0, 6]
find_anagrams_array("abab", "ab")           # [0, 1, 2]
find_anagrams_array("baa", "aa")            # [1]
```

Valid **only** because the problem guarantees lowercase English. Say that constraint aloud as
you use it - using a 26-slot array on unspecified input is a bug, not an optimisation.

## 6. Complexity

Let `n = len(s)`, `m = len(p)`, `k = 26`.

| | Time | Space |
|---|---|---|
| Sort each window and compare | `O(n * m log m)` | `O(m)` |
| Rebuild a Counter per window | `O(n * m)` | `O(k)` |
| Slide + full Counter compare | `O(n * k)` | `O(k)` |
| **Slide + `missing` counter** | **`O(n)`** | `O(k)` |

Space is bounded by the alphabet, so `O(1)` for lowercase ASCII. Note that `O(n * k)` with
`k = 26` is a constant factor, not a complexity class - be precise about that rather than
calling the simple version "slow".

## 7. How to present it

1. **Restate**, confirm indices and that overlapping windows count separately (`"abab"`
   gives three answers).
2. **Note that the window size is fixed** at `len(p)` - so this is the simple window shape.
3. **Ask about the character set**, and say what it licenses.
4. **Give the naive bound** - rebuild a frequency map per position, `O(n*m)`.
5. **State the slide**: "One character enters and one leaves per step, so I update counts in
   `O(1)`."
6. **Address the comparison explicitly**: "Comparing the two maps is `O(26)`, which is a
   constant - so `O(26n)` is already linear. If you want strict `O(1)` per step I can track
   how many characters are still missing instead."
7. **Write whichever version they prefer.** Default to the `Counter` comparison unless they
   push; it is harder to get wrong.
8. **If you write the `missing` version**, explain the key insight: *"because the window size
   is fixed at `len(p)`, having all of `p`'s characters means the window is exactly an
   anagram - so I don't need to check for surplus."*
9. **Test** `"abab"`/`"ab"` for overlaps, `p` longer than `s`, and a no-match case.
10. **Close**: `O(n)` time, `O(1)` space for a bounded alphabet - and mention 3.12 is the same
    algorithm returning a boolean.

## 8. Follow-ups and variations

- **"Just return whether any anagram exists"** - LC 567 *Permutation in String*, at 3.12.
  Return `True` at the first match.
- **"Minimum Window Substring"** (LC 76). The **variable**-size cousin: find the shortest
  window containing all of `p`'s characters, surplus allowed. Same `missing` bookkeeping,
  but now you shrink from the left once valid. Much harder, and the natural next question -
  be ready for it.
- **"What if the alphabet is Unicode?"** Use a dict; the 26-array is invalid. Complexity is
  unchanged in `n` but the constant becomes the number of distinct characters.
- **"Case insensitive, or ignore non-letters."** Normalise on entry, as in 2.3.
- **"Find anagrams of `p` in a stream."** Works as-is: fixed memory, one pass, no lookback.
- **"Group anagrams"** (LC 49). A different technique - canonical keys in a hash map,
  Part 1. Worth distinguishing: here the window is fixed and you slide; there you bucket.
- **"Count anagram pairs in a list of words."** Canonical key plus `n choose 2` per bucket.
- **"Is `s2` a rotation of `s1`?"** Unrelated but often confused - `s2 in s1 + s1`.
- **"What if `p` can contain repeated characters?"** It already can - `"aab"` - which is
  exactly why counts are needed rather than a set.

## 9. Pitfalls

- **Using a `set` instead of counts**, so `"aab"` matches `"abb"`.
- **Rebuilding the frequency map for every window**, making it `O(n*m)`.
- **Off-by-one in the recorded index**: it is `right - m + 1`, the window's **start**.
- **Starting to record before the window is full** - guard with `right >= m - 1`.
- **Forgetting to remove the outgoing character**, so the window grows without bound.
- **Using a 26-element array without checking the alphabet is lowercase ASCII.**
- **In the `missing` version, decrementing `missing` unconditionally** rather than only when
  `need[ch] > 0`. Surplus characters must not count as progress.
- **Not guarding `len(p) > len(s)`**, which produces negative indices.
- **Claiming `O(n*26)` is slow.** It is linear; 26 is a constant.
