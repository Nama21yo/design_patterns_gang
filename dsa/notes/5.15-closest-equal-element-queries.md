A **recent** problem combining three ideas: grouping by value, **circular** distance, and
binary search within a sorted index list. It is the best example in Part 5 of binary search
as a *component* rather than the whole answer.

## 1. Problem statement

You are given a **circular** array `nums` and an array `queries`.

For each query `i`, find the **minimum distance** between index `queries[i]` and any **other**
index `j` with `nums[j] == nums[queries[i]]`. If no such index exists, the answer is `-1`.

Return an array of the answers.

```
nums = [1,3,1,4,1,3,2], queries = [0,3,5]  ->  [2,-1,3]

    query 0: nums[0] = 1; nearest other 1 is at index 2, distance 2
    query 1: nums[3] = 4; no other 4 exists, so -1
    query 2: nums[5] = 3; nearest other 3 is at index 1, distance 3
             (going the circular way: 5 -> 6 -> 0 -> 1)
```

```
nums = [1,2,3,4], queries = [0,1,2,3]  ->  [-1,-1,-1,-1]
```

## 2. Clarifying questions

1. **Circular?** Yes - distance may wrap around either end. **This is the crux**; the third
   example in the prompt exists precisely to test it.
2. **How is circular distance defined?** For indices `i` and `j` in an array of length `n`:
   `min(|i - j|, n - |i - j|)`. Confirm this formula out loud.
3. **Must `j` differ from the queried index?** Yes - "any **other** index". So a value
   appearing only once yields `-1`.
4. **Can the same index be queried twice?** Yes; the answers are independent.
5. **Sizes?** Up to 10^5 for both `nums` and `queries`, so an `O(n)` scan per query is
   `O(n * q) = 10^10` - far too slow. That is what forces the preprocessing.
6. **Value range?** Up to 10^6, so group with a dict rather than an array.

## 3. Intuition

### Step 1: group the indices by value

Build `positions[value] = sorted list of indices where that value occurs`. Iterating the
array in order means each list is **already sorted** - no sort needed, which is worth
pointing out.

If a value's list has length 1, every query on it answers `-1` immediately.

### Step 2: only the neighbours matter

Within one value's sorted index list, the nearest other occurrence of the queried index is
one of its **immediate neighbours in that list** - the predecessor or the successor. Nothing
further away can be closer in the linear sense.

Finding those neighbours is a binary search: `bisect_left(positions[value], query_index)`
locates the query's own position in the list, and the candidates are the entries either side.

That is where binary search enters - as a lookup inside the preprocessing structure, not as
the overall strategy.

### Step 3: the circular twist

Because the array wraps, there is a third candidate: the **first and last** entries of the
list are neighbours *through the wrap*. So for the query index `i` at list position `p`:

- **predecessor**: `positions[p - 1]` if `p > 0`, else **the last entry** (wrapping backwards)
- **successor**: `positions[p + 1]` if `p + 1 < len`, else **the first entry** (wrapping
  forwards)

Then take the circular distance to each and return the smaller.

Because the wrap-around candidates are just the ends of the list, you do not need any extra
structure - only careful indexing. Python's negative indexing makes the backwards wrap fall
out naturally as `positions[p - 1]`, since `p = 0` gives `positions[-1]`, the last entry.
**That is a genuine convenience, not a coincidence to rely on blindly** - say that you are
using it deliberately.

For the successor, `positions[(p + 1) % len(positions)]` handles the forward wrap.

## 4. Approach

1. Build `positions: value -> list of indices`, in increasing order.
2. For each query index `q`:
   - `lst = positions[nums[q]]`; if `len(lst) == 1`, answer `-1`.
   - `p = bisect_left(lst, q)` - the position of `q` within `lst`.
   - previous = `lst[p - 1]`, next = `lst[(p + 1) % len(lst)]`.
   - answer = `min(circular_distance(q, previous), circular_distance(q, next))`.

## 5. Solution

```python
import bisect
from collections import defaultdict


def solve_queries(nums, queries):
    """Minimum circular distance from each queried index to another index holding
    the same value, or -1 if the value occurs only once.

    Indices are grouped by value (already sorted, since the array is scanned in
    order). Within a group, only the immediate neighbours can be nearest - including
    the wrap-around pair formed by the first and last entries.
    """
    n = len(nums)

    positions = defaultdict(list)
    for i, x in enumerate(nums):
        positions[x].append(i)      # appended in increasing order, so already sorted

    def circular_distance(a, b):
        gap = abs(a - b)
        return min(gap, n - gap)    # either way round the circle

    answer = []
    for q in queries:
        group = positions[nums[q]]
        if len(group) == 1:
            answer.append(-1)       # the only occurrence of this value
            continue

        p = bisect.bisect_left(group, q)        # where q sits within its group
        # p - 1 wraps to the last entry when p == 0, via Python's negative indexing.
        previous = group[p - 1]
        # (p + 1) % len wraps to the first entry at the end of the list.
        following = group[(p + 1) % len(group)]

        answer.append(min(circular_distance(q, previous),
                          circular_distance(q, following)))

    return answer
```

```python
solve_queries([1, 3, 1, 4, 1, 3, 2], [0, 3, 5])     # [2, -1, 3]
solve_queries([1, 2, 3, 4], [0, 1, 2, 3])           # [-1, -1, -1, -1]
solve_queries([1, 1], [0, 1])                       # [1, 1]
solve_queries([5], [0])                             # [-1]
solve_queries([1, 2, 1], [0])                       # [1]
solve_queries([1, 2, 3, 1], [0, 3])                 # [1, 1]
solve_queries([2, 2, 2], [0, 1, 2])                 # [1, 1, 1]
solve_queries([1, 0, 0, 0], [3, 0])                 # [1, -1]
```

Two to work through:

- **`[1,2,3,1]` with queries `[0,3]` -> `[1,1]`.** The two `1`s are at indices 0 and 3, which
  are 3 apart linearly but only **1 apart circularly** (`4 - 3 = 1`). This is the case that
  proves the wrap is handled, and it is the fastest one to check.
- **Query 2 of the given example**: `nums[5] = 3`, whose group is `[1, 5]`.
  `bisect_left([1,5], 5)` gives `p = 1`, so `previous = group[0] = 1` and
  `following = group[(1+1) % 2] = group[0] = 1`. The circular distance from 5 to 1 is
  `min(4, 7-4) = 3`. Correct.

### The brute force, as the oracle

```python
def solve_queries_brute(nums, queries):
    """O(n) per query. Correct, far too slow at the real limits, and exactly what the
    linear solution should be validated against."""
    n = len(nums)
    answer = []
    for q in queries:
        best = -1
        for j in range(n):
            if j != q and nums[j] == nums[q]:
                gap = abs(q - j)
                d = min(gap, n - gap)
                best = d if best == -1 else min(best, d)
        answer.append(best)
    return answer


solve_queries_brute([1, 3, 1, 4, 1, 3, 2], [0, 3, 5])   # [2, -1, 3]
solve_queries_brute([1, 2, 3, 1], [0, 3])               # [1, 1]
solve_queries_brute([1, 2, 3, 4], [0, 1, 2, 3])         # [-1, -1, -1, -1]
```

### Avoiding the binary search entirely

Since the queries are indices into `nums`, you can precompute each index's **position within
its own group** in the same pass, removing the `bisect` call:

```python
from collections import defaultdict


def solve_queries_precomputed(nums, queries):
    """O(n + q): store each index's rank within its value group, so no search is
    needed at query time. Strictly better than the bisect version."""
    n = len(nums)
    positions = defaultdict(list)
    rank = [0] * n                  # rank[i] = index of i within positions[nums[i]]

    for i, x in enumerate(nums):
        rank[i] = len(positions[x])
        positions[x].append(i)

    def circular_distance(a, b):
        gap = abs(a - b)
        return min(gap, n - gap)

    answer = []
    for q in queries:
        group = positions[nums[q]]
        if len(group) == 1:
            answer.append(-1)
            continue
        p = rank[q]
        answer.append(min(circular_distance(q, group[p - 1]),
                          circular_distance(q, group[(p + 1) % len(group)])))
    return answer


solve_queries_precomputed([1, 3, 1, 4, 1, 3, 2], [0, 3, 5])     # [2, -1, 3]
solve_queries_precomputed([1, 2, 3, 1], [0, 3])                 # [1, 1]
solve_queries_precomputed([2, 2, 2], [0, 1, 2])                 # [1, 1, 1]
solve_queries_precomputed([1, 2, 3, 4], [0, 1, 2, 3])           # [-1, -1, -1, -1]
```

**Offer this as the improvement.** It removes the `log` factor and, more importantly, shows
you noticed that the query is an *index* rather than an arbitrary value - so its position in
the group is known at build time. That observation is the best thing you can say on this
question.

## 6. Complexity

Let `n = len(nums)` and `q = len(queries)`.

| | Time | Space |
|---|---|---|
| Brute force | `O(n * q)` | `O(1)` |
| Grouping + binary search per query | `O(n + q log n)` | `O(n)` |
| **Grouping + precomputed ranks** | **`O(n + q)`** | `O(n)` |

At the stated limits (`n, q` up to 10^5) the brute force is 10^10 operations; the grouped
solutions are around 2·10^5. Space is `O(n)` for the position lists, which together hold
exactly `n` indices.

## 7. How to present it

1. **Restate**, and **confirm the circular distance formula**: `min(|i-j|, n-|i-j|)`. Write
   it down.
2. **Confirm `j != i`**, so a unique value gives `-1`.
3. **State the scale problem**: `O(n)` per query is 10^10 - so preprocessing is required.
4. **Describe the grouping**: indices bucketed by value, already sorted because you scan in
   order. Note that a group of size 1 answers `-1` immediately.
5. **State the neighbour observation**: *"within a value's sorted index list, only the
   immediate predecessor and successor can be nearest - everything else is further away."*
6. **Then handle the wrap**: *"and because the array is circular, the first and last entries
   of the list are also neighbours, through the wrap."* Draw the group `[1, 5]` from the
   example with `n = 7` to make it concrete.
7. **Write the bisect version**, then **offer the precomputed-rank improvement**: *"actually,
   since the query is an index rather than a value, I can record its rank within its group
   while building - no search needed, so `O(n + q)`."*
8. **Test** `[1,2,3,1]` with queries `[0,3]`, which is the wrap case.
9. **Close**: `O(n + q)` time, `O(n)` space.

## 8. Follow-ups and variations

- **"What if the array were not circular?"** Drop the wrap: `previous` is `None` when
  `p == 0` and `following` is `None` when `p` is last, and the distance is plain `|i - j|`.
  Simpler, and worth stating as the contrast.
- **"What if the queries gave a *value* rather than an index?"** Then the rank is unknown and
  you genuinely need the binary search - which is exactly why the bisect version is worth
  having written.
- **"What if `nums` can be updated between queries?"** The sorted index lists would need
  insertions and deletions - a balanced BST or a skip list per value, `O(log n)` per update.
  A good extension to name.
- **"Return the index of the nearest equal element, not the distance."** Track which candidate
  won.
- **"Nearest element with a *different* value."** Almost always an immediate neighbour in the
  array; a completely different and much easier problem.
- **"k-th nearest equal element."** Walk `k` steps either way in the group list, handling the
  wrap - the group list makes this easy.
- **"Contains Duplicate II"** (3.7) - "is there an equal element within distance `k`" is the
  boolean cousin, solvable with a sliding window. Worth contrasting: that one needs no
  preprocessing because the distance bound is fixed.

## 9. Pitfalls

- **Ignoring the circular wrap**, giving 3 instead of 1 on `[1,2,3,1]` with query 0.
  **The defining bug.**
- **Computing the distance as `abs(i - j)`** without the `min(gap, n - gap)`.
- **Forgetting that the first and last entries of a group are neighbours.** Handling the
  linear neighbours only misses the wrap candidate.
- **Not excluding the queried index itself**, giving 0 for every query.
- **Returning `-1` only when the value is absent**, rather than when it occurs exactly once.
- **Sorting each group** - unnecessary, since scanning the array in order already produces
  sorted lists.
- **Scanning the array per query**, which times out at the real limits.
- **Using a fixed-size array keyed by value** when values go up to 10^6 - a dict is the right
  structure.
- **Relying on Python's negative indexing without saying so.** It is correct and deliberate
  here, but in another language `p - 1` with `p == 0` is an out-of-bounds read.
