**Link:** https://leetcode.com/problems/first-bad-version
**Difficulty:** Easy | **LeetCode #278**
**Bloomberg frequency:** 50% at six months.

**The lower-bound template with no array at all.** The predicate is supplied as an API, which
makes the "binary search is about a monotone predicate, not about sorted data" point more
directly than any other question in Part 5. Five lines, and the whole content is the
boundary handling and minimising API calls.

## 1. Problem statement

You are a product manager leading a team developing a new product. The latest version fails
the quality check, and since each version is developed based on the previous one, **all
versions after a bad one are also bad**.

You are given `n` versions `[1, 2, ..., n]` and an API `isBadVersion(version)` that returns
whether a version is bad. Find the **first** bad version.

You should **minimise the number of API calls**.

```
n = 5, bad = 4  ->  4
    isBadVersion(3) -> False
    isBadVersion(5) -> True
    isBadVersion(4) -> True, and it is the first

n = 1, bad = 1  ->  1
```

## 2. Clarifying questions

1. **Are versions numbered from 1?** Yes, `1..n` inclusive. **Not** 0-indexed - a common slip.
2. **Is it guaranteed that a bad version exists?** Yes, since the latest version is bad. So
   the answer always lies in `[1, n]` and there is no "not found" case.
3. **Is badness really monotone?** Yes - *"all versions after a bad one are also bad"*, which
   is the `F F F T T T` pattern. **Say this back**; it is the precondition and stating it is
   the whole justification.
4. **Is the API expensive?** The problem says to minimise calls, which is the hint that a
   linear scan is unacceptable and that you should not make redundant calls.
5. **How large can `n` be?** Up to `2^31 - 1`, so `(lo + hi)` overflows a 32-bit int - the
   classic reason to write `lo + (hi - lo) // 2`.
6. **Can the API be called with out-of-range values?** Do not - keep the search inside
   `[1, n]`.

## 3. Intuition

There is no array to search. What you have is a **monotone boolean function**:

```
isBadVersion:  F  F  F  T  T  T
version:       1  2  3  4  5  6
                        ^ the answer
```

That is exactly the lower-bound shape: **find the first `True`.**

> **`lo, hi = 1, n`. While `lo < hi`: if `isBadVersion(mid)`, the answer is at `mid` or
> earlier, so `hi = mid`; otherwise it is strictly after, so `lo = mid + 1`. Return `lo`.**

The three safety properties from the primer apply unchanged:

- **`while lo < hi`** - the loop ends with `lo == hi`, which is the answer, so there is no
  final API call to decide between them.
- **`hi = mid`, never `mid - 1`** - `mid` might itself be the first bad version.
- **`mid` rounds down**, so `mid < hi` whenever `lo < hi`, so `hi = mid` strictly shrinks the
  range. No infinite loop.

### Minimising API calls

The template makes **exactly one call per iteration**, and there are `ceil(log2(n))`
iterations - about 31 for `n = 2^31 - 1`. That is optimal: each call yields one bit of
information, and distinguishing `n` possibilities needs `log2(n)` bits.

Two things that would waste calls, and are worth naming:
- **Calling `isBadVersion(lo)` or `isBadVersion(hi)` to check the endpoints.** Unnecessary -
  the invariant already guarantees the answer is in range.
- **Using the inclusive `lo <= hi` template** and calling the API again after the loop to
  decide. The exclusive template avoids that final call entirely.

### The overflow point

`(lo + hi) // 2` with both near `2^31` overflows a signed 32-bit integer. Write
`lo + (hi - lo) // 2`, which is algebraically identical and never exceeds `hi`. Python is
immune, **but this problem is the canonical place to mention it** - it is a genuinely famous
bug, present in the JDK's binary search for years.

## 4. Approach

1. `lo, hi = 1, n`.
2. While `lo < hi`:
   - `mid = lo + (hi - lo) // 2`
   - if `isBadVersion(mid)`: `hi = mid`
   - else: `lo = mid + 1`
3. Return `lo`.

## 5. Solution

```python
def make_is_bad_version(first_bad):
    """Test harness standing in for the provided API. Counts calls so the call
    budget can actually be checked rather than assumed."""
    state = {"calls": 0}

    def is_bad_version(version):
        state["calls"] += 1
        return version >= first_bad

    return is_bad_version, state


def first_bad_version(n, is_bad_version):
    """First bad version in 1..n, given a monotone isBadVersion API.

    No array involved: the predicate itself is False then True, which is all binary
    search needs. Exactly one API call per iteration, so ceil(log2(n)) calls total.
    """
    lo, hi = 1, n                   # versions are 1-indexed

    while lo < hi:
        # lo + (hi - lo) // 2, not (lo + hi) // 2: the latter overflows 32-bit ints.
        mid = lo + (hi - lo) // 2
        if is_bad_version(mid):
            hi = mid                # mid might itself be the first bad one
        else:
            lo = mid + 1            # mid is good, so the answer is strictly after it

    return lo
```

```python
api, state = make_is_bad_version(4)
first_bad_version(5, api)           # 4
state["calls"]                      # 2   -- ceil(log2(5)) = 3 is the bound, not the exact count

api, state = make_is_bad_version(1)
first_bad_version(1, api)           # 1
state["calls"]                      # 0

api, _ = make_is_bad_version(1)
first_bad_version(5, api)           # 1

api, _ = make_is_bad_version(5)
first_bad_version(5, api)           # 5

api, state = make_is_bad_version(1702766719)
first_bad_version(2126753390, api)  # 1702766719
state["calls"]                      # 31
```

Three worth pointing at:

- **`n = 1` makes zero API calls.** The loop never runs because `lo == hi` immediately. A
  nice demonstration that the exclusive template does not waste a call confirming the obvious.
- **The first and last versions being bad** are the two boundary cases; both must work
  without special handling.
- **`n = 2126753390` takes 31 calls**, which is `ceil(log2(n))`. That is the concrete answer
  to "how many API calls?" and it is worth measuring rather than asserting.

### The inclusive template, for contrast

```python
def first_bad_version_inclusive(n, is_bad_version):
    """The lo <= hi form. Correct, but it needs a `result` variable to remember the
    best candidate, because the loop does not converge onto the answer."""
    lo, hi = 1, n
    result = n
    while lo <= hi:
        mid = lo + (hi - lo) // 2
        if is_bad_version(mid):
            result = mid            # remember it, then look further left
            hi = mid - 1
        else:
            lo = mid + 1
    return result


api, _ = make_is_bad_version(4)
first_bad_version_inclusive(5, api)     # 4

api, state = make_is_bad_version(1702766719)
first_bad_version_inclusive(2126753390, api)    # 1702766719
state["calls"]                                  # 31
```

Same call count here, but note the extra `result` variable - the exclusive template converges
onto the answer and needs no such bookkeeping. That is the argument for standardising on it.

### The linear scan, to reject

```python
def first_bad_version_linear(n, is_bad_version):
    """O(n) API calls. With n up to 2^31 this is hopeless - but it is the baseline
    that makes the logarithmic call count meaningful."""
    for v in range(1, n + 1):
        if is_bad_version(v):
            return v
    return -1


api, state = make_is_bad_version(4)
first_bad_version_linear(5, api)        # 4
state["calls"]                          # 4
```

## 6. Complexity

| | API calls | Time | Space |
|---|---|---|---|
| Linear scan | `O(n)` | `O(n)` | `O(1)` |
| **Binary search** | **`ceil(log2 n)`** | **`O(log n)`** | **`O(1)`** |

For `n = 2^31 - 1` that is 31 calls versus two billion. This is **information-theoretically
optimal**: each boolean call yields one bit, and identifying one of `n` possibilities needs
`log2(n)` bits. Saying that is a strong close, because it proves you cannot do better rather
than merely being fast.

## 7. How to present it

1. **Restate**, and **state the monotonicity explicitly**: *"Once a version is bad, every
   later one is bad - so `isBadVersion` is False then True. That's exactly the shape binary
   search needs, even though there is no array here."* **This is the point of the question.**
2. **Confirm 1-indexing** and that a bad version is guaranteed to exist.
3. **Note the call-minimisation requirement** and what it rules out.
4. **Announce the lower-bound template** and the three safety properties as you write them:
   `while lo < hi`, `hi = mid` keeps the candidate, `mid` rounds down so the range shrinks.
5. **Write `lo + (hi - lo) // 2` and say why** - *"`(lo + hi)` overflows a 32-bit int when
   `n` is near two billion; this form is identical and safe. Python doesn't have the problem,
   but the habit is worth keeping."* This is the aside that lifts an Easy.
6. **Point out there is no call after the loop** - the exclusive template converges onto the
   answer, so `lo` is returned directly.
7. **Test** `n = 1`, the first version bad, the last version bad.
8. **Close**: `ceil(log2 n)` API calls, `O(1)` space, and note it is information-theoretically
   optimal - one bit per call.

## 8. Follow-ups and variations

- **"How many API calls exactly?"** `ceil(log2(n))`. Measure it rather than guessing - 31 for
  `n` near `2^31`.
- **"Can you do fewer?"** No. Each call returns one bit, and distinguishing `n` answers needs
  `log2(n)` bits. A clean lower-bound argument and a strong thing to state.
- **"What if the API is unreliable / can return a wrong answer occasionally?"** Now it is
  noisy binary search - you would repeat calls and take a majority, costing a `log` factor,
  or use the Rényi-Ulam framing. Naming the problem class is enough.
- **"What if versions were not monotone?"** Binary search is invalid - you would have to test
  every version, `O(n)`. Worth stating, because it isolates the assumption doing the work.
- **"Search Insert Position"** (5.4) - the same template with an array instead of an API.
- **"Guess Number Higher or Lower"** (LC 374) - the same shape with a three-way API.
- **"What if `n` were unbounded?"** Exponential search: call `isBadVersion(1), (2), (4),
  (8), ...` until the first `True`, then binary search that window. `O(log answer)` calls.
  A genuinely good follow-up to name.
- **"Find the last good version instead."** `first_bad_version(n) - 1`, guarding for 1.

## 9. Pitfalls

- **Starting at `lo = 0`.** Versions are 1-indexed.
- **`hi = mid - 1` in the exclusive template**, which can skip the answer when `mid` is the
  first bad version.
- **Mixing templates**: `while lo <= hi` with `hi = mid` is an infinite loop.
- **Calling the API after the loop** to confirm - unnecessary and it wastes the budget.
- **Calling the API on the endpoints first** as a "sanity check" - also wasted calls.
- **`(lo + hi) // 2` overflow** in a fixed-width language. Mention it even in Python.
- **Returning `mid` from inside the loop.** It may be *a* bad version without being the
  *first*.
- **Assuming the answer must be strictly inside `(1, n)`.** Either endpoint can be the
  answer.
