**Difficulty:** Medium | **LeetCode #189**
**Bloomberg frequency:** 38% at three months.

The **reverse-three-times** trick. It looks like magic the first time and is obvious once you
see the picture, so the interview is about *explaining why it works*, not about recalling it.
There is also a genuinely interesting alternative (cyclic replacements) with a subtle
termination condition involving `gcd`.

## 1. Problem statement

Given an integer array `nums`, rotate it to the **right** by `k` steps, where `k` is
non-negative.

```
nums = [1,2,3,4,5,6,7], k = 3  ->  [5,6,7,1,2,3,4]
nums = [-1,-100,3,99],  k = 2  ->  [3,99,-1,-100]
```

Follow-up: solve it in place with **O(1)** extra space; there are at least three different
approaches.

## 2. Clarifying questions

1. **Rotate right or left?** Right. (Left by `k` is right by `n - k`, so one converts to the
   other - worth saying.)
2. **Can `k` exceed `n`?** Yes. `k = 10` on a 7-element array is `k = 3`. **Take `k % n`
   first** - forgetting this is the most common bug.
3. **Must it be in place?** The follow-up asks for `O(1)` space; the `O(n)`-space version is
   trivial, so give it then improve.
4. **Can `k` be zero?** Yes; the array is unchanged. Note `k % n` makes `k = n` behave the
   same way.
5. **Can the array be empty?** Then `n = 0` and `k % n` divides by zero - guard it.
6. **Return or mutate?** Mutate in place; LeetCode returns nothing.

## 3. Intuition

### The easy `O(n)`-space answer

`result[(i + k) % n] = nums[i]`, then copy back. Or in Python, `nums[:] = nums[-k:] +
nums[:-k]`. Say this first - it is one line and obviously correct.

### The reversal trick

Watch what rotation does to the array as two blocks:

```
original:              [1,2,3,4] [5,6,7]        (A = first n-k, B = last k)
after rotating right:  [5,6,7] [1,2,3,4]        (B then A)
```

So a right rotation by `k` is exactly **swapping two adjacent blocks**. And there is a
classic identity for that:

> **`BA = reverse(reverse(A) + reverse(B))`**

Concretely, three reversals:

```
[1,2,3,4,5,6,7]
reverse everything   -> [7,6,5,4,3,2,1]
reverse first k=3    -> [5,6,7] 4,3,2,1
reverse the rest     -> [5,6,7] [1,2,3,4]      done
```

The first reversal puts the blocks in the right **order** but each is internally backwards;
the next two straighten them out. Saying it that way - *"the first reversal fixes the block
order, the other two fix the contents"* - is the explanation that makes it click, and it is
what an interviewer wants to hear.

### The cyclic-replacement alternative

You can also move each element directly to its final position, following the cycle
`i -> (i + k) % n`, carrying the displaced value.

The subtlety: this decomposes into **`gcd(n, k)` disjoint cycles**, so a single pass round one
cycle does not necessarily cover the array. You either run the outer loop `gcd(n, k)` times
starting from successive indices, or count how many elements you have placed and stop at `n`.

For `n = 6, k = 2`, `gcd = 2`: the cycles are `0->2->4->0` and `1->3->5->1`. A naive single
cycle would move only half the array. This is the trap, and knowing it is worth real credit.

## 4. Approach

**Reversal:**
1. `k %= n`.
2. Reverse the whole array.
3. Reverse `nums[0:k]`.
4. Reverse `nums[k:n]`.

**Cyclic replacement:**
1. `k %= n`; `count = 0`; `start = 0`.
2. While `count < n`: follow the cycle from `start`, swapping the carried value forward, until
   you return to `start`; then `start += 1`.

## 5. Solution

```python
def rotate(nums, k):
    """Rotate nums right by k, in place, O(1) extra space.

    A right rotation swaps two adjacent blocks: [A][B] becomes [B][A].
    Reversing the whole array puts the blocks in the right order but reverses each
    one's contents; reversing each block individually then repairs them.
    """
    n = len(nums)
    if n == 0:
        return nums
    k %= n                      # k can exceed n; k == n is a no-op
    if k == 0:
        return nums

    def reverse(lo, hi):
        """Reverse nums[lo:hi+1] in place with two pointers."""
        while lo < hi:
            nums[lo], nums[hi] = nums[hi], nums[lo]
            lo += 1
            hi -= 1

    reverse(0, n - 1)           # block order is now correct, contents reversed
    reverse(0, k - 1)           # repair the first block
    reverse(k, n - 1)           # repair the second block
    return nums
```

```python
rotate([1, 2, 3, 4, 5, 6, 7], 3)        # [5, 6, 7, 1, 2, 3, 4]
rotate([-1, -100, 3, 99], 2)            # [3, 99, -1, -100]
rotate([1, 2, 3], 0)                    # [1, 2, 3]
rotate([1, 2, 3], 3)                    # [1, 2, 3]
rotate([1, 2, 3], 4)                    # [3, 1, 2]
rotate([1], 5)                          # [1]
rotate([], 3)                           # []
rotate([1, 2], 1)                       # [2, 1]
rotate([1, 2, 3, 4, 5, 6], 2)           # [5, 6, 1, 2, 3, 4]
```

`[1,2,3]` with `k = 4` is the case that proves the modulo: `4 % 3 == 1`, so it is a rotation
by one. Without `k %= n` the slice indices go out of range or silently do nothing.

### The cyclic-replacement version

```python
from math import gcd


def rotate_cyclic(nums, k):
    """Move each element directly to its destination, following i -> (i + k) % n.

    The permutation splits into gcd(n, k) disjoint cycles, so one cycle is not enough;
    counting placements is the simplest way to guarantee full coverage.
    """
    n = len(nums)
    if n == 0:
        return nums
    k %= n
    if k == 0:
        return nums

    count = 0
    start = 0
    while count < n:
        current = start
        carried = nums[start]
        while True:
            nxt = (current + k) % n
            nums[nxt], carried = carried, nums[nxt]
            current = nxt
            count += 1
            if current == start:
                break
        start += 1
    return nums


rotate_cyclic([1, 2, 3, 4, 5, 6, 7], 3)     # [5, 6, 7, 1, 2, 3, 4]
rotate_cyclic([-1, -100, 3, 99], 2)         # [3, 99, -1, -100]
rotate_cyclic([1, 2, 3, 4, 5, 6], 2)        # [5, 6, 1, 2, 3, 4]
rotate_cyclic([1, 2, 3], 4)                 # [3, 1, 2]
rotate_cyclic([], 3)                        # []
gcd(6, 2)                                   # 2   -- so [1..6] with k=2 needs two cycles
```

`[1,2,3,4,5,6]` with `k = 2` is precisely the case that breaks a single-cycle
implementation, since `gcd(6, 2) = 2`. Use it as your test.

### The one-liner

```python
def rotate_slicing(nums, k):
    """O(n) space, one line. Note the slice assignment mutates in place."""
    n = len(nums)
    if n:
        k %= n
        nums[:] = nums[-k:] + nums[:-k] if k else nums
    return nums


rotate_slicing([1, 2, 3, 4, 5, 6, 7], 3)    # [5, 6, 7, 1, 2, 3, 4]
rotate_slicing([1, 2, 3], 0)                # [1, 2, 3]
rotate_slicing([], 3)                       # []
```

`nums[:] = ...` matters: plain `nums = ...` rebinds the local name and leaves the caller's
list untouched. Guarding `k != 0` matters too, because `nums[-0:]` is the **whole** list, not
an empty one - a genuinely nasty Python gotcha worth mentioning.

## 6. Complexity

| | Time | Space |
|---|---|---|
| Rotate by one, `k` times | `O(n * k)` | `O(1)` |
| Extra array / slicing | `O(n)` | `O(n)` |
| **Reversal** | **`O(n)`** | **`O(1)`** |
| **Cyclic replacement** | **`O(n)`** | **`O(1)`** |

The reversal version touches each element exactly **three** times (once per reversal, and
each reversal swaps half its range). Cyclic replacement touches each element **once**, so it
is better on constant factors - but it is harder to write correctly, and in an interview the
reversal version is almost always the right choice.

## 7. How to present it

1. **Restate**, and **ask whether `k` can exceed `n`** immediately. Then say `k %= n`.
2. **Give the `O(n)`-space answer** first, in one line, with its complexity.
3. **Then take the follow-up**: "For `O(1)` space, notice that rotating right is just
   swapping two adjacent blocks."
4. **Draw the blocks on the board** and show the three reversals on the seven-element
   example. This takes fifteen seconds and is far more convincing than the code.
5. **Give the one-sentence justification**: *"the first reversal puts the blocks in the right
   order but reverses their contents; the other two put each block's contents back."*
6. **Write it**, with a local `reverse(lo, hi)` helper - do not inline three copies of the
   swap loop.
7. **Test** `k = 0`, `k = n`, `k > n`, single element, and empty.
8. **Offer the alternative**: "there's also a cyclic-replacement version that touches each
   element once, but it splits into `gcd(n, k)` cycles so you have to handle that - `n = 6,
   k = 2` is the case that catches it." Mentioning `gcd` unprompted is a strong close.

## 8. Follow-ups and variations

- **"Do it in O(1) space."** The reversal, or cyclic replacement.
- **"There are at least three approaches - what are they?"** Extra array, reversal, cyclic
  replacement. LeetCode's hint says this explicitly, so have all three named.
- **"Rotate left instead."** Right by `n - k`, or reverse the three-step order. One line.
- **"Why does cyclic replacement need `gcd`?"** Because `i -> (i+k) mod n` generates a
  subgroup whose orbits have size `n / gcd(n, k)`, giving `gcd(n, k)` disjoint cycles. Give
  the `n=6, k=2` example rather than the group theory.
- **"Rotate a linked list right by k"** (LC 61). Find the length, connect the tail to the
  head to form a ring, then break it `n - k % n` steps along. Different mechanics, same idea.
- **"Rotate a matrix by 90 degrees"** (LC 48). Transpose then reverse each row - the same
  "two cheap in-place operations compose into the one you want" flavour. Worth naming as the
  2D cousin.
- **"Search in a rotated sorted array."** LC 33, at 5.2 - the rotation is the *input*, not
  the operation.
- **"Is B a rotation of A?"** `len(A) == len(B) and B in A + A`. A cute application.

## 9. Pitfalls

- **Forgetting `k %= n`.** The single most common bug. Test `k > n`.
- **Dividing by zero** on an empty array when computing `k % n`.
- **`nums[-0:]` being the whole list**, so the slicing version must special-case `k == 0`.
- **`nums = ...` instead of `nums[:] = ...`**, which rebinds locally and does not mutate the
  caller's list.
- **Rotating one step at a time** `k` times - `O(n*k)` and it will time out.
- **In cyclic replacement, running a single cycle** and covering only part of the array.
  `n=6, k=2` exposes it.
- **Off-by-one in the reversal bounds** - it is `reverse(0, k-1)` and `reverse(k, n-1)`.
- **Rotating left when asked to rotate right.** Check against the given example.
