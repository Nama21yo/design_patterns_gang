> Read [[3.3 Find All Anagrams in a String]] first if you have not.

## 1. Problem statement

Given two strings `s1` and `s2`, return `True` if `s2` contains a **permutation** of `s1` -
that is, if one of `s1`'s permutations is a **substring** of `s2`.

```
s1 = "ab", s2 = "eidbaooo"   ->  True     s2 contains "ba"
s1 = "ab", s2 = "eidboaoo"   ->  False
```

Both consist of lowercase English letters.

## 2. Clarifying questions

1. **Permutation means the same multiset of characters?** Yes - same characters with the same
   counts, contiguous in `s2`.
2. **Substring, not subsequence?** Substring. `"eidboaoo"` contains `b`...`a` but not
   adjacently, hence `False`. That example exists precisely to test this.
3. **Return a boolean, or the index?** A boolean here; the index is a trivial extension.
4. **Can `s1` be longer than `s2`?** Then `False`; guard it.
5. **Lowercase English only?** Stated, which licenses a 26-element array.
6. **Can either be empty?** LeetCode says length >= 1. An empty `s1` would trivially be
   `True`; ask.

## 3. Intuition

A permutation of `s1` has exactly `len(s1)` characters, so the window size is **fixed**. Slide
a window of that width across `s2` and ask whether its character counts equal `s1`'s.

> **Fixed-size window, frequency match, return `True` on the first hit.**

Because the window size is fixed, "contains at least all of `s1`'s characters" and "is exactly
a permutation of `s1`" are the same condition - there is no room for surplus. That is the same
observation as in 3.3 and it is what lets a single counter suffice.

### Three ways to test the match

**(a) Compare the whole `Counter`** - `O(26)` per position, so `O(26n)`. Simple and correct.

**(b) Track `matches`** - the number of letters (out of 26) whose window count **equals** the
target count. The window is a permutation exactly when `matches == 26`. Updating `matches`
costs `O(1)` per character entering or leaving, so the whole thing is a strict `O(n)`.

**(c) Track `missing`** - as in 3.3.

Formulation (b) is the one worth learning *here*, because it is the cleanest expression of
"compare two frequency maps in `O(1)`", and because it generalises to problems where surplus
matters. The update rule is small but fiddly, so the ordering below matters:

When a character's window count changes, it either **gains** a match, **loses** one, or
neither:

```
before the change: if window[c] == need[c], we are about to LOSE a match
after  the change: if window[c] == need[c], we have just GAINED one
```

Checking before and after, rather than trying to reason about the direction of the change,
is what keeps it correct.

## 4. Approach

1. If `len(s1) > len(s2)`, return `False`.
2. Build `need` and `window` as 26-element arrays; seed `window` with the first `len(s1)`
   characters of `s2`.
3. `matches` = number of letters where `need[i] == window[i]`.
4. Slide: for each new right character, add it and update `matches`; remove the outgoing
   character and update `matches`; if `matches == 26`, return `True`.
5. Return `False`.

## 5. Solution

```python
def check_inclusion(s1, s2):
    """True if some permutation of s1 is a substring of s2.

    Fixed-size window of len(s1). `matches` counts how many of the 26 letters currently
    have the right frequency; the window is a permutation exactly when all 26 agree.
    Updating `matches` is O(1) per character, so the whole scan is O(n).
    """
    m, n = len(s1), len(s2)
    if m > n:
        return False

    need = [0] * 26
    window = [0] * 26
    for ch in s1:
        need[ord(ch) - 97] += 1
    for ch in s2[:m]:
        window[ord(ch) - 97] += 1

    matches = sum(1 for i in range(26) if need[i] == window[i])
    if matches == 26:
        return True

    for right in range(m, n):
        enter = ord(s2[right]) - 97
        leave = ord(s2[right - m]) - 97

        # Check before and after each change, rather than reasoning about direction.
        if window[enter] == need[enter]:
            matches -= 1
        window[enter] += 1
        if window[enter] == need[enter]:
            matches += 1

        if window[leave] == need[leave]:
            matches -= 1
        window[leave] -= 1
        if window[leave] == need[leave]:
            matches += 1

        if matches == 26:
            return True

    return False
```

```python
check_inclusion("ab", "eidbaooo")       # True
check_inclusion("ab", "eidboaoo")       # False
check_inclusion("a", "a")               # True
check_inclusion("ab", "a")              # False
check_inclusion("abc", "ccccbbbbaaaa")  # False
check_inclusion("adc", "dcda")          # True
check_inclusion("hello", "ooolleoooleh")    # False
check_inclusion("aab", "aaab")          # True
check_inclusion("abcd", "abcd")         # True
check_inclusion("ab", "ba")             # True
```

`"abc"` in `"ccccbbbbaaaa"` -> **False** is the case that catches anyone testing "are the same
characters present" rather than "are they adjacent with the right counts". All three letters
appear, but never together in a window of three.

`"aab"` in `"aaab"` -> **True** (the window `"aab"` at index 1) is the duplicates test: a
`set` would accept `"ab"` too.

### The simple Counter version

```python
from collections import Counter


def check_inclusion_counter(s1, s2):
    """O(26n). Write this first - obviously correct, and 26 is a constant."""
    m, n = len(s1), len(s2)
    if m > n:
        return False

    need = Counter(s1)
    window = Counter(s2[:m])
    if window == need:
        return True

    for right in range(m, n):
        window[s2[right]] += 1
        out = s2[right - m]
        window[out] -= 1
        if window[out] == 0:
            del window[out]
        if window == need:
            return True

    return False


check_inclusion_counter("ab", "eidbaooo")       # True
check_inclusion_counter("ab", "eidboaoo")       # False
check_inclusion_counter("abc", "ccccbbbbaaaa")  # False
check_inclusion_counter("aab", "aaab")          # True
check_inclusion_counter("ab", "a")              # False
```

### Returning the index instead

```python
def find_permutation_index(s1, s2):
    """Start index of the first permutation of s1 in s2, or -1."""
    m, n = len(s1), len(s2)
    if m > n:
        return -1
    need = [0] * 26
    window = [0] * 26
    for ch in s1:
        need[ord(ch) - 97] += 1
    for right, ch in enumerate(s2):
        window[ord(ch) - 97] += 1
        if right >= m:
            window[ord(s2[right - m]) - 97] -= 1
        if right >= m - 1 and window == need:
            return right - m + 1
    return -1


find_permutation_index("ab", "eidbaooo")        # 3
find_permutation_index("ab", "eidboaoo")        # -1
find_permutation_index("adc", "dcda")           # 1
find_permutation_index("aab", "aaab")           # 1
```

This is the bridge to 3.3: collect these indices instead of returning the first, and you have
*Find All Anagrams*. Saying that explicitly is the cleanest way to show you see them as one
problem.

## 6. Complexity

Let `m = len(s1)`, `n = len(s2)`, `k = 26`.

| | Time | Space |
|---|---|---|
| Sort each window and compare | `O(n * m log m)` | `O(m)` |
| Rebuild a Counter per window | `O(n * m)` | `O(k)` |
| Slide + full comparison | `O(n * k)` | `O(k)` |
| **Slide + `matches` counter** | **`O(n)`** | `O(k)` |

Space is `O(26)`, i.e. `O(1)` for a fixed alphabet. Note again that `O(26n)` is linear -
being precise that 26 is a constant, not a variable, is the right framing.

Best case is better than the worst: the early return means you stop at the first match.

## 7. How to present it

1. **Restate, and confirm substring rather than subsequence**, using the second example.
2. **Immediately name the connection**: *"This is Find All Anagrams returning a boolean - same
   fixed-size window, same frequency match, but I return on the first hit."* If you have
   already discussed 3.3, this saves five minutes and shows pattern recognition.
3. **Note the window size is fixed** at `len(s1)`, so there is no shrink decision.
4. **Write the Counter version first** and state `O(26n)`, explicitly calling 26 a constant.
5. **Offer the `matches` refinement** for strict `O(1)` per step, and explain the
   check-before-and-after rule as you write it - that is the only tricky part.
6. **Test** `"abc"` in `"ccccbbbbaaaa"` (the adjacency test) and `"aab"` in `"aaab"` (the
   duplicates test).
7. **Close**: `O(n)` time, `O(1)` space for a bounded alphabet, with an early exit on the
   first match. Offer the index-returning variant as the bridge to 3.3.

## 8. Follow-ups and variations

- **"Return all the starting indices."** That is 3.3 exactly - collect instead of returning.
- **"Return the first index."** `find_permutation_index` above.
- **"Minimum Window Substring"** (LC 76). The **variable**-size cousin: shortest window
  containing all of `s1`'s characters, with surplus allowed. Same bookkeeping, plus a shrink
  loop. The natural harder follow-up - be ready to describe it even if you do not write it.
- **"What if the alphabet is Unicode?"** Use a dict; the 26-array assumption breaks. Say the
  constraint aloud when you rely on it.
- **"Case insensitive, or ignoring spaces."** Normalise on entry.
- **"Is `s2` a permutation of `s1`?"** (whole strings, not substrings) - just
  `Counter(s1) == Counter(s2)`, or `sorted(s1) == sorted(s2)`.
- **"Permutation of `s1` as a subsequence of `s2`?"** Completely different and much easier -
  it reduces to "does `s2` contain at least `s1`'s character counts anywhere", a single
  `Counter` comparison with no window.
- **"What if `s1` may contain characters absent from `s2`?"** Handled; `matches` never
  reaches 26.
- **"Stream `s2`."** Works as-is: fixed memory, one pass, `m` characters of lookbehind.

## 9. Pitfalls

- **Solving for subsequence rather than substring** - `"eidboaoo"` returns `True`.
- **Using a `set` instead of counts** - `"aab"` and `"ab"` become indistinguishable.
- **Rebuilding the frequency map per window**, making it `O(n*m)`.
- **In the `matches` version, updating the counter without checking before and after** the
  change. Both checks are needed; one alone drifts.
- **Updating `matches` for the entering and leaving characters in a single combined step**
  when they happen to be the same letter - handling them as two independent
  check/change/check sequences avoids the special case entirely.
- **Forgetting the `len(s1) > len(s2)` guard**, producing negative slice indices.
- **Not seeding the initial window** before the slide loop, so the first `m` characters are
  never tested.
- **Using a 26-element array without confirming the alphabet.**
