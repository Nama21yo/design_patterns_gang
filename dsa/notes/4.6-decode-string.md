**Difficulty:** Medium | **LeetCode #394**
**Bloomberg frequency:** 75% at three months.

**Reported from a real Bloomberg Round 1** on 2025-11-06.

The canonical **parsing with nesting** problem: recursive descent implemented with an
explicit stack. The idea is simple; the execution is fiddly, and the fiddliness is entirely
about **what you push and when**.

## 1. Problem statement

Given an encoded string, return its decoded form.

The encoding rule is `k[encoded_string]`, where the string inside the square brackets is
repeated exactly `k` times. `k` is guaranteed to be a **positive integer** and the input is
always valid.

```
s = "3[a]2[bc]"       ->  "aaabcbc"
s = "3[a2[c]]"        ->  "accaccacc"
s = "2[abc]3[cd]ef"   ->  "abcabccdcdcdef"
```

## 2. Clarifying questions

1. **Can `k` be multi-digit?** Yes - `"10[a]"` is valid, and parsing digits one at a time is
   the first bug people hit. **Ask**, or just handle it and say so.
2. **Can brackets nest?** Yes - example 2. This is what forces a stack rather than a single
   pass.
3. **Is the input guaranteed well-formed?** Yes - no unmatched brackets, no malformed
   numbers, no digits in the decoded output. That removes a lot of error handling; confirm it.
4. **Can `k` be 0?** LeetCode says `k` is positive. Ask - `0[abc]` would be an empty string,
   which the code handles but is worth confirming.
5. **How large can the output be?** Up to 10^5 on LeetCode. Nested repeats multiply, so the
   output can be far larger than the input - worth noting.
6. **Are there other characters?** Lowercase letters only.

## 3. Intuition

Scan left to right. At any moment you are building up a **current string**. There are exactly
four kinds of character, and each has one job:

| Character | Action |
|---|---|
| digit | accumulate into the current number (`num = num * 10 + digit`) |
| `[` | **push** the current string and the current number; reset both |
| `]` | **pop** the saved string and count; set current = saved + current * count |
| letter | append to the current string |

> **The stack holds the *context you will need to restore*: the text built before the bracket
> opened, and how many times the bracket's contents must repeat.**

That one sentence is the answer. Everything else follows.

### The two things to get right

**(a) Multi-digit numbers.** `num = num * 10 + int(ch)` accumulated across consecutive
digits, reset to 0 on `[`. Treating each digit separately breaks `"10[a]"` into `1[a]` then
`0[a]`.

**(b) What `[` pushes.** It pushes the string built *so far* - not the string inside the
brackets, which does not exist yet. On `]`, the finished inner string is repeated and
**appended** to the saved outer string. Getting the order backwards (`current * count + saved`)
reverses the output.

Trace `"3[a2[c]]"` to see the nesting work:

| char | current | num | stack |
|---|---|---|---|
| `3` | `""` | 3 | `[]` |
| `[` | `""` | 0 | `[("", 3)]` |
| `a` | `"a"` | 0 | `[("", 3)]` |
| `2` | `"a"` | 2 | `[("", 3)]` |
| `[` | `""` | 0 | `[("", 3), ("a", 2)]` |
| `c` | `"c"` | 0 | `[("", 3), ("a", 2)]` |
| `]` | `"acc"` | 0 | `[("", 3)]` |
| `]` | `"accaccacc"` | 0 | `[]` |

That table is what to draw on the board. The two pops happening in reverse order of the
pushes is the nesting.

## 4. Approach

1. `stack = []`, `current = []` (a list of pieces), `num = 0`.
2. For each character:
   - digit: `num = num * 10 + int(ch)`
   - `[`: push `(current, num)`; reset `current = []`, `num = 0`
   - `]`: pop `(prev, count)`; `current = prev + current * count`
   - otherwise: append to `current`
3. Return `"".join(current)`.

Using a **list of pieces** rather than a string avoids quadratic concatenation.

## 5. Solution

```python
def decode_string(s):
    """Decode k[encoded] strings, with arbitrary nesting.

    The stack holds the context to restore: the text built before the bracket opened
    and the repeat count for the bracket's contents. Pieces are kept in a list rather
    than a string so that appending stays O(1) instead of O(n).
    """
    stack = []              # (pieces built before this bracket, repeat count)
    current = []            # pieces of the string being built right now
    num = 0                 # the number currently being parsed

    for ch in s:
        if ch.isdigit():
            # Accumulate: k can be multi-digit, e.g. 10[a].
            num = num * 10 + int(ch)
        elif ch == "[":
            # Save the outer context and start a fresh inner string.
            stack.append((current, num))
            current = []
            num = 0
        elif ch == "]":
            # Finish the inner string, repeat it, and append to the outer one.
            prev, count = stack.pop()
            prev.append("".join(current) * count)
            current = prev
        else:
            current.append(ch)

    return "".join(current)
```

```python
decode_string("3[a]2[bc]")          # 'aaabcbc'
decode_string("3[a2[c]]")           # 'accaccacc'
decode_string("2[abc]3[cd]ef")      # 'abcabccdcdcdef'
decode_string("abc")                # 'abc'
decode_string("")                   # ''
decode_string("10[a]")              # 'aaaaaaaaaa'
decode_string("2[2[2[a]]]")         # 'aaaaaaaa'
decode_string("3[a]b2[c]")          # 'aaabcc'
decode_string("100[leetcode]")[:20] # 'leetcodeleetcodeleet'
decode_string("2[ab3[c]]")          # 'abcccabccc'
```

`"10[a]"` is the multi-digit test and `"2[2[2[a]]]"` is the deep-nesting test - three levels
producing `2*2*2 = 8` characters. Run both out loud.

### The recursive version

Often clearer to write and to explain, and it makes the "this is recursive descent" point
explicit:

```python
def decode_string_recursive(s):
    """Same algorithm expressed as recursive descent. The index is carried in a
    mutable cell so the recursive calls agree on how far they have consumed."""
    def parse(i):
        """Decode from index i until a ']' or the end; returns (text, next index)."""
        pieces = []
        num = 0
        while i < len(s):
            ch = s[i]
            if ch.isdigit():
                num = num * 10 + int(ch)
                i += 1
            elif ch == "[":
                inner, i = parse(i + 1)     # consume past '[' and recurse
                pieces.append(inner * num)
                num = 0
            elif ch == "]":
                return "".join(pieces), i + 1   # consume the ']' and return
            else:
                pieces.append(ch)
                i += 1
        return "".join(pieces), i

    return parse(0)[0]


decode_string_recursive("3[a]2[bc]")        # 'aaabcbc'
decode_string_recursive("3[a2[c]]")         # 'accaccacc'
decode_string_recursive("2[abc]3[cd]ef")    # 'abcabccdcdcdef'
decode_string_recursive("10[a]")            # 'aaaaaaaaaa'
decode_string_recursive("2[2[2[a]]]")       # 'aaaaaaaa'
decode_string_recursive("")                 # ''
```

The recursion depth equals the nesting depth, which is small in practice - but say that you
would prefer the iterative version if nesting could be deep, because Python's limit is 1000.

### Two stacks instead of one

Some people find this clearer, and it is worth recognising if an interviewer writes it:

```python
def decode_string_two_stacks(s):
    """Equivalent, with the strings and counts in separate stacks."""
    count_stack = []
    string_stack = []
    current = ""
    num = 0
    for ch in s:
        if ch.isdigit():
            num = num * 10 + int(ch)
        elif ch == "[":
            count_stack.append(num)
            string_stack.append(current)
            num = 0
            current = ""
        elif ch == "]":
            current = string_stack.pop() + current * count_stack.pop()
        else:
            current += ch
    return current


decode_string_two_stacks("3[a2[c]]")        # 'accaccacc'
decode_string_two_stacks("2[abc]3[cd]ef")   # 'abcabccdcdcdef'
decode_string_two_stacks("10[a]")           # 'aaaaaaaaaa'
```

Note this one uses `current += ch`, which is `O(n^2)` in the worst case. Fine for the
constraints, but the list-of-pieces version is the one to prefer, and being able to say why
is worth a point.

## 6. Complexity

Let `n` be the input length and `m` the **output** length.

| | Time | Space |
|---|---|---|
| Stack, list of pieces | `O(n + m)` | `O(m)` |
| Stack, string concatenation | `O(n * m)` worst case | `O(m)` |
| Recursive | `O(n + m)` | `O(m)` plus `O(depth)` stack |

The key point: **the output can be exponentially larger than the input**. `"2[2[2[2[a]]]]"`
is 13 characters and produces 16; with larger multipliers it grows much faster. So the honest
bound is in terms of the output size, and the algorithm is **output-optimal** - you cannot do
better than writing the answer down.

Saying "`O(n + m)` where `m` is the output length, and `m` can be exponential in `n`" is a
much better answer than `O(n)`.

## 7. How to present it

1. **Restate**, and **ask about multi-digit `k`** immediately - it is the first real
   decision.
2. **Confirm nesting is possible**, and say what that implies: *"nesting means I need a
   stack, or recursion - a single pass with one counter won't do."*
3. **Enumerate the four character types and their actions** before writing anything. Draw the
   small table. That *is* the algorithm, and getting agreement on it makes the code
   mechanical.
4. **State clearly what the stack holds**: *"the text built before the bracket opened, and
   the repeat count - the context I'll restore when the bracket closes."*
5. **Announce**, then write it. Call out the two traps as you reach them: the multi-digit
   accumulation, and the fact that `[` pushes the *outer* string.
6. **Trace `"3[a2[c]]"`** with the table above. This is the single most convincing thing you
   can do here; the nested pops make the structure obvious.
7. **Mention the list-of-pieces choice**: *"I'm collecting into a list and joining, because
   `+=` on strings in a loop is quadratic."*
8. **Test** `"10[a]"`, `"2[2[2[a]]]"`, and a plain string with no brackets.
9. **Close**: `O(n + m)` time and `O(m)` space, and note the output can be exponentially
   larger than the input. Offer the recursive version as the alternative framing.

## 8. Follow-ups and variations

- **"Write it recursively."** Shown above. Say that the two are the same algorithm, one with
  an explicit stack and one with the call stack.
- **"What if the input might be malformed?"** Now you need real error handling: unmatched
  `]` (empty stack on pop), unmatched `[` (non-empty stack at the end), missing count.
  Good follow-up, and it mirrors 4.5's two failure modes.
- **"What if `k` could be 0?"** `"".join(current) * 0` is `""`, so it already works - but
  confirm it is intended rather than a malformed input.
- **"Encode a string"** - the inverse problem. Much harder and under-specified: you would
  need to define what "best" encoding means (shortest?), which becomes a DP.
- **"What if the decoded string is too large to materialise?"** Return a generator, or answer
  queries like "what is the character at index `i`?" without expanding - that is LC 880,
  *Decoded String at Index*, and it works by computing sizes and walking backwards. A genuinely
  good follow-up to name.
- **"Nested ternary / arithmetic expression evaluation."** Same recursive-descent shape -
  connect it to 4.2 *Basic Calculator*, which is the arithmetic version of this exact
  technique.
- **"Number of Atoms"** (LC 726) - chemical formula parsing, the same stack-of-contexts
  pattern with a counter map instead of a string.
- **"What if brackets could be of several types?"** Combine with 4.5's matching logic.

## 9. Pitfalls

- **Parsing digits one at a time**, breaking `"10[a]"`.
- **Forgetting to reset `num = 0` after `[`**, so a later bracket reuses a stale count.
- **Forgetting to reset `current` after `[`**, so the outer text is duplicated inside.
- **Appending in the wrong order on `]`** - it is `outer + inner * count`, not
  `inner * count + outer`.
- **Pushing the inner string instead of the outer one** at `[`.
- **Using `current += ch` in a loop**, which is quadratic. Use a list and `join`.
- **Assuming a fixed nesting depth** and using a fixed number of variables instead of a
  stack.
- **Claiming `O(n)` time** when the output can be exponentially larger than the input.
- **In the recursive version, losing track of the index** - the parse function must return
  how far it consumed, or the caller resumes in the wrong place.
