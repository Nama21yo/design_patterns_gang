**Difficulty:** Medium | **LeetCode #904**
**Bloomberg frequency:** 38% at three months.

**"Longest subarray with at most 2 distinct values", dressed up as a story.** The entire
difficulty is translating the story into that sentence. Once you have, it is the standard
at-most-k-distinct window with `k = 2`.

## 1. Problem statement

You are visiting a farm with a single row of fruit trees. `fruits[i]` is the **type** of
fruit the `i`-th tree produces.

You have **two baskets**, and each basket can hold only **one type** of fruit. Starting from
any tree, you must pick **exactly one fruit from every tree** (including the start tree)
while moving right, and you stop once you reach a tree whose fruit cannot fit in your
baskets.

Return the **maximum number of fruits** you can pick.

```
fruits = [1,2,1]      ->  3    all of them: types {1,2}
fruits = [0,1,2,2]    ->  3    [1,2,2], types {1,2}
fruits = [1,2,3,2,2]  ->  4    [2,3,2,2], types {2,3}
```

## 2. Clarifying questions

1. **So this is "longest contiguous subarray with at most 2 distinct values"?** Say this
   back explicitly and get confirmation. It is the whole translation, and doing it out loud
   is the single most valuable thing on this question.
2. **Must I pick from *every* tree in the range?** Yes - so the range is contiguous. That is
   what makes it a window rather than a subsequence problem.
3. **Can I skip a tree?** No.
4. **Do I have to use both baskets?** No - "at most" two types, so a single type is fine.
5. **Return the count of fruits, or the types?** The count, which is the window length.
6. **Can the array be empty?** Return 0.
7. **How many distinct fruit types exist?** Arbitrary; `fruits[i]` can be up to `n - 1`, so
   use a dict rather than a fixed array.

## 3. Intuition

Strip away the story:

> **Two baskets, one type each, pick from every tree in a contiguous run = the longest
> contiguous subarray containing at most 2 distinct values.**

That is the standard at-most-k-distinct window from the primer, with `k = 2`.

- Grow `right`, adding `fruits[right]` to a count map.
- While the map holds more than 2 distinct types, shrink from the left.
- Record the window length after each step.

The window is valid because distinct-count is monotonic in the window size: shrinking can
only remove types, never add them.

### The `del` that matters

`len(counts)` must be exactly the number of distinct types **currently in the window**. So
when a type's count falls to zero, **delete the key**. Leaving a zero-count entry makes
`len(counts)` too large, and the window shrinks further than it should - producing answers
that are too small.

This is the single most common bug in every at-most-k-distinct problem, and it is silent:
you get a plausible but wrong number. Say the `del` out loud as you write it.

An alternative that avoids `del` is to keep a separate `distinct` counter, incremented when a
count goes 0 -> 1 and decremented when it goes 1 -> 0. Equivalent; pick one and be
consistent.

## 4. Approach

1. `counts = defaultdict(int)`, `left = 0`, `best = 0`.
2. For each `right`, `f`:
   - `counts[f] += 1`
   - while `len(counts) > 2`: decrement `counts[fruits[left]]`, `del` if zero, `left += 1`
   - `best = max(best, right - left + 1)`
3. Return `best`.

## 5. Solution

```python
from collections import defaultdict


def total_fruit(fruits):
    """Longest contiguous run containing at most 2 distinct fruit types.

    The two baskets are a limit of 2 distinct values; picking from every tree makes
    the range contiguous. So this is the standard at-most-k-distinct window, k = 2.
    """
    counts = defaultdict(int)
    left = 0
    best = 0

    for right, f in enumerate(fruits):
        counts[f] += 1

        # More than two types in the window: shrink from the left until it fits.
        while len(counts) > 2:
            leaving = fruits[left]
            counts[leaving] -= 1
            if counts[leaving] == 0:
                del counts[leaving]     # so len(counts) is exactly the distinct count
            left += 1

        best = max(best, right - left + 1)

    return best
```

```python
total_fruit([1, 2, 1])                          # 3
total_fruit([0, 1, 2, 2])                       # 3
total_fruit([1, 2, 3, 2, 2])                    # 4
total_fruit([3, 3, 3, 1, 2, 1, 1, 2, 3, 3, 4])  # 5
total_fruit([])                                 # 0
total_fruit([1])                                # 1
total_fruit([1, 1, 1, 1])                       # 4
total_fruit([1, 2])                             # 2
total_fruit([1, 2, 3])                          # 2
total_fruit([0, 1, 6, 6, 4, 4, 6])              # 5
```

`[3,3,3,1,2,1,1,2,3,3,4]` -> **5** is the one to trace: the answer is `[1,2,1,1,2]` at
indices 3..7, types `{1,2}`. The leading run of three `3`s is a red herring, and the trailing
`3,3` cannot join because `4` follows. It is a good test that the window really is shrinking
correctly rather than latching onto the first two types it sees.

`[0,1,6,6,4,4,6]` -> **5** is the other good one: the answer is `[6,6,4,4,6]`, types `{6,4}`.

### The generalised k-distinct version

Since this *is* the general problem, write it that way and call it with `k = 2`:

```python
from collections import defaultdict


def longest_k_distinct(values, k):
    """Longest contiguous subarray with at most k distinct values (LC 340)."""
    counts = defaultdict(int)
    left = 0
    best = 0
    for right, x in enumerate(values):
        counts[x] += 1
        while len(counts) > k:
            leaving = values[left]
            counts[leaving] -= 1
            if counts[leaving] == 0:
                del counts[leaving]
            left += 1
        best = max(best, right - left + 1)
    return best


longest_k_distinct([1, 2, 3, 2, 2], 2)          # 4
longest_k_distinct([3, 3, 3, 1, 2, 1, 1, 2, 3, 3, 4], 2)    # 5
longest_k_distinct("eceba", 2)                  # 3
longest_k_distinct("aa", 1)                     # 2
longest_k_distinct([1, 2, 3], 0)                # 0
longest_k_distinct([1, 2, 3], 5)                # 3
```

Writing the general version and instantiating it is a good move in the interview: it costs
nothing, it demonstrates you saw past the story, and it pre-empts the obvious follow-up.

### The `distinct`-counter variant, avoiding `del`

```python
from collections import defaultdict


def total_fruit_counter(fruits):
    """Equivalent, tracking the distinct count explicitly instead of deleting keys."""
    counts = defaultdict(int)
    distinct = 0
    left = 0
    best = 0
    for right, f in enumerate(fruits):
        if counts[f] == 0:
            distinct += 1
        counts[f] += 1
        while distinct > 2:
            leaving = fruits[left]
            counts[leaving] -= 1
            if counts[leaving] == 0:
                distinct -= 1
            left += 1
        best = max(best, right - left + 1)
    return best


total_fruit_counter([1, 2, 3, 2, 2])                        # 4
total_fruit_counter([3, 3, 3, 1, 2, 1, 1, 2, 3, 3, 4])      # 5
total_fruit_counter([])                                     # 0
```

## 6. Complexity

| | Time | Space |
|---|---|---|
| Brute force over all subarrays | `O(n^2)` | `O(k)` |
| **Sliding window** | **`O(n)` amortised** | `O(k)` |

`left` only moves forward, so the inner `while` does `O(n)` total work across the whole run.
Space is `O(k)` - at most `k+1` entries in the map at any moment - which for `k = 2` is
`O(1)`.

## 7. How to present it

1. **Translate the story first, out loud**: *"Two baskets each holding one type, and I must
   pick from every tree in the range - so this is the longest contiguous subarray with at
   most two distinct values. Is that right?"* **This is the entire question.** Everything
   after it is a template.
2. **Confirm "at most" rather than "exactly" two.**
3. **Name the pattern** and the skeleton: grow right, shrink while more than 2 distinct,
   record.
4. **Justify the window**: distinct-count is monotonic in the window size.
5. **Write the generalised `k` version** and call it with `k = 2`. Say why: the story is
   incidental, and the follow-up is obviously "what about k baskets".
6. **Call out the `del`** as you write it, and say what goes wrong without it - `len(counts)`
   over-counts and the window over-shrinks.
7. **Trace `[3,3,3,1,2,1,1,2,3,3,4]`** and show the answer is the middle run, not the
   leading one.
8. **Close**: `O(n)` amortised time, `O(k)` space, and the amortised argument for the nested
   loop.

## 8. Follow-ups and variations

- **"What if there were `k` baskets?"** Already written - LC 340, *Longest Substring with At
  Most K Distinct Characters*.
- **"Exactly `k` distinct instead of at most `k`."** The window cannot express it directly;
  use `atMost(k) - atMost(k-1)` for counting problems (LC 992), or track the longest window
  with exactly `k` by running two windows. Name the at-most trick from the primer.
- **"Return the fruits picked, not the count."** Track the best start index and slice.
- **"At most two distinct, but you may also skip up to `d` trees."** The window breaks; it
  becomes a DP. Good example of a follow-up that changes the technique.
- **"Longest substring with at most 2 distinct characters"** (LC 159) - literally the same
  problem on a string.
- **"Subarrays with exactly k distinct"** (LC 992) - the counting cousin, using the at-most
  trick and `total += right - left + 1`.
- **"What if the fruit types are unbounded integers?"** The dict handles it; a fixed-size
  array would not. Worth saying, since `fruits[i]` can be as large as `n - 1`.
- **"Streaming trees."** Works as-is: one pass, `O(k)` memory.

## 9. Pitfalls

- **Not deleting zero-count keys**, so `len(counts)` over-counts and the window shrinks too
  far. Silent wrong answers - the defining bug.
- **Misreading "at most two" as "exactly two"**, which breaks `[1,1,1,1]` (should be 4).
- **Using a `set` of types** without counts, so you cannot tell when a type has fully left
  the window.
- **`if` instead of `while`** when shrinking.
- **Tracking only the two types rather than their counts**, which fails on
  `[1,2,1,2,3]`-style inputs where one type recurs.
- **Recording the answer inside the shrink loop.** This is a *longest* window problem, so
  record after.
- **Computing the length as `right - left`.**
- **Getting lost in the story** and trying to simulate baskets literally.
