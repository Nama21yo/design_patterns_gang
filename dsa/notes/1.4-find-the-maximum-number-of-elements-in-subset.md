**Bloomberg frequency:** 62% in the **30-day** window.

A recent, less-drilled question, which makes it more likely to be asked cold. The pattern is
"frequency map plus a walk", and the traps are `x = 1` and integer overflow in the chain.

## 1. Problem statement

Given an array of **positive** integers `nums`, select a subset that can be arranged into the
palindromic pattern

```
[x, x^2, x^4, ..., x^(k/2), x^k, x^(k/2), ..., x^4, x^2, x]
```

where `k` is a non-negative power of 2. Return the **maximum number of elements** in such a
subset.

```
nums = [5,4,1,2,2]  ->  3     the subset {4,2,2} arranged as [2,4,2]
nums = [1,3,2,4]    ->  1     any single element
```

`[2,4,16,4,2]` and `[3,9,3]` follow the pattern. `[2,4,8,4,2]` does **not**, because 8 is not
`4^2`.

Constraints: `2 <= len(nums) <= 10^5`, `1 <= nums[i] <= 10^9`.

## 2. Clarifying questions

1. **Does the subset have to be contiguous?** No - it is a subset, and you may arrange it
   freely. So only the multiset of values matters.
2. **Can `k` be 1?** Yes, `k = 1` is `2^0`, giving the pattern `[x]` - a single element. So
   the answer is at least 1 and never 0.
3. **Is `[x, x, x]` valid for an ordinary `x`?** **No**, and this is the sharpest trap in the
   question. `k` must be a power of two, and `k = 2^0 = 1` degenerates the pattern to just
   `[x]` - there is no `x^(k/2)` term when `k = 1`. The smallest pattern that uses a value
   twice is `[x, x^2, x]` with `k = 2`, which needs `x^2` to be present. So three copies of
   `2` with no `4` gives an answer of **1**, not 3.
4. **Are duplicates in `nums` usable?** Yes, and they are essential: `[2,4,2]` needs two `2`s.
5. **Can `x = 1`?** Yes, and it is the special case that breaks the general logic, because
   `1^2 == 1`.
6. **How large can the values get?** Up to `10^9`, so squaring repeatedly overflows a 64-bit
   integer quickly. In Python integers are unbounded, but you must still **stop early** or
   the loop wastes time. In C++/Java this is a real overflow bug.

## 3. Intuition

Reading the pattern carefully: the array is a **palindrome** whose values are
`x, x^2, x^4, ...` doubling the exponent each step up to a peak `x^k`, then mirroring back
down.

So the subset is fully determined by two things: the base `x`, and how far up the chain you
can go. Every value except the peak appears **exactly twice**; the peak appears **once**.

That gives the algorithm directly:

> **For each candidate base `x`, walk `x -> x^2 -> x^4 -> ...` while the current value
> appears at least twice. When it stops, add one more element if the next value is present
> at all (it becomes the single peak).**

If the chain from `x` has `t` values that each appear twice, the arrangement has `2t`
elements plus possibly `1` for the peak - and the total is always **odd**, because a
palindrome with a unique centre has odd length.

### The `x = 1` special case

For `x = 1` the chain never moves: `1^2 == 1`. So the general walk loops forever. Handle it
separately: with `c` copies of `1`, the best arrangement is all of them if `c` is odd, or
`c - 1` if `c` is even, because the length must be odd (a single centre). At least 1.

```
counts[1] = 5  ->  5      [1,1,1,1,1]
counts[1] = 4  ->  3      one must be left out
counts[1] = 1  ->  1
```

This is the trap in the question and the thing an interviewer will check.

## 4. Approach

1. Build `counts = Counter(nums)`.
2. Handle `x = 1` separately as above; seed `best` with it.
3. For each distinct `x > 1`:
   - `length = 0`, `current = x`
   - while `counts.get(current, 0) >= 2`: `length += 2`, `current = current * current`
   - if `counts.get(current, 0) >= 1`: `length += 1` (this value is the peak)
   - else `length -= 1` ... **careful**: if the chain stopped without a usable peak, the
     last doubled pair must instead donate one element as the centre, so the length is
     `length - 1`. Equivalently, take `max(length - 1, 1)`.
   - `best = max(best, length)`
4. Return `best`.

Step 3's final adjustment is the fiddly bit. Reason it out: if you have pairs for
`x, x^2, ..., x^(2^(t-1))` but the next value is absent, you cannot use all `2t` elements,
because the palindrome needs a unique centre. You drop one, giving `2t - 1`.

## 5. Solution

```python
from collections import Counter


def maximum_length(nums):
    """Largest subset arrangeable as [x, x^2, x^4, ..., x^k, ..., x^4, x^2, x].

    Every value except the peak is used twice, so walk the squaring chain while the
    current value has at least two copies, then add a single peak if one exists.
    The result is always odd, because the palindrome has a unique centre.
    """
    counts = Counter(nums)

    # x = 1 is special: 1^2 == 1, so the chain never advances. Use as many 1s as
    # possible while keeping the length odd.
    ones = counts.get(1, 0)
    best = ones if ones % 2 == 1 else max(ones - 1, 1)

    for x in counts:
        if x == 1:
            continue
        length = 0
        current = x
        # Each value below the peak must appear at least twice, once on each side.
        while counts.get(current, 0) >= 2:
            length += 2
            current = current * current
            # 1e9 squared already exceeds any value in nums, so nothing further can match.
            if current > 10 ** 9:
                break
        # The value where the chain stopped can serve as the single centre if present;
        # otherwise drop one element from the last pair to make the length odd.
        if counts.get(current, 0) >= 1:
            length += 1
        else:
            length -= 1
        best = max(best, length)

    return max(best, 1)
```

```python
maximum_length([5, 4, 1, 2, 2])         # 3
maximum_length([1, 3, 2, 4])            # 1
maximum_length([2, 4, 16, 4, 2])        # 5
maximum_length([3, 9, 3])               # 3
maximum_length([2, 4, 8, 4, 2])         # 3
maximum_length([1, 1, 1, 1])            # 3
maximum_length([1, 1, 1])               # 3
maximum_length([1, 1])                  # 1
maximum_length([5, 5])                  # 1
maximum_length([2, 2, 2])               # 1
```

Three of those deserve a spoken explanation:

- `[2,4,8,4,2]` gives **3**, not 5, because `8 != 4^2`. The chain is `2` (twice), then `4`
  (twice), then `16` which is absent - so `2` and `4` give 4 elements, minus one for the
  centre rule, is 3. That is `[2,4,2]`.
- `[1,1,1,1]` gives **3**: four `1`s, but the length must be odd.
- `[5,5]` gives **1**: `5` appears twice, but `25` is absent, so `2 - 1 = 1`.
- `[2,2,2]` also gives **1**, for the same reason - three copies of a value are useless
  without its square, because `[x,x,x]` is not a legal pattern. Only `x = 1` escapes this,
  since `1^2 == 1` makes `[1,1,1]` the legal pattern `[x, x^2, x]`.

## 6. Complexity

Let `n = len(nums)` and `d` the number of distinct values.

| | Time | Space |
|---|---|---|
| Build the counter | `O(n)` | `O(d)` |
| Walk all chains | `O(d log log M)` | `O(1)` |
| **Total** | **`O(n)` in practice** | `O(d)` |

The chain length is tiny: starting from `x >= 2`, squaring reaches `10^9` in at most 5 steps
(2, 4, 16, 256, 65536, ~4.3e9). So each walk is effectively constant and the whole thing is
linear in the input. Say "at most about 5 iterations per base, because squaring grows
doubly-exponentially" - it is a much better answer than quoting a log-log bound nobody wants
to parse.

## 7. How to present it

1. **Decode the pattern out loud first.** "So it's a palindrome where the exponents double
   going up and mirror coming down - which means every value appears twice except the peak,
   which appears once. That makes the length always odd."
   Arriving at "every value twice except the peak" is the whole problem; say it before
   anything else.
2. **Note the subset is unordered**, so only the value counts matter - hence a `Counter`.
3. **Announce**: "For each distinct base, I walk the squaring chain while the value has at
   least two copies, then add one for the peak."
4. **Raise `x = 1` yourself** before coding. "One is special - one squared is one, so the
   chain never advances and the loop would spin. I'll handle it separately with a parity
   rule." Spotting this unprompted is the strongest move available here.
5. **Raise the growth bound**: "values go up to 1e9, so the chain is at most about five
   steps - and in a language with fixed-width integers I'd need an overflow guard."
6. **Code it**, explaining the `length - 1` adjustment when the peak is missing.
7. **Test** `[2,4,8,4,2]` -> 3, `[1,1,1,1]` -> 3, `[5,5]` -> 1.

## 8. Follow-ups and variations

- **"Why is the answer always odd?"** A palindrome with a distinct centre element has odd
  length; every non-centre value is mirrored. Good, quick, and it validates the whole model.
- **"What if the exponents increased by 1 instead of doubling?"** The chain becomes
  `x, x^2, x^3, ...` - much longer, and now the walk is `O(log_x M)` per base, still small.
  The code barely changes; the overflow guard matters more.
- **"What if negative numbers were allowed?"** Squaring makes signs collapse, so `-2` and `2`
  both lead to `4`. You would need to decide whether `[-2, 4, -2]` counts. Worth raising as
  a question rather than assuming.
- **"Return the actual subset, not the size."** Record the chain as you walk it and emit the
  palindrome. Cheap.
- **"What if you may use each element only once across all bases?"** Now the bases compete
  for elements and it becomes a much harder optimisation - say that it changes the problem
  from "max over independent chains" to a matching/packing problem.
- **"Can you avoid `Counter`?"** Sort and group, `O(n log n)` - strictly worse.
- **"Overflow in C++/Java."** `current * current` on a value near `10^9` overflows a 64-bit
  signed integer on the second squaring. Guard with `if current > 10**9: break` **before**
  multiplying, or use `unsigned long long` with a bound check. This is a strong point to
  volunteer, since Python hides the bug.

## 9. Pitfalls

- **Infinite loop on `x = 1`.** The single biggest trap. `1 * 1 == 1` forever.
- **Forgetting the odd-length rule** and returning `2t` when the peak is missing.
- **Using `>= 1` instead of `>= 2`** in the chain condition, which lets a value with one copy
  serve on both sides.
- **Not guarding the squaring**, which in Python merely wastes time on huge integers and in
  C++/Java is undefined behaviour.
- **Iterating over `nums` instead of `counts`**, repeating work for every duplicate - still
  correct, but `O(n)` chains instead of `O(d)`.
- **Mutating `counts` while iterating it** if you try to "consume" elements as you go.
- **Returning 0** for an input where no chain works; the minimum is always 1.
- **Misreading the pattern** as `x, 2x, 4x` (arithmetic doubling) rather than squaring. The
  `[2,4,8,4,2]` counterexample in the prompt exists precisely to catch that.
