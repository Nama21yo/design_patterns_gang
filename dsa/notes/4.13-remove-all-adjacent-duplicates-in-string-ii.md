## 1. Problem statement

You are given a string `s` and an integer `k`. A **k-duplicate removal** consists of choosing
`k` **adjacent and equal** letters from `s` and removing them, causing the left and right
sides of the deleted substring to concatenate.

Repeat until no more removals can be made. Return the final string. The answer is guaranteed
to be unique.

```
s = "abcd",           k = 2  ->  "abcd"      nothing to remove
s = "deeedbbcccbdaa", k = 3  ->  "aa"
s = "pbbcggttciiippooaais", k = 2  ->  "ps"
```

## 2. Clarifying questions

1. **Exactly `k` at a time, or `k` or more?** **Exactly `k`.** This is the crucial
   distinction from the reported Bloomberg variant (23.5), which removes an entire run of `k`
   or more. On `"aaaa"` with `k = 3`, this problem leaves `"a"`; the "k or more" rule leaves
   `""`. **Ask.**
2. **Does the order of removals matter?** For this problem, no - the answer is stated to be
   unique. (For the "k or more" variant it **does** matter; see 23.5.)
3. **Can removals cascade?** Yes - that is the point. `"deeedbbcccbdaa"` needs several rounds.
4. **Is `k` at least 2?** Yes on LeetCode. `k = 1` would delete everything.
5. **Character set?** Lowercase English.
6. **Sizes?** Up to 10^5, so the naive repeated-scan approach will time out.

## 3. Intuition

The naive approach: scan for a run of `k`, delete it, start over. Each deletion is `O(n)` to
rebuild the string and you may do `O(n/k)` of them, so `O(n^2)` - and it is fiddly to write.

The stack insight:

> **Build the result left to right on a stack of `(character, run_length)` pairs. A cascade
> is just "after popping, look at the new top".**

When a character arrives:
- if it matches the stack top's character, increment that top's count;
- otherwise push a fresh `(char, 1)`;
- if a count reaches `k`, pop that entry entirely.

The cascade falls out for free. After popping, the element beneath is now adjacent to
whatever comes next, so if the next character matches it, its count simply continues growing.
No rescanning, no restarting.

**Storing counts rather than individual characters** is what makes it linear: a run of 10^5
identical characters is one stack entry, not 10^5.

### Why this is `O(n)`

Each character is pushed once (or merged into an existing entry) and each stack entry is
popped at most once. Total work is linear. Same amortised argument as everywhere in Part 4.

### The difference from the reported Bloomberg question

In 23.5, the rule is *"remove any substring of **three or more** consecutive identical
characters"*. That is **not** this problem:

| input | `k=3` exactly (this problem) | 3-or-more (23.5) |
|---|---|---|
| `"aaaa"` | `"a"` | `""` |
| `"aabbbbc"` | `"aabc"` | `"aac"` |

Under "exactly k", you pop the moment the count hits `k`. Under "k or more", you must wait
until the run is **finished** before deciding, because it may still be growing. That one
difference changes the code and the answer, and it is exactly the kind of ambiguity the
Bloomberg interviewers exploited.

## 4. Approach

1. `stack = []` of `[char, count]`.
2. For each character `ch`:
   - if `stack` and `stack[-1][0] == ch`: `stack[-1][1] += 1`; if it equals `k`, pop.
   - else: `stack.append([ch, 1])`.
3. Rebuild: `"".join(char * count for char, count in stack)`.

## 5. Solution

```python
def remove_duplicates(s, k):
    """Repeatedly remove exactly k adjacent equal characters until none remain.

    The stack holds (character, run length) pairs, so a long run costs one entry.
    Cascades need no rescanning: after a pop, the exposed top is already the new
    neighbour, and the next matching character simply continues its count.
    """
    stack = []                      # [character, run length]

    for ch in s:
        if stack and stack[-1][0] == ch:
            stack[-1][1] += 1
            if stack[-1][1] == k:
                stack.pop()         # exactly k reached: delete the whole group
        else:
            stack.append([ch, 1])

    return "".join(char * count for char, count in stack)
```

```python
remove_duplicates("abcd", 2)                    # 'abcd'
remove_duplicates("deeedbbcccbdaa", 3)          # 'aa'
remove_duplicates("pbbcggttciiippooaais", 2)    # 'ps'
remove_duplicates("aaaa", 3)                    # 'a'
remove_duplicates("aaa", 3)                     # ''
remove_duplicates("", 2)                        # ''
remove_duplicates("a", 2)                       # 'a'
remove_duplicates("abbaca", 2)                  # 'ca'
remove_duplicates("yfttttfbbbbnnnnffbgffffgbbbbgssssgthyyyy", 4)    # 'ybth'
```

`"aaaa"` with `k = 3` giving `"a"` is the case to lead with - it is the one that
distinguishes this rule from the reported Bloomberg variant, and it takes five seconds.

Trace `"deeedbbcccbdaa"` with `k = 3`:

| step | stack |
|---|---|
| `d` | `[(d,1)]` |
| `eee` | `[(d,1),(e,3)]` -> pops -> `[(d,1)]` |
| `d` | `[(d,2)]` |
| `bb` | `[(d,2),(b,2)]` |
| `ccc` | `[(d,2),(b,2),(c,3)]` -> pops -> `[(d,2),(b,2)]` |
| `b` | `[(d,2),(b,3)]` -> pops -> `[(d,2)]` |
| `d` | `[(d,3)]` -> pops -> `[]` |
| `aa` | `[(a,2)]` |

Result `"aa"`. That table is the single best thing to draw here: the three cascading pops at
the end (`b`, then `d`) show why a stack is the right structure.

### The k-or-more variant (the reported Bloomberg rule)

```python
def remove_runs_k_or_more(s, k=3):
    """The reported Bloomberg variant: delete any maximal run of k OR MORE.

    A run must be CLOSED before it is judged, because it may still be growing.
    After deleting one, the exposed neighbours may merge into a new long run.
    """
    stack = []                      # [character, run length]

    def collapse():
        while stack and stack[-1][1] >= k:
            stack.pop()
            # The two runs now on top may share a character and must merge.
            while len(stack) >= 2 and stack[-1][0] == stack[-2][0]:
                char, count = stack.pop()
                stack[-1][1] += count

    for ch in s:
        if stack and stack[-1][0] == ch:
            stack[-1][1] += 1
        else:
            collapse()              # the run on top is now final: judge it
            if stack and stack[-1][0] == ch:
                stack[-1][1] += 1   # collapsing exposed a matching run
            else:
                stack.append([ch, 1])

    collapse()                      # the last run is final too
    return "".join(char * count for char, count in stack)


remove_runs_k_or_more("aaaa", 3)            # ''
remove_runs_k_or_more("aabbbbc", 3)         # 'aac'
remove_runs_k_or_more("aabbbbac", 3)        # 'c'
remove_runs_k_or_more("abcd", 3)            # 'abcd'
```

Compare directly against the exactly-`k` version on the same inputs:

```python
remove_duplicates("aaaa", 3)                # 'a'
remove_duplicates("aabbbbc", 3)             # 'aabc'
remove_duplicates("aabbbbac", 3)            # 'aabac'
```

Every one of those three differs. **If the interviewer gives you examples, work them to
decide which rule you are being asked for** - that is exactly how the Bloomberg candidates
should have disambiguated it.

### The naive version, for the complexity contrast

```python
def remove_duplicates_naive(s, k):
    """O(n^2): find a run of k, cut it, restart. Correct, and the baseline to beat."""
    changed = True
    while changed:
        changed = False
        for i in range(len(s) - k + 1):
            if s[i] == s[i + k - 1] and len(set(s[i:i + k])) == 1:
                s = s[:i] + s[i + k:]
                changed = True
                break
    return s


remove_duplicates_naive("deeedbbcccbdaa", 3)        # 'aa'
remove_duplicates_naive("pbbcggttciiippooaais", 2)  # 'ps'
remove_duplicates_naive("aaaa", 3)                  # 'a'
```

## 6. Complexity

| | Time | Space |
|---|---|---|
| Naive cut-and-restart | `O(n^2)` | `O(n)` |
| **Stack of (char, count)** | **`O(n)`** | `O(n)` |
| Stack of individual characters | `O(n)` | `O(n)`, but a long run costs `n` entries |

Linear by the push-once-pop-once argument. The `(char, count)` encoding matters for the
constant factor: with 10^5 identical characters and `k = 2`, counting keeps the stack at one
entry.

## 7. How to present it

1. **Restate, and immediately pin down the rule**: *"Exactly `k` at a time, or a whole run of
   `k` or more? On `'aaaa'` with `k=3` those give `'a'` and `''` respectively."* Getting this
   confirmed in fifteen seconds is the most valuable thing you can do, and it is precisely
   the ambiguity that appeared in the real Bloomberg question.
2. **Show that removals cascade** using the given example, and note that a naive scan would
   have to restart.
3. **Name the structure**: *"cascading adjacent removals is a stack - and because runs can be
   long, I'll store (character, count) rather than individual characters."*
4. **Explain why the cascade is free**: after popping, the exposed top is the new neighbour,
   so the next matching character just continues its count.
5. **Write it.** Ten lines.
6. **Trace `"deeedbbcccbdaa"`** with the table above - the cascade at the end is the payoff.
7. **Give the amortised argument.**
8. **Close**: `O(n)` time and space - and if you have time, show the k-or-more variant and how
   the answers differ, which demonstrates you understood the rule rather than the recipe.

## 8. Follow-ups and variations

- **"What if the rule is `k` or more?"** The reported Bloomberg variant (23.5). The run must
  be closed before being judged, and neighbours must be merged after a pop. Show the
  differing outputs.
- **"Remove All Adjacent Duplicates in String I"** (LC 1047) - the `k = 2` special case, and
  it needs no counts at all: push, and pop when the top matches.
- **"Does the order of removals matter?"** For exactly-`k`, no. For k-or-more, **yes** - see
  23.5, where `"aaabbbbaa"` can give either `"aa"` or `""` depending on order. Being able to
  say which rule is confluent is a strong answer.
- **"Return the number of characters removed."** `len(s) - len(result)`.
- **"Remove k adjacent equal characters, but only if they match a given letter."** One extra
  condition; the structure is unchanged.
- **"Minimum removals to make the string free of any run of length k."** A different,
  greedy/DP problem.
- **"Do it in place with O(1) extra space."** Possible with two pointers writing back into a
  mutable array plus a parallel count array, but the stack is already `O(distinct runs)`
  which is usually far less than `n`.
- **"What if the string is streamed?"** The stack works incrementally, but an early character
  may still be removed later, so you cannot emit output until the end.

## 9. Pitfalls

- **Answering the wrong rule.** Exactly-`k` versus k-or-more. Ask, and check against the
  examples.
- **Pushing individual characters instead of counts**, which is still `O(n)` but makes the
  `k`-detection awkward and blows up on long runs.
- **Using a tuple `(char, count)`** on the stack - tuples are immutable, so the increment
  fails. Use a list.
- **Rebuilding the string inside the loop** (`s = s[:i] + s[i+k:]`), which is `O(n)` per
  removal and quadratic overall.
- **Forgetting that the count can exceed `k`** if you only check `>=` without popping
  promptly - with the exactly-`k` rule, popping at `== k` means it never exceeds it.
- **In the k-or-more variant, popping as soon as the count reaches `k`**, cutting a run
  short. It must be closed out first.
- **In the k-or-more variant, forgetting to merge neighbours after a pop**, so two runs of
  the same character sit adjacent and never combine.
- **Building the result with `+=` in a loop.** Use a list and `join`.
