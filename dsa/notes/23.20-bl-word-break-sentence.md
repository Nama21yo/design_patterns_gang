title: "23.20 Split a string into dictionary words"
---

> Reported once in R1 on 2025-11-26. The dressing is cute (the answer is literally
> "bloomberg is fun") and the greedy trap is real: `"bloom"` is a valid word and taking it
> leads to a dead end.

## Prompt as given

```
  input1 = "bloombergisfun"
  input2 = ["bloom", "bloomberg", "is", "fun"]

Split input1 with spaces so that all the words exist in input2, and return the sentence.

  answer = "bloomberg is fun"
```

Related: [Word Break](https://leetcode.com/problems/word-break/) (LC 139),
[Word Break II](https://leetcode.com/problems/word-break-ii/) (LC 140).

## Why the example is chosen the way it is

The dictionary contains **both** `"bloom"` and `"bloomberg"`. A greedy scan that takes the
first match it finds picks `"bloom"`, and then `"bergisfun"` cannot be segmented at all -
there is no word starting with `"berg"`. A greedy scan that takes the *longest* match picks
`"bloomberg"` and succeeds here, but longest-match is not correct in general either:
with dictionary `["a", "ab", "bc"]` and input `"abc"`, longest-match takes `"ab"` and then
fails on `"c"`, while `"a" + "bc"` works.

> **So greedy is wrong in both directions, and you must be able to back out of a choice.
> That means DP or memoised recursion.**

Say this with the counterexample. Identifying *why* greedy fails, with a concrete case, is
the scored moment.

## Clarifying questions to ask first

1. **Is a valid segmentation guaranteed to exist?** If not, what do I return - `None`, `""`,
   or raise?
2. **If several segmentations exist, which one?** Any? The one with the fewest words? The
   lexicographically smallest? The example has a unique answer, so this is unstated - ask.
3. **Can a dictionary word be reused?** Yes, normally.
4. **Case sensitivity, punctuation, spaces already present?**
5. **Sizes?** String length `n` and dictionary size `m` decide whether `O(n^2)` substring
   hashing is fine or whether you need a trie.
6. **Can the dictionary contain the empty string?** Guard against it - it causes infinite
   recursion.

## Intuition

Define the subproblem on suffixes:

> **`can_break(i)` = "is `s[i:]` segmentable?"**

Then `can_break(i)` is true if there is some dictionary word `w` matching at position `i`
such that `can_break(i + len(w))` is true. The base case is `can_break(n) = True` - the empty
suffix is trivially segmentable.

That is a recurrence with `n + 1` states, each doing `O(n)` work (trying each end position)
plus a set lookup, so `O(n^2)` with memoisation - and it naturally *backtracks*, which is
what greedy could not do.

To return the sentence rather than a boolean, store the choice: `choice[i] = j` meaning
"take `s[i:j]` as a word". Then walk the chain from 0 and you have the split. Storing the
decision rather than reconstructing it afterwards is the cleaner habit.

## Approach

1. Put the dictionary in a `set` for `O(1)` membership.
2. `dp[i]` over `i = n` down to `0`: `dp[i] = any(s[i:j] in words and dp[j] for j in
   range(i+1, n+1))`, recording `choice[i] = j` on success.
3. If `dp[0]`, walk `choice` from 0 to build the word list; join with spaces.

Small optimisation worth mentioning: cap the inner loop at `i + max_word_length`, since no
word is longer than that. It does not change the worst case but it matters in practice.

## Solution

```python
def word_break(s, word_dict):
    """Split s into dictionary words. Returns the sentence, or None if impossible.

    Greedy fails here - "bloom" is a valid word but leads to a dead end - so this is a
    DP over suffixes that can back out of a choice.
    """
    words = set(word_dict)
    words.discard("")                   # an empty word would loop forever
    if not words:
        return None if s else ""
    longest = max(len(w) for w in words)
    n = len(s)

    # dp[i] is True when s[i:] can be segmented. choice[i] is the end index of the
    # word we take at position i, so the split can be rebuilt without re-searching.
    dp = [False] * (n + 1)
    dp[n] = True                        # the empty suffix is always segmentable
    choice = [None] * (n + 1)

    for i in range(n - 1, -1, -1):
        # No word is longer than `longest`, so the inner scan is bounded.
        for j in range(i + 1, min(n, i + longest) + 1):
            if dp[j] and s[i:j] in words:
                dp[i] = True
                choice[i] = j
                break                   # any valid split will do; stop at the first

    if not dp[0]:
        return None

    parts = []
    i = 0
    while i < n:
        j = choice[i]
        parts.append(s[i:j])
        i = j
    return " ".join(parts)
```

```python
word_break("bloombergisfun", ["bloom", "bloomberg", "is", "fun"])
# 'bloomberg is fun'

word_break("abc", ["a", "ab", "bc"])
# 'a bc'          -- the case where longest-match would have failed

word_break("bloombergisfun", ["bloom", "berg", "is", "fun"])
# 'bloom berg is fun'

word_break("catsandog", ["cats", "dog", "sand", "and", "cat"])
# None            -- LC 139's classic unsolvable case
```

The `break` in the inner loop is safe **because `dp[j]` was already checked**: we only accept
a word when the rest is known to be segmentable, so the first acceptable choice is as good as
any other. If you dropped the `dp[j]` test and broke on the first dictionary match, you would
have written the greedy algorithm and it would fail on the first example. Point at that line.

### Returning all segmentations (LC 140)

```python
from functools import lru_cache


def word_break_all(s, word_dict):
    """Every valid sentence. Exponential in the worst case - the output itself can be."""
    words = set(word_dict)
    words.discard("")
    n = len(s)

    @lru_cache(maxsize=None)
    def segment(i):
        """All segmentations of s[i:], each as a tuple of words."""
        if i == n:
            return [()]
        out = []
        for j in range(i + 1, n + 1):
            if s[i:j] in words:
                out.extend((s[i:j],) + rest for rest in segment(j))
        return out

    return [" ".join(parts) for parts in segment(0)]
```

```python
word_break_all("bloombergisfun", ["bloom", "bloomberg", "berg", "is", "fun"])
# ['bloom berg is fun', 'bloomberg is fun']

word_break_all("catsanddog", ["cat", "cats", "and", "sand", "dog"])
# ['cat sand dog', 'cats and dog']
```

Say the complexity honestly: the number of segmentations can be exponential (consider
`"aaaa..."` with dictionary `["a", "aa"]`), so this is output-bound and memoisation caps the
*work per state*, not the total.

### With a trie, when the dictionary is large

```python
def word_break_trie(s, word_dict):
    """Avoids building O(n^2) substrings and avoids hashing them. Walks a trie
    from each start position instead."""
    root = {}
    for w in word_dict:
        if not w:
            continue
        node = root
        for ch in w:
            node = node.setdefault(ch, {})
        node["$"] = True

    n = len(s)
    dp = [False] * (n + 1)
    dp[n] = True
    choice = [None] * (n + 1)

    for i in range(n - 1, -1, -1):
        node = root
        for j in range(i, n):
            node = node.get(s[j])
            if node is None:
                break                   # no dictionary word continues this way
            if "$" in node and dp[j + 1]:
                dp[i] = True
                choice[i] = j + 1
                break

    if not dp[0]:
        return None
    parts, i = [], 0
    while i < n:
        parts.append(s[i:choice[i]])
        i = choice[i]
    return " ".join(parts)
```

The win: no substring is ever materialised, and the inner loop stops as soon as no word can
continue - which on a real dictionary is very early. Complexity is the same `O(n^2)` bound
but with a far smaller constant and no hashing of `O(n)`-length strings.

## Complexity

Let `n = len(s)`, `m` = dictionary size, `L` = longest word.

| | Time | Space |
|---|---|---|
| Naive recursion, no memo | `O(2^n)` | `O(n)` |
| DP over suffixes (set) | `O(n * L)` substring checks, each `O(L)` to hash -> `O(n * L^2)` | `O(n + total dict chars)` |
| DP with a trie | `O(n * L)` character steps | `O(total dict chars)` |
| All segmentations | exponential (output-bound) | exponential |

The commonly quoted `O(n^2)` assumes `L = O(n)` and treats substring hashing as `O(1)`.
Being precise about the hidden `O(L)` cost of `s[i:j] in words` is a good detail - most
candidates miss it.

## How to present it

1. **Point at the trap in the given example immediately.** "The dictionary has both `bloom`
   and `bloomberg`. If I greedily take `bloom` I'm stuck with `bergisfun`, so I need to be
   able to undo a choice."
2. **Kill longest-match too**, with `["a","ab","bc"]` on `"abc"`. Now you have ruled out both
   greedy variants and DP is forced rather than guessed.
3. **Define the subproblem out loud**: "`can_break(i)` - can the suffix starting at `i` be
   split?" Write the recurrence and the base case `can_break(n) = True`.
4. **Say you will store the choice**, not just the boolean, so the sentence comes out
   directly.
5. **Code it bottom-up**, right to left, and explain why the direction matches the recurrence.
6. **Justify the `break`** - it is only safe because `dp[j]` is already known.
7. **Test on the three cases**: the given one, the `abc` one, and an unsolvable one.
8. **Offer the trie** for a large dictionary and mention the substring-hashing cost.

## Follow-ups and variations

- **"Return ALL valid sentences."** LC 140, `word_break_all` above. Note it is output-bound
  and exponential.
- **"The dictionary is huge - use a trie instead of a set."** Shown. The real argument is not
  just speed: you stop scanning as soon as no word can continue, and you never build
  substrings.
- **"Prefer the segmentation with the fewest words."** Change `dp` from a boolean to a count:
  `dp[i] = 1 + min(dp[j])` over valid `j`, and record the argmin. Same complexity.
- **"Prefer the longest first word"** (or lexicographically smallest sentence). Iterate `j`
  in the appropriate order and take the first success - but **only** among `j` where `dp[j]`
  holds, which is exactly why the DP table must be computed first.
- **"What if no valid segmentation exists?"** Return `None` (or raise). Ask what they want.
- **"What if words can be reused a limited number of times?"** The state grows to include the
  remaining counts - exponential in the dictionary size unless counts are tiny.
- **"Unknown words allowed, minimise their number."** `dp[i] = min over j of (dp[j] +
  (0 if s[i:j] in words else 1))`. This is how real tokenisers handle out-of-vocabulary text.
- **"This is the Welsh dictionary question again."** It is closely related to `23.10` - there,
  tokenisation was greedy-longest-match by fiat; here greedy provably fails. Worth
  connecting: the difference is whether the tokenisation rule is *given* or must be
  *searched for*.

## Pitfalls

- **Greedy first-match or greedy longest-match.** The example is built to break the first;
  `["a","ab","bc"]` breaks the second.
- **Breaking out of the inner loop on a dictionary hit without checking `dp[j]`.** This is the
  greedy bug wearing DP clothing.
- **Forgetting the base case `dp[n] = True`**, which makes everything false.
- **Recursing without memoisation** - exponential and it will time out.
- **An empty string in the dictionary**, causing an infinite loop.
- **Reconstructing the answer by re-running the search** instead of storing `choice`, which
  is more code and more chances to be wrong.
- **Quoting `O(n^2)` while ignoring the `O(L)` cost of hashing each substring.**
- **Building the sentence with `+=` in a loop** on a long input - use a list and `join`.
