**Link:** https://leetcode.com/problems/valid-palindrome
**Difficulty:** Easy | **LeetCode #125**
**Bloomberg frequency:** 62% in the **30-day** window.

The classic opposite-ends scan. The algorithm is four lines; the question is really about
**how carefully you handle the filtering** and whether you avoid allocating a cleaned copy
when asked for `O(1)` space.

## 1. Problem statement

A phrase is a **palindrome** if, after converting all uppercase letters to lowercase and
removing all non-alphanumeric characters, it reads the same forwards and backwards.

Given a string `s`, return `True` if it is a palindrome.

```
s = "A man, a plan, a canal: Panama"  ->  True    ("amanaplanacanalpanama")
s = "race a car"                      ->  False   ("raceacar")
s = " "                               ->  True    ("" - an empty string is a palindrome)
```

## 2. Clarifying questions

1. **What counts as alphanumeric?** Letters and digits. Confirm that **digits count** -
   `"0P"` is a real LeetCode test case and is `False`, because `'0' != 'p'`.
2. **Case insensitive?** Yes.
3. **Is the empty string a palindrome?** Yes - example 3 reduces to `""` and returns `True`.
4. **ASCII or Unicode?** LeetCode says printable ASCII. If Unicode, `str.isalnum()` accepts
   letters from any script and `str.lower()` has locale subtleties - worth one sentence.
5. **Must it be `O(1)` space?** The natural follow-up. Say you can do it either way.
6. **Can I modify the input?** Strings are immutable in Python, so the question is really
   whether you may allocate a cleaned copy.

## 3. Intuition

Two pointers from the ends, moving inward, comparing as they go. The only wrinkle is the
characters you must ignore.

> **Skip non-alphanumerics *inside* the loop rather than pre-cleaning the string, and you
> never allocate anything.**

The pre-clean version is perfectly readable:

```
cleaned = [c.lower() for c in s if c.isalnum()]
return cleaned == cleaned[::-1]
```

but it is `O(n)` space, and the reversal allocates a second copy. The two-pointer version is
`O(1)`. Offer the clean version first if you like, then say you can remove the allocation -
interviewers usually want to see that you can.

The skipping needs `while` loops, not `if`, because there can be **runs** of punctuation:
`"a,,,a"` has three commas between the letters. An `if` advances one position and then
compares a comma against a letter. This is the single bug in the question.

You also need `lo < hi` guarding each inner `while`, or a string of only punctuation walks
the pointers past each other and indexes out of range.

## 4. Approach

1. `lo, hi = 0, len(s) - 1`.
2. While `lo < hi`:
   - while `lo < hi` and `not s[lo].isalnum()`: `lo += 1`
   - while `lo < hi` and `not s[hi].isalnum()`: `hi -= 1`
   - if `s[lo].lower() != s[hi].lower()`: return `False`
   - `lo += 1`, `hi -= 1`
3. Return `True`.

## 5. Solution

```python
def is_palindrome(s):
    """True if s reads the same forwards and backwards, ignoring case and
    non-alphanumeric characters. O(1) space - nothing is allocated.
    """
    lo, hi = 0, len(s) - 1

    while lo < hi:
        # `while`, not `if`: there can be runs of punctuation, as in "a,,,a".
        # The `lo < hi` guard stops the pointers crossing on all-punctuation input.
        while lo < hi and not s[lo].isalnum():
            lo += 1
        while lo < hi and not s[hi].isalnum():
            hi -= 1

        if s[lo].lower() != s[hi].lower():
            return False

        lo += 1
        hi -= 1

    return True
```

```python
is_palindrome("A man, a plan, a canal: Panama")     # True
is_palindrome("race a car")                         # False
is_palindrome(" ")                                  # True
is_palindrome("")                                   # True
is_palindrome("0P")                                 # False
is_palindrome("aa")                                 # True
is_palindrome("ab")                                 # False
is_palindrome("a,,,a")                              # True
is_palindrome(".,")                                 # True
is_palindrome("12321")                              # True
is_palindrome("1a2")                                # False
```

Three to mention aloud:
- `"0P"` -> `False`. Digits are alphanumeric, and `'0'` is not `'p'`. People who lowercase
  only letters, or who use an ASCII arithmetic trick, get this wrong.
- `"a,,,a"` -> `True`, which only works if the skips are `while` loops.
- `".,"` -> `True`, the all-punctuation case that needs the `lo < hi` guard.

### The readable version, for the first pass

```python
def is_palindrome_clean(s):
    """O(n) space. Clearer, and fine unless O(1) space was requested."""
    cleaned = [c.lower() for c in s if c.isalnum()]
    return cleaned == cleaned[::-1]


is_palindrome_clean("A man, a plan, a canal: Panama")   # True
is_palindrome_clean("race a car")                       # False
is_palindrome_clean("0P")                               # False
is_palindrome_clean(" ")                                # True
```

Write this, say "`O(n)` space because of the cleaned copy and the reversal", then offer to
remove both allocations. That sequence is better than jumping straight to the pointer
version, because it shows the progression.

### Two-pointer without the library helpers

If asked to avoid `isalnum()` and `lower()`:

```python
def is_alnum(c):
    return ("a" <= c <= "z") or ("A" <= c <= "Z") or ("0" <= c <= "9")


def to_lower(c):
    return chr(ord(c) + 32) if "A" <= c <= "Z" else c


def is_palindrome_manual(s):
    lo, hi = 0, len(s) - 1
    while lo < hi:
        while lo < hi and not is_alnum(s[lo]):
            lo += 1
        while lo < hi and not is_alnum(s[hi]):
            hi -= 1
        if to_lower(s[lo]) != to_lower(s[hi]):
            return False
        lo += 1
        hi -= 1
    return True


is_palindrome_manual("A man, a plan, a canal: Panama")  # True
is_palindrome_manual("0P")                              # False
is_palindrome_manual("race a car")                      # False
```

Note `to_lower` deliberately leaves digits untouched - the `+ 32` trick applied blindly to
`'0'` gives `'P'`, which is exactly how `"0P"` gets wrongly accepted. Point that out; it is a
real bug that this test case exists to catch.

## 6. Complexity

| | Time | Space |
|---|---|---|
| Clean then reverse | `O(n)` | `O(n)` |
| **Two pointers** | **`O(n)`** | **`O(1)`** |

Each pointer only moves inward, so across the whole run they cover `n` positions between
them - the nested `while` loops do not make it quadratic. That amortised argument is worth
one sentence.

## 7. How to present it

1. **Restate**, and confirm the two filters: lowercase, and keep only alphanumerics.
   **Ask explicitly whether digits count** - it is the one genuine ambiguity, and `"0P"` is
   the test.
2. **Give the clean-then-reverse solution** in two lines and state its `O(n)` space.
3. **Offer the improvement**: "I can avoid both allocations with two pointers from the ends,
   skipping non-alphanumerics as I go - that's `O(1)` space."
4. **Write it**, and as you type the inner loops say: *"these have to be `while` not `if`,
   because there can be several punctuation characters in a row"* and *"and they need the
   `lo < hi` guard or an all-punctuation string runs off the end."* Those two sentences are
   the whole difficulty of the question, and volunteering them is the signal.
5. **Test out loud**: the two given examples, then `""`, `".,"`, `"a,,,a"`, and `"0P"`.
6. **Close**: `O(n)` time, `O(1)` space, and note the pointers together traverse `n`
   positions so the nested loops are still linear.

## 8. Follow-ups and variations

- **"Do it in O(1) space."** The main follow-up - the pointer version above.
- **"Allow deleting at most one character"** (LC 680, *Valid Palindrome II*). On the first
  mismatch, try skipping the left character **or** the right one and check whether either
  remainder is a plain palindrome:
  ```python
  def valid_palindrome_one_deletion(s):
      def is_pal(lo, hi):
          while lo < hi:
              if s[lo] != s[hi]:
                  return False
              lo += 1
              hi -= 1
          return True

      lo, hi = 0, len(s) - 1
      while lo < hi:
          if s[lo] != s[hi]:
              # One deletion allowed: drop either the left or the right character.
              return is_pal(lo + 1, hi) or is_pal(lo, hi - 1)
          lo += 1
          hi -= 1
      return True


  valid_palindrome_one_deletion("aba")        # True
  valid_palindrome_one_deletion("abca")       # True
  valid_palindrome_one_deletion("abc")        # False
  ```
  Still `O(n)`, because the helper runs at most twice and only on the remaining suffix.
- **"Allow deleting at most k characters."** Now it is DP - the longest palindromic
  subsequence - and you check `n - lps <= k`. `O(n^2)`. Name the technique.
- **"Longest palindromic substring."** LC 5 - expand around centres, `O(n^2)`, or Manacher's
  in `O(n)`. Different problem; name it rather than deriving it.
- **"Palindrome number, without converting to a string."** LC 9, reported in a Bloomberg R1.
  Reverse half the digits arithmetically; negatives are never palindromes.
- **"Is a linked list a palindrome?"** LC 234. Find the middle with fast/slow, reverse the
  second half, compare, then restore. `O(n)` time, `O(1)` space.
- **"Unicode input."** `isalnum()` accepts letters from any script and `lower()` can change
  length in some locales (the classic is German `ß`), so full case folding wants
  `str.casefold()`. One sentence is enough.
- **"Count palindromic substrings."** LC 647 - expand around centres.

## 9. Pitfalls

- **Using `if` instead of `while`** for the skips. `"a,,,a"` breaks.
- **Omitting the `lo < hi` guard** in the inner loops, so `".,"` indexes out of range.
- **Forgetting that digits are alphanumeric**, or lowercasing with `ord(c) + 32` applied to
  digits - `"0P"` is the test case that exists for this.
- **Pre-cleaning when `O(1)` space was requested.**
- **`s == s[::-1]` on the raw string**, ignoring the filtering entirely.
- **Comparing `s[lo]` and `s[hi]` before skipping**, so punctuation is compared.
- **Not lowercasing both sides.**
- **Claiming the nested `while` loops make it `O(n^2)`** - they do not; give the argument.
