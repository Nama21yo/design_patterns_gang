**Link:** https://leetcode.com/problems/asteroid-collision
**Difficulty:** Medium | **LeetCode #735**
**Bloomberg frequency:** 38% at three months.

A **simulation** problem where the stack is the natural state, not an optimisation. The
algorithm is short; the difficulty is entirely in the **case analysis**, and getting the
three outcomes and the control flow right is what the question tests.

## 1. Problem statement

You are given an array `asteroids` of integers representing asteroids in a row. For each:
- the **absolute value** is its size,
- the **sign** is its direction: **positive means moving right, negative means moving left**.

Each asteroid moves at the same speed. If two meet, the **smaller one explodes**; if they are
the **same size, both explode**. Two asteroids moving in the same direction never meet.

Return the state after all collisions.

```
asteroids = [5,10,-5]   ->  [5,10]     10 and -5 collide, -5 explodes
asteroids = [8,-8]      ->  []         equal sizes, both explode
asteroids = [10,2,-5]   ->  [10]       -5 destroys 2, then 10 destroys -5
```

## 2. Clarifying questions

1. **Which sign means which direction?** Positive is **right**, negative is **left**.
   Confirm - getting it backwards inverts the whole solution.
2. **When do two asteroids collide?** Only when a **right-moving** one is to the left of a
   **left-moving** one - that is, `+` followed by `-`. Every other adjacent pairing
   (`+ +`, `- -`, `- +`) never meets. **This is the crux**; state it explicitly.
3. **Equal sizes?** Both explode.
4. **Can an asteroid be 0?** No - LeetCode guarantees non-zero.
5. **Can one asteroid destroy several?** Yes - `[10,2,-5]` has `-5` destroy `2` and then be
   destroyed by `10`. That cascading is why a `while` loop is needed.
6. **Sizes?** Up to 10^4; `O(n)` expected.

## 3. Intuition

The observation that decides everything:

> **A collision happens only between a positive asteroid on the left and a negative one on
> the right - `+` then `-`. `- +` moves apart, and same-signed pairs never meet.**

So process left to right with a stack of surviving asteroids:

- A **negative** incoming asteroid threatens the positives on the stack, and may destroy
  several in a row.
- A **positive** incoming asteroid can never collide with anything already on the stack
  (anything there is either positive and moving away, or negative and moving away
  leftwards). So it is always pushed.

That asymmetry is the whole algorithm. Only the `incoming < 0` case does any work.

### The three outcomes

When `incoming` is negative and `stack[-1]` is positive, compare sizes:

| condition | what happens | control flow |
|---|---|---|
| `stack[-1] < -incoming` | the stack asteroid explodes | pop, and **keep comparing** |
| `stack[-1] == -incoming` | **both** explode | pop, and **stop** (incoming is gone) |
| `stack[-1] > -incoming` | the incoming explodes | **stop**, do not push |

The control flow is the part people get wrong. The first case continues the loop; the other
two end it *and* prevent the push. A `while` with a `break`, plus an `else` clause on the
`while`, expresses it exactly - or an explicit `alive` flag, which is clearer under pressure.

Using `-incoming` (the size) rather than `incoming` throughout avoids sign confusion; or
compare `abs()` values. Pick one and be consistent.

## 4. Approach

1. `stack = []`.
2. For each `a`:
   - `alive = True`
   - while `alive` and `a < 0` and `stack` and `stack[-1] > 0`:
     - if `stack[-1] < -a`: `stack.pop()` (continue)
     - elif `stack[-1] == -a`: `stack.pop()`; `alive = False`
     - else: `alive = False`
   - if `alive`: `stack.append(a)`
3. Return `stack`.

## 5. Solution

```python
def asteroid_collision(asteroids):
    """State after all collisions. Positive moves right, negative moves left.

    A collision happens only when a right-moving asteroid sits to the LEFT of a
    left-moving one, i.e. stack top is positive and the incoming is negative.
    A positive incoming asteroid never collides with anything already surviving,
    so it is always pushed.
    """
    stack = []

    for a in asteroids:
        alive = True

        # Only a left-moving asteroid can collide, and only with right-moving
        # survivors. It may destroy several in a row, hence the while.
        while alive and a < 0 and stack and stack[-1] > 0:
            if stack[-1] < -a:
                stack.pop()             # the survivor loses; keep going
            elif stack[-1] == -a:
                stack.pop()             # equal sizes: both explode
                alive = False
            else:
                alive = False           # the incoming loses

        if alive:
            stack.append(a)

    return stack
```

```python
asteroid_collision([5, 10, -5])         # [5, 10]
asteroid_collision([8, -8])             # []
asteroid_collision([10, 2, -5])         # [10]
asteroid_collision([-2, -1, 1, 2])      # [-2, -1, 1, 2]
asteroid_collision([1, -2, -2, -2])     # [-2, -2, -2]
asteroid_collision([])                  # []
asteroid_collision([1])                 # [1]
asteroid_collision([-1])                # [-1]
asteroid_collision([1, -1])             # []
asteroid_collision([-1, 1])             # [-1, 1]
asteroid_collision([5, 10, -5, -10, -20])   # [-20]
asteroid_collision([2, -2, 1, -2])      # [-2]
```

The four to say out loud:

- **`[-2,-1,1,2]` -> unchanged.** Everything is moving apart; no collision is possible. It
  is the cleanest proof that you got the direction rule right.
- **`[-1,1]` -> unchanged** but **`[1,-1]` -> `[]`.** The same two asteroids, opposite order,
  opposite outcome. This pair is the single best test of the `+` then `-` rule, and it takes
  three seconds.
- **`[5,10,-5,-10,-20]` -> `[-20]`.** A cascade: `-10` destroys `10`... and then `-20`
  destroys `5`. Exercises the `while` properly.
- **`[1,-2,-2,-2]` -> `[-2,-2,-2]`.** After `-2` destroys `1`, the stack holds only negatives,
  so the later `-2`s sail through untouched - the `stack[-1] > 0` guard doing its job.

### The explicit for-else version

Python's `for ... else` expresses "the loop finished without breaking" and removes the flag:

```python
def asteroid_collision_for_else(asteroids):
    """Same logic using while/else instead of an `alive` flag. Idiomatic, but only
    write it if the construct is second nature - the flag version is clearer aloud."""
    stack = []
    for a in asteroids:
        while stack and a < 0 < stack[-1]:
            if stack[-1] < -a:
                stack.pop()
                continue
            elif stack[-1] == -a:
                stack.pop()
            break
        else:
            stack.append(a)
    return stack


asteroid_collision_for_else([5, 10, -5])        # [5, 10]
asteroid_collision_for_else([8, -8])            # []
asteroid_collision_for_else([10, 2, -5])        # [10]
asteroid_collision_for_else([1, -1])            # []
asteroid_collision_for_else([-1, 1])            # [-1, 1]
asteroid_collision_for_else([5, 10, -5, -10, -20])  # [-20]
```

Note `a < 0 < stack[-1]` is Python's chained comparison - readable, and it states the
collision condition in one expression. The `while ... else` runs the `append` only when no
`break` occurred, i.e. when the incoming asteroid survived.

Both versions are correct; **write the flag version in an interview** unless you are certain
about `for/while ... else`, because a construct you have to explain twice costs more than it
saves.

## 6. Complexity

| | Time | Space |
|---|---|---|
| Repeated scan-and-collide simulation | `O(n^2)` | `O(n)` |
| **Stack** | **`O(n)`** | `O(n)` |

Each asteroid is pushed at most once and popped at most once, so the total work is linear
even though a single incoming asteroid can pop many. The usual amortised argument.

Space is `O(n)` for the stack, which is also the output - so `O(1)` auxiliary if you count
the result as required output.

## 7. How to present it

1. **Restate**, and **confirm the sign convention** immediately.
2. **State the collision rule** before anything else: *"Two asteroids only meet when a
   right-moving one is to the left of a left-moving one. So the only interesting case is a
   negative arriving on top of a positive."* Everything follows from that sentence, and
   arriving at it is most of the question.
3. **Note the asymmetry**: a positive asteroid is always safe to push; only a negative one
   does any work.
4. **Enumerate the three outcomes** - bigger, equal, smaller - and say what each does to the
   control flow. Writing the three-row table before coding makes the code obviously
   complete.
5. **Announce**, then write it with the `alive` flag.
6. **Trace `[5,10,-5,-10,-20]`**: the cascade is the payoff and it exercises every branch.
7. **Test the direction pair** `[1,-1]` versus `[-1,1]`.
8. **Give the amortised argument.**
9. **Close**: `O(n)` time, `O(n)` space (which is the output).

## 8. Follow-ups and variations

- **"What if equal-size asteroids both survive instead?"** Drop the middle case: on equality,
  neither pops and the incoming is not pushed... or both are kept. **Ask what is intended** -
  the rule change is small but the answer differs.
- **"What if asteroids had different speeds?"** The stack model breaks completely: a faster
  asteroid can catch a slower one moving the *same* direction, so same-signed pairs collide
  too. It becomes an event-driven simulation, sorted by collision time - a priority queue.
  Naming that shift is a strong answer.
- **"Return the number of collisions."** Count the pops (with the equal case counting one
  collision that destroys two).
- **"What if collisions produce debris"** (e.g. a new asteroid of the size difference)? Then
  the result of a collision re-enters the process, so push the debris back as the new
  `incoming` and continue.
- **"Simplify the path / Backspace string compare."** Other pure-simulation stack problems -
  same shape, easier case analysis. Worth naming as the family.
- **"Car Fleet"** (LC 853). Another stack simulation with directions and catching-up; a good
  harder cousin.
- **"What if the input is streamed?"** The stack processes incrementally, and a prefix's
  answer can still change when a later negative arrives - so you can only emit the final
  state.

## 9. Pitfalls

- **Getting the direction convention backwards.** Test `[1,-1]` versus `[-1,1]`.
- **Using `if` instead of `while`**, so one asteroid cannot destroy several. `[10,2,-5]` and
  `[5,10,-5,-10,-20]` are the tests.
- **Pushing the incoming asteroid after it has exploded.** The `alive` flag exists for this.
- **Forgetting the equal-size case**, where **both** die - so you pop *and* do not push.
- **Comparing `stack[-1] < a` instead of `stack[-1] < -a`**, mixing a size with a signed
  value. Use `abs()` or negate consistently.
- **Checking only `stack`** without `stack[-1] > 0`, so a negative incoming tries to collide
  with negatives already on the stack. `[1,-2,-2,-2]` catches it.
- **Colliding same-signed asteroids**, which never meet at equal speed.
- **Using `for ... else` without being sure of the semantics**, producing a silent logic bug.
