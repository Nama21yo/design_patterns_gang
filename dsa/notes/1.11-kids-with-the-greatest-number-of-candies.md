**Link:** https://leetcode.com/problems/kids-with-the-greatest-number-of-candies
**Difficulty:** Easy | **LeetCode #1431**
**Bloomberg frequency:** 38% at three months.

The easiest question in Part 1. It is here as a warm-up and as a small lesson in **not
recomputing an aggregate inside a loop** - which is the same idea as prefix sums, in its
simplest possible form.

## 1. Problem statement

There are `n` kids with candies. You are given `candies`, where `candies[i]` is how many the
`i`-th kid has, and an integer `extraCandies`.

Return a boolean array `result` where `result[i]` is `True` if, **after giving the `i`-th
kid all the extra candies**, they would have the greatest number among all kids.

Multiple kids can have the greatest number.

```
candies = [2,3,5,1,3], extraCandies = 3  ->  [True, True, True, False, True]
candies = [4,2,1,1,2], extraCandies = 1  ->  [True, False, False, False, False]
candies = [12,1,12],   extraCandies = 10 ->  [True, False, True]
```

## 2. Clarifying questions

1. **Are the extra candies given to *each* kid hypothetically, or distributed once?**
   Hypothetically, to each kid independently. Every entry of the answer is a separate
   what-if. This is the only genuine ambiguity, and it is worth one sentence.
2. **Is "greatest" a tie or strictly greatest?** A tie counts - "note that multiple kids can
   have the greatest number", so the comparison is `>=`.
3. **Is the maximum computed before or after adding the extras?** Before - against the
   *current* maximum of the other kids. See the analysis below, since this is subtler than
   it looks.
4. **Can `extraCandies` be zero?** Yes; then only the current maximum holders are `True`.
5. **Can values be zero or negative?** Candies are non-negative on LeetCode.

## 3. Intuition

The naive reading is: for each kid, add the extras, then scan every other kid to see if
anyone beats them. That is `O(n^2)`.

The observation:

> **The relevant comparison is always against the global maximum, and the global maximum
> does not change as you consider different kids.**

Why can you compare against the *global* max rather than the max of the *other* kids? Because
if kid `i` is themselves the maximum, then `candies[i] + extraCandies >= candies[i] == max`
holds automatically (extras are non-negative). So using the global maximum is safe and
avoids any special case.

So: compute `max(candies)` **once**, then one pass producing
`candies[i] + extraCandies >= maximum`.

That "hoist the invariant out of the loop" move is the entire content of the question, and
it is exactly what prefix sums do in a more elaborate way.

## 4. Approach

1. `maximum = max(candies)` - one pass.
2. Return `[c + extraCandies >= maximum for c in candies]` - a second pass.

Two passes, `O(n)`.

## 5. Solution

```python
def kids_with_candies(candies, extra_candies):
    """For each kid, would giving them all the extra candies make them (joint) greatest?

    The global maximum is computed once and hoisted out of the loop. Comparing against
    the global max rather than the max of the OTHER kids is safe, because a kid who is
    already the max trivially still reaches it after receiving non-negative extras.
    """
    maximum = max(candies, default=0)
    # '>=' not '>', because ties count as having the greatest number.
    return [c + extra_candies >= maximum for c in candies]
```

```python
kids_with_candies([2, 3, 5, 1, 3], 3)       # [True, True, True, False, True]
kids_with_candies([4, 2, 1, 1, 2], 1)       # [True, False, False, False, False]
kids_with_candies([12, 1, 12], 10)          # [True, False, True]
kids_with_candies([1, 1, 1], 0)             # [True, True, True]
kids_with_candies([5], 0)                   # [True]
kids_with_candies([1, 2], 0)                # [False, True]
kids_with_candies([], 5)                    # []
```

`[1,1,1]` with zero extras giving all `True` is the case that confirms the `>=`: everyone
ties for the greatest.

### The `O(n^2)` version, to state and reject

```python
def kids_with_candies_brute(candies, extra_candies):
    """O(n^2): for each kid, rescan everyone else. Mention it, then improve it."""
    result = []
    for i, c in enumerate(candies):
        after = c + extra_candies
        result.append(all(after >= other for j, other in enumerate(candies) if j != i))
    return result


kids_with_candies_brute([2, 3, 5, 1, 3], 3)     # [True, True, True, False, True]
kids_with_candies_brute([1, 1, 1], 0)           # [True, True, True]
```

Note this one compares against the *other* kids explicitly, which is the literal reading of
the problem. That it agrees with the global-max version on every input is the little proof
obligation worth mentioning out loud.

## 6. Complexity

| | Time | Space |
|---|---|---|
| Brute force | `O(n^2)` | `O(n)` output |
| Max then compare | **`O(n)`** | `O(n)` output, `O(1)` extra |

Two linear passes. `max()` cannot be avoided, and the output is necessarily `O(n)`, so this
is optimal. Say "`O(1)` auxiliary space, not counting the output array" - the same
distinction as in 1.5.

## 7. How to present it

This is a two-minute question. The risk is spending ten minutes on it or, conversely, going
silent because it is beneath comment. Do neither.

1. **Restate, and clear up the one ambiguity**: "Each kid is considered independently - I
   give *all* the extras to kid `i` and ask whether they'd then be at least as high as
   everyone else. It's a separate hypothetical per kid, not a distribution."
2. **Confirm ties count**, so the comparison is `>=`.
3. **Name the brute force and its cost** in one sentence.
4. **State the hoist**: "The comparison target is the global maximum, and that doesn't change
   between kids - so I compute it once."
5. **Justify using the global max rather than the max of the others** - one sentence, because
   it is the only place a careful interviewer will probe.
6. **Write the two lines.**
7. **Close**: `O(n)` time, `O(1)` extra space beyond the output, and mention `[1,1,1]` with
   zero extras as the tie case.

## 8. Follow-ups and variations

- **"What if the extras must actually be distributed among the kids?"** A completely
  different, much harder problem - now it is an allocation question and you would ask what is
  being optimised. Worth flagging that the hypothetical reading is what makes it easy.
- **"What if `extraCandies` could be negative?"** The global-max shortcut breaks, because a
  kid who *was* the maximum might no longer reach it and would now need comparing against
  the others. You would need the maximum of the other kids, which is the max-excluding-self
  problem - solvable with the **largest two values**: if kid `i` holds the unique maximum,
  compare against the second largest, otherwise against the largest. Good follow-up, and it
  connects straight back to 1.5.
- **"Return the indices of the kids rather than booleans."** A list comprehension with
  `enumerate`.
- **"Which kid needs the fewest extra candies to become greatest?"** `max(candies) -
  candies[i]`, minimised over `i` - which is 0 for whoever is already the max.
- **"Streaming: candies arrive one at a time."** You cannot answer until the maximum is
  known, so buffer, or answer with a delay. Same structural point as 1.3.
- **"2D: greatest in their row?"** Row maxima, then the same comparison.

## 9. Pitfalls

- **Recomputing `max(candies)` inside the loop**, which is the `O(n^2)` version in disguise
  and is easy to write by accident.
- **Using `>` instead of `>=`**, so tied kids are reported as `False`. `[1,1,1]` with 0
  extras is the test.
- **Comparing against the max *after* hypothetically adding the extras to everyone**, which
  makes almost nobody qualify.
- **Interpreting the extras as being shared out** rather than offered to each kid in turn.
- **Mutating `candies` in place** while computing the answers, so later comparisons use
  corrupted values.
- **`max()` on an empty list** raises `ValueError`; use `default=0` if empty input is
  possible.
- **Spending too long here.** Solve it, narrate briefly, and invite the follow-up.
