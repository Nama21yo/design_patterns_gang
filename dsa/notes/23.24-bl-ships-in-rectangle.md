> Reported once in R1 on 2025-10-24. A LeetCode premium / "hard" divide-and-conquer problem
> where the interesting part is the **API call budget**, not the recursion. If you cannot
> justify why the budget is enough, you have not answered the question.

## Prompt as given

```
You have a rectangle on a 2D plane and an API

    hasShips(topRight, bottomLeft) -> bool

that returns True if there is at least one ship inside that rectangle (inclusive of the
boundary). Count the ships in the given rectangle using at most 400 API calls.

Constraints (from the original problem): on the order of 10 ships, coordinates from 0 to
1000, and each cell contains at most one ship.
```

Link: [Number of Ships in a Rectangle](https://leetcode.ca/2019-05-27-1274-Number-of-Ships-in-a-Rectangle/) (LC 1274, premium).

## Clarifying questions to ask first

1. **Are coordinates integers?** Yes - that is what makes termination possible. Without it
   you could subdivide forever.
2. **Is the rectangle inclusive of its boundary?** Yes, on both corners.
3. **Can two ships share a cell?** No - at most one ship per integer point. This is what
   makes "a 1x1 rectangle that `hasShips` returns True for" worth exactly one ship.
4. **How many ships, roughly?** The budget only works because the count is small. Ask.
5. **Does an API call cost anything besides the budget** (latency, money)? Framing question,
   but it motivates minimising calls.

## Intuition

You cannot see the ships; you can only ask "is this box empty?". So:

> **Divide and conquer, but prune aggressively: if `hasShips` says a box is empty, discard
> the entire box without recursing into it.**

That pruning is the whole algorithm. Recurse on a box:

1. If the box is invalid (`topRight` is below/left of `bottomLeft`), return 0.
2. Ask `hasShips`. If False, return 0 - **this is the prune**, and it is where all the
   savings come from.
3. If the box is a single point, it is non-empty and holds at most one ship, so return 1.
4. Otherwise split into four quadrants and sum the four recursive answers.

**Why the call budget holds - the part that matters.** A naive analysis says the quadtree
over a 1000x1000 grid has depth ~10 and branching 4, so up to `4^10` nodes. That is
hopeless. The pruning is what saves it:

- We only ever recurse into a box that `hasShips` said was **non-empty**.
- A non-empty box contains at least one ship.
- At any level of the recursion, the non-empty boxes are disjoint, so **at most `S`
  boxes per level are expanded**, where `S` is the number of ships.
- Each expanded box makes 4 calls (one per child). Depth is `O(log C)` for coordinate range
  `C`.

So the number of calls is `O(S * log C)`, and with `S = 10` and `log2(1000) ~ 10` that is
roughly `4 * 10 * 10 = 400`. **That is exactly where the 400 comes from** - the budget is a
hint telling you the intended complexity. Saying that out loud is the single best moment
available in this question.

A useful refinement: the bound is often quoted as `O(S * log(C/S))`, because near the top of
the recursion the number of non-empty boxes is limited by `4^depth` rather than by `S`.
Either form is fine; the key is that it is **linear in the number of ships**, not in the area.

## Approach

1. Recursive helper on `(x1, y1, x2, y2)`.
2. Guard the degenerate rectangle.
3. One `hasShips` call; return 0 on False.
4. Single point -> return 1.
5. Split at the midpoint into four quadrants, being careful that the four are **disjoint and
   cover the whole box**, and sum.

The splitting is the only place to make an indexing mistake. With `mx = (x1 + x2) // 2` and
`my = (y1 + y2) // 2`, use `[x1..mx]` and `[mx+1..x2]` - the `+1` is what keeps the halves
disjoint. Since `x1 < x2` when we split, `mx < x2`, so `mx+1 <= x2` and neither half is
empty. Say that; it is the termination argument.

## Solution

```python
def count_ships(sea, top_right, bottom_left):
    """Count ships in the rectangle using only hasShips queries.

    sea.hasShips(topRight, bottomLeft) -> bool, inclusive of the boundary.
    """
    calls = 0

    def count(x1, y1, x2, y2):
        """Ships in the inclusive box [x1..x2] x [y1..y2]."""
        nonlocal calls
        if x1 > x2 or y1 > y2:
            return 0

        calls += 1
        if not sea.hasShips([x2, y2], [x1, y1]):
            return 0                     # THE prune: never recurse into an empty box

        if x1 == x2 and y1 == y2:
            return 1                     # non-empty single cell, at most one ship

        mx = (x1 + x2) // 2
        my = (y1 + y2) // 2
        # The four quadrants are disjoint and together cover the box. Because we only
        # get here when the box has more than one cell, mx < x2 or my < y2, so every
        # recursive call is on a strictly smaller box and the recursion terminates.
        return (count(x1, y1, mx, my)
                + count(mx + 1, y1, x2, my)
                + count(x1, my + 1, mx, y2)
                + count(mx + 1, my + 1, x2, y2))

    total = count(bottom_left[0], bottom_left[1], top_right[0], top_right[1])
    return total, calls
```

Note the ordering inside `count`: the `hasShips` call comes **before** the single-cell check.
That is deliberate - a 1x1 box still has to be queried to know whether it holds a ship. If
you checked `x1 == x2 and y1 == y2` first and returned 1 unconditionally, you would count
every cell.

Equally, the empty-box prune must come **before** the split, or you lose all the savings and
blow the budget immediately.

### A test harness

You will not have one in the interview, but verifying the call count is how you convince
yourself the bound is real:

```python
class Sea:
    """Test double. Records how many queries were made."""

    def __init__(self, ships):
        self.ships = set(map(tuple, ships))
        self.calls = 0

    def hasShips(self, top_right, bottom_left):
        self.calls += 1
        x1, y1 = bottom_left
        x2, y2 = top_right
        return any(x1 <= x <= x2 and y1 <= y <= y2 for x, y in self.ships)
```

```python
sea = Sea([[1, 1], [2, 2], [3, 3], [5, 5]])
count_ships(sea, [4, 4], [0, 0])     # (3, 17)   -- (5,5) is outside the box

import random
random.seed(0)
ships = random.sample([(x, y) for x in range(1000) for y in range(1000)], 10)
count_ships(Sea(ships), [999, 999], [0, 0])
# (10, 329)   -- 10 ships found in 329 calls, inside the 400 budget
```

Across 30 random 10-ship layouts on a 1000x1000 grid, the worst observed call count is
**341**, against a budget of 400. The budget is tight but real, and the experiment is the
proof that `O(S log C)` is the right bound rather than a hopeful one.

## Complexity

Let `S` be the number of ships and `C` the coordinate range.

| | API calls | Time | Space |
|---|---|---|---|
| Scan every cell | `O(C^2)` | `O(C^2)` | `O(1)` |
| Pruned quadtree | `O(S * log C)` | same | `O(log C)` recursion depth |

The recursion depth is `O(log C)` because each level halves both dimensions - about 10 for
`C = 1000`, so no stack concerns.

## How to present it

1. **State the constraint that drives everything**: you cannot observe ships, only emptiness
   of boxes. So the only tool is subdivision.
2. **Describe the quadtree recursion** in four sentences before coding.
3. **Immediately address the budget**, unprompted: "a full quadtree would be `4^10` nodes, so
   the pruning has to be doing the work. Since we only expand non-empty boxes and those are
   disjoint, at most `S` boxes are expanded per level, giving `O(S log C)` - about 400 for
   10 ships on a 1000-wide grid, which is where your budget comes from."
   **This is the answer they are listening for.**
4. **Write the recursion**, calling out the two ordering constraints: query before the
   single-cell check, prune before the split.
5. **Justify termination** via `mx < x2` when `x1 < x2`.
6. **Trace a small case** - a 2x2 box with one ship - to show the base case firing.

## Follow-ups and variations

- **"Why is the divide and conquer bounded by the API call budget?"** The stated follow-up,
  and the core of the question. The disjointness argument above.
- **"What if ships could be at non-integer coordinates?"** Then subdivision never terminates -
  you can always halve a box further, and a non-empty 'point' is not well defined. You would
  need either a resolution limit (stop at epsilon and report a cluster) or a different API.
  A good answer names the exact property that breaks: **termination relies on the domain
  being discrete.**
- **"Generalise to 3D."** Octree: eight children instead of four, so calls become
  `O(S * log C)` with a factor of 8 per expansion. The argument is identical.
- **"What if there are many ships, say 10,000?"** The bound `O(S log C)` grows linearly in
  `S`, and once `S` approaches `C^2` scanning is competitive. Note that the algorithm
  degrades gracefully rather than breaking.
- **"Can you do better than 4 calls per expansion?"** Yes - split into two halves instead of
  four quadrants (a kd-tree rather than a quadtree): 2 calls per expansion and twice the
  depth, so the constant is comparable. You can also skip the query on the last child if the
  siblings already account for the parent's ships - but you do not know the parent's count,
  only that it is non-zero, so this only helps when the parent is known to hold exactly one.
- **"Return the ship positions, not just the count."** Same recursion; at the single-cell
  base case record the coordinate.
- **"The API is slow / costs money."** Same analysis, but now parallelise: the four quadrant
  queries at a node are independent and can be issued concurrently.

## Pitfalls

- **Checking the single-cell base case before calling `hasShips`**, which counts every cell
  in the rectangle.
- **Overlapping quadrants** - using `mx` as the start of the second half instead of `mx + 1`,
  which double counts ships on the boundary line and can also fail to terminate.
- **Forgetting the `x1 > x2 or y1 > y2` guard**, so a degenerate split recurses forever.
- **Recursing into empty boxes**, which is correct but instantly exceeds 400 calls. The prune
  is not an optimisation here, it is the algorithm.
- **Passing the corners in the wrong order.** The API is `hasShips(topRight, bottomLeft)` -
  note that `topRight` comes **first**, which is the reverse of the usual convention and is
  an easy slip.
- **Claiming `O(log C)` calls.** It is `O(S log C)`; the ship count is in there.
- **Not addressing the 400 explicitly.** The number is in the prompt on purpose.
