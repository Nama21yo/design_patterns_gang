> Reported 5 times across R1 and R2 on 2025-10-08, 2025-11-04 and 2025-11-05, in two
> different tellings. The follow-up (gas stations) is where the question actually lives -
> it changes the state space, and that is the thing being tested.

## Prompt as given

```
You are given a grid and two points (a starting point and an ending point) and you have a
fuel amount. Check whether it is possible to reach the ending point without running out of
fuel. You may only travel horizontally and vertically.

A later retelling of the same question:

You are on a desert given by an m x n matrix containing the characters '.', 'c' and 'o'.
'c' is your car's position and 'o' is the oasis you want to reach with the fuel you are
given. Can you make it to the oasis?

    [ ['.','.','c'],
      ['.','r','r'],
      ['.','.','o'] ]
```

`'r'` is an obstacle (added mid-interview in one report).

Related: [Shortest Path in Binary Matrix](https://leetcode.com/problems/shortest-path-in-binary-matrix/),
[Shortest Path in a Grid with Obstacles Elimination](https://leetcode.com/problems/shortest-path-in-a-grid-with-obstacles-elimination/)

## Clarifying questions to ask first

1. **Does each move cost exactly one fuel?** Almost certainly yes, but confirm - if moves
   have varying cost this becomes Dijkstra, not BFS.
2. **Four directions or eight?** The prompt says horizontal and vertical, so four.
3. **Are there obstacles?** In the first telling, no. In the second, `'r'`. Ask up front -
   it is a one-line change but you want it in your mental model.
4. **Is "without running out of fuel" `fuel >= 0` on arrival, or `fuel > 0`?** Arriving with
   exactly zero is normally fine. Confirm.
5. **Can I revisit a cell?** Yes, physically - but see the intuition below for why that only
   matters once stations exist.
6. **Do I need the answer, or the path?** Boolean first; be ready to reconstruct.
7. **Grid size?** Decides whether `O(m*n*fuel)` is acceptable.

## Intuition

**Without gas stations, this is not really a search problem at all.**

Every move costs one fuel, so the cheapest way to arrive is the shortest path, and revisiting
a cell is never useful - it only burns fuel. So:

> reachable  <=>  shortest_path_length(start, end) <= fuel

and the shortest path in an unweighted grid is plain BFS. The answer is a single comparison.

Say this explicitly, because it reframes the problem: **fuel is not part of the state**, it
is just a budget compared against one number at the end.

**With gas stations, that collapses.** Now revisiting a cell *can* be useful - you might
detour to a station, refill, and come back. The quantity "shortest distance to this cell" is
no longer sufficient to decide the future, because arriving at the same cell with more fuel
is strictly better. So fuel joins the state:

> state = (row, col, fuel_remaining)

and you BFS over that larger space. This is the same structural move as "Shortest Path in a
Grid with Obstacles Elimination", where the extra dimension is remaining eliminations rather
than remaining fuel. Naming that parallel out loud is a strong signal.

One important pruning rule: if you have already visited `(r, c)` with fuel `f1 >= f2`, then
reaching it again with `f2` is useless - anything you could do with `f2` you could do with
`f1`. So track the **best fuel seen per cell** and skip dominated states. That keeps the
search small in practice.

## Approach

### Part 1: no stations

1. Locate `'c'` and `'o'`.
2. BFS from the start over passable cells, tracking distance.
3. Return `distance[end] <= fuel`.

### Part 2: with stations

1. State is `(r, c, fuel)`. Start at `(sr, sc, initial_fuel)`.
2. BFS (or DFS - there is no shortest-path requirement any more, only reachability).
3. On entering a cell: if it is a station, set `fuel = tank_capacity` (or `fuel += refill`,
   depending on the rules - **ask**).
4. Prune with `best[r][c]`: the maximum fuel with which we have already stood on that cell.
   Skip any state whose fuel is not strictly greater.
5. Success when the cell is the oasis.

## Solution

### Part 1: no stations

```python
from collections import deque

DIRECTIONS = ((1, 0), (-1, 0), (0, 1), (0, -1))


def can_reach(grid, fuel):
    """Four-directional movement, one fuel per move, '#' blocks, 'c' start, 'o' oasis."""
    rows, cols = len(grid), len(grid[0])

    start = end = None
    for r in range(rows):
        for c in range(cols):
            if grid[r][c] == "c":
                start = (r, c)
            elif grid[r][c] == "o":
                end = (r, c)
    if start is None or end is None:
        return False
    if start == end:
        return True

    queue = deque([(start[0], start[1], 0)])     # row, col, distance travelled
    seen = {start}

    while queue:
        r, c, dist = queue.popleft()
        if dist == fuel:
            continue                              # tank empty, cannot step further
        for dr, dc in DIRECTIONS:
            nr, nc = r + dr, c + dc
            if not (0 <= nr < rows and 0 <= nc < cols):
                continue
            if grid[nr][nc] == "r":               # obstacle
                continue
            if (nr, nc) in seen:
                continue
            if (nr, nc) == end:
                return True                       # dist + 1 <= fuel, checked above
            seen.add((nr, nc))
            queue.append((nr, nc, dist + 1))

    return False
```

BFS pops cells in non-decreasing distance order, so the first time we touch the oasis we
have touched it by a shortest path - which is why a plain `seen` set is safe here.

### Part 2: with gas stations

```python
from collections import deque

DIRECTIONS = ((1, 0), (-1, 0), (0, 1), (0, -1))


def can_reach_with_stations(grid, capacity):
    """'c' start, 'o' oasis, 'g' gas station (refills to full), 'r' obstacle.

    State is (row, col, fuel), because after refuelling it can be worth revisiting a cell.
    """
    rows, cols = len(grid), len(grid[0])
    start = end = None
    for r in range(rows):
        for c in range(cols):
            if grid[r][c] == "c":
                start = (r, c)
            elif grid[r][c] == "o":
                end = (r, c)

    # best[r][c] = the most fuel we have ever had while standing on (r, c).
    # Arriving with less than that is dominated, so we can prune it.
    best = [[-1] * cols for _ in range(rows)]

    sr, sc = start
    start_fuel = capacity if grid[sr][sc] == "g" else capacity
    best[sr][sc] = start_fuel
    queue = deque([(sr, sc, start_fuel)])

    while queue:
        r, c, fuel = queue.popleft()
        if (r, c) == end:
            return True
        if fuel == 0:
            continue

        for dr, dc in DIRECTIONS:
            nr, nc = r + dr, c + dc
            if not (0 <= nr < rows and 0 <= nc < cols):
                continue
            if grid[nr][nc] == "r":
                continue

            nfuel = fuel - 1
            if grid[nr][nc] == "g":
                nfuel = capacity            # refill on arrival

            if nfuel <= best[nr][nc]:
                continue                    # we have been here with at least this much fuel
            best[nr][nc] = nfuel
            queue.append((nr, nc, nfuel))

    return False
```

### If they want the path, not just a boolean

Store a parent pointer keyed by the full state and walk it back:

```python
    parent = {(sr, sc, start_fuel): None}
    # ... on push:  parent[(nr, nc, nfuel)] = (r, c, fuel)
    # ... on success, walk parent back from the winning state and reverse.
```

## Complexity

| | Time | Space |
|---|---|---|
| No stations (BFS) | `O(m * n)` | `O(m * n)` |
| With stations, naive `(r, c, fuel)` BFS | `O(m * n * capacity)` | `O(m * n * capacity)` |
| With stations + dominance pruning | `O(m * n * capacity)` worst case, far less in practice | `O(m * n)` for `best` |

The dominance pruning is worth stating carefully: because `best[r][c]` only ever increases,
each cell can be pushed at most `capacity + 1` times, which is where the worst-case bound
comes from. In practice the pruning collapses it close to `O(m*n)`.

## How to present it

1. **Draw the grid** and mark start, oasis, obstacles.
2. **State the reframing immediately**: "with no refuelling, fuel is just a budget - the
   question is whether the shortest path is at most `fuel`. So this is BFS plus one
   comparison." This is the insight; lead with it.
3. **Justify why revisiting is pointless** in this version: every move costs one, so a
   revisit strictly wastes fuel.
4. **Code the BFS**, narrating the `seen` set and the early exit.
5. **Pre-empt the follow-up**: "if there were gas stations, this argument breaks, because
   arriving at a cell with more fuel is strictly better - so fuel would have to enter the
   state." Saying this before they ask is the strongest move available in this question.
6. **When they do ask**, code the three-dimensional BFS and add the dominance pruning as an
   optimisation, explaining it as "we only care about the best fuel per cell".

## Follow-ups and variations

- **"Some cells have gas stations, so you can refill and continue."** The main follow-up.
  Ask whether a station refills **to full** or adds a fixed amount, and whether a station
  can be used **more than once**. If single-use, the state needs a visited-stations bitmask
  - say that it is exponential in the number of stations and only tractable when there are
  few (this is the Travelling-Salesman flavour; bitmask DP).
- **"Only ONE gas station, somewhere."** Neat special case: the answer is
  `dist(start, end) <= fuel` **or** `dist(start, g) <= fuel and dist(g, end) <= capacity`.
  Two BFS runs, no extra state dimension. Offer this - it shows you look for structure
  instead of reaching for the general machine.
- **"Multiple gas stations, with edge cases around refilling on the same cell twice."**
  Decide and state the rule: refilling when already full is a no-op, and the dominance
  pruning already prevents the infinite loop that worries them.
- **"Obstacles are added, given by 'r'."** One condition in the neighbour loop.
- **"What is the minimum fuel needed?"** Binary search the answer over `[0, m*n]` calling the
  boolean version, or just run BFS once and read `dist[end]` (no stations). With stations,
  binary search on capacity, since feasibility is monotone in capacity.
- **"Minimise the number of refuel stops."** 0-1 BFS: moving costs 0 stops, refuelling costs
  1, so use a deque with push-front for zero-cost transitions.
- **"Different terrain costs different fuel."** Now edge weights vary, so BFS is wrong -
  Dijkstra with `(fuel_used, r, c)` in a heap.
- **"Eight directions / diagonal movement."** Extend `DIRECTIONS`.
- **"The grid is huge and mostly empty."** Bidirectional BFS, or A* with Manhattan distance
  as the heuristic (admissible on a four-directional unit-cost grid).

## Pitfalls

- **Putting fuel into the state when there are no stations.** It is correct but it multiplies
  the work by `fuel` for nothing, and it signals you did not see the structure.
- **Leaving fuel *out* of the state once stations exist.** Now it is simply wrong: a plain
  `seen` set blocks the detour-and-return path that is the whole point of the follow-up.
- **Using DFS for the no-station version** and concluding "no path" because the first route
  found was too long. Reachability with a budget needs the *shortest* route.
- **Checking `fuel > 0` instead of `fuel >= 0` on arrival**, rejecting a path that lands on
  the oasis with an empty tank.
- **Forgetting the `start == end` case** (zero fuel needed).
- **Marking `seen` on pop rather than on push** in BFS, which lets the same cell be queued
  many times.
- **No dominance check in the station version**, so a cycle of refuel loops forever.
