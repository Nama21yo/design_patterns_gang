## Prompt as given

```
Convert a number from 1 to 4000 into Roman numerals.
```

Link: [Integer to Roman](https://leetcode.com/problems/integer-to-roman/) (LC 12).
The reverse direction is [Roman to Integer](https://leetcode.com/problems/roman-to-integer/) (LC 13).

## Clarifying questions to ask first

1. **Is 4000 actually in range?** Standard Roman numerals only go to 3999 - `MMMM` is not
   conventional (the classical form uses an overbar for thousands). The prompt says
   "1 to 4000". Ask: do they want `MMMM` for 4000, or should 4000 be rejected? Either answer
   is fine; **noticing** is the point.
2. **Subtractive notation required?** Is 4 `IV` or `IIII`? Modern convention is `IV`. Clock
   faces use `IIII`. Confirm.
3. **Uppercase output?** Yes.
4. **Must I validate the input** (zero, negative, above range)?
5. **Do they also want the reverse direction?** Ask - it is the obvious follow-up and it is
   quick.

## Intuition

The naive approach special-cases each digit position with nested `if`s and is a swamp of
edge cases.

The trick is to treat the **six subtractive forms as if they were ordinary symbols**:

```
M = 1000   CM = 900   D = 500   CD = 400
C = 100    XC = 90    L = 50    XL = 40
X = 10     IX = 9     V = 5     IV = 4
I = 1
```

That is 13 value-symbol pairs. With those in the table, the algorithm is a plain greedy:

> **Walk the table from largest value to smallest; while the number is at least the current
> value, append the symbol and subtract.**

No special cases at all - `4` is handled because `IV` is literally in the table, and `900` is
handled because `CM` is.

**Why greedy is correct here:** the value set is constructed so that at every step, taking
the largest usable symbol never forces a worse choice later. Concretely, after you have taken
all the `M`s, the remainder is under 1000, and the table's next entries (`CM`, `D`, `CD`, `C`)
cover 900/500/400/100 in a way that each hundreds digit 0-9 has a unique shortest encoding.
Roman numerals are *designed* to be greedy-decodable - that is the honest answer if asked to
prove it, and it is better than pretending there is a deep argument.

## Approach

1. Build the 13-entry table, descending by value.
2. For each `(value, symbol)`: `count, num = divmod(num, value)`, append `symbol * count`.
3. Join.

The `divmod` form is neater than a `while` loop and does the same thing - it takes all
repetitions of a symbol at once. Since no symbol repeats more than three times in valid
Roman numerals (except `M`), either is fine.

## Solution

```python
# Subtractive forms are included as if they were ordinary symbols, which removes
# every special case from the loop below.
ROMAN = (
    (1000, "M"), (900, "CM"), (500, "D"), (400, "CD"),
    (100,  "C"), (90,  "XC"), (50,  "L"), (40,  "XL"),
    (10,   "X"), (9,   "IX"), (5,   "V"), (4,   "IV"),
    (1,    "I"),
)


def int_to_roman(num):
    """Greedy largest-first over the value table. Works because Roman numerals are
    constructed to be greedy-decodable."""
    if not 1 <= num <= 3999:
        raise ValueError(f"{num} is outside the conventional Roman range 1-3999")
    parts = []
    for value, symbol in ROMAN:
        if num >= value:
            count, num = divmod(num, value)
            parts.append(symbol * count)
    return "".join(parts)
```

```python
int_to_roman(1)      # 'I'
int_to_roman(4)      # 'IV'
int_to_roman(9)      # 'IX'
int_to_roman(14)     # 'XIV'
int_to_roman(40)     # 'XL'
int_to_roman(58)     # 'LVIII'
int_to_roman(400)    # 'CD'
int_to_roman(1994)   # 'MCMXCIV'
int_to_roman(3999)   # 'MMMCMXCIX'
```

`1994` is the one to trace out loud: `M` (1000) leaves 994, `CM` (900) leaves 94, `XC` (90)
leaves 4, `IV` (4) leaves 0. `MCMXCIV`. Four steps, no branching.

If they do want 4000 as `MMMM`, change the guard to `1 <= num <= 4000` and note that the
greedy still works because `M` simply repeats four times.

### The reverse direction

```python
VALUES = {"I": 1, "V": 5, "X": 10, "L": 50, "C": 100, "D": 500, "M": 1000}


def roman_to_int(s):
    """A symbol smaller than the one after it is subtractive; otherwise additive.
    One pass, no lookahead table needed."""
    total = 0
    for i, ch in enumerate(s):
        value = VALUES[ch]
        # IV, IX, XL, XC, CD, CM are exactly the cases where a smaller symbol
        # precedes a larger one.
        if i + 1 < len(s) and value < VALUES[s[i + 1]]:
            total -= value
        else:
            total += value
    return total
```

```python
roman_to_int("III")        # 3
roman_to_int("IV")         # 4
roman_to_int("LVIII")      # 58
roman_to_int("MCMXCIV")    # 1994
roman_to_int("MMMCMXCIX")  # 3999
```

The subtract-if-smaller-than-next rule is the whole algorithm and it is worth stating as a
sentence before coding: *"scan left to right; a symbol whose successor is larger is
subtracted, otherwise added."*

### Validating a Roman numeral

Worth having ready, since "validate it" is a natural follow-up:

```python
import re

ROMAN_PATTERN = re.compile(
    r"^M{0,3}(CM|CD|D?C{0,3})(XC|XL|L?X{0,3})(IX|IV|V?I{0,3})$")


def is_valid_roman(s):
    """Canonical form only: at most three repeats, subtractive pairs where required."""
    return bool(s) and ROMAN_PATTERN.fullmatch(s) is not None
```

```python
is_valid_roman("MCMXCIV")   # True
is_valid_roman("IIII")      # False  -- four repeats
is_valid_roman("IC")        # False  -- not a legal subtractive pair
is_valid_roman("MMMM")      # False  -- above 3999 in canonical form
```

The cleaner non-regex answer, and the one to give if they want an algorithm rather than a
pattern: `is_valid_roman(s)` iff `int_to_roman(roman_to_int(s)) == s`. Round-tripping is a
neat validity test because `int_to_roman` only ever emits canonical forms. Offer that - it is
a nicer idea than the regex.

## Complexity

| | Time | Space |
|---|---|---|
| `int_to_roman` | `O(1)` | `O(1)` |
| `roman_to_int` | `O(len(s))` | `O(1)` |

Both are genuinely constant-time for a bounded input range: the table has 13 entries and the
output is at most 15 characters (`MMMDCCCLXXXVIII` for 3888). Say "`O(1)` because the input
is bounded" rather than reflexively saying `O(n)` - and if they push, the honest general
bound is `O(log num)` symbols, since each table step reduces the number multiplicatively.

## How to present it

This is a short question and the risk is fumbling the table under time pressure.

1. **Ask about 4000 immediately.** It is the one genuine oddity in the prompt and it costs
   ten seconds. Whether they wanted `MMMM` or a rejection, you look careful.
2. **Write the table first**, all 13 rows, before any code. Say: "I'm including the six
   subtractive forms as if they were symbols, which removes every special case."
3. **State the greedy** in one sentence and note that Roman numerals are constructed to make
   it correct - do not overclaim a proof.
4. **Write the loop.** Five lines.
5. **Trace 1994** out loud. It exercises three of the six subtractive forms.
6. **Test the boundaries**: 1, 4, 9, 3999.
7. **Offer the reverse direction** unprompted; it is six lines and it is the expected
   follow-up.

## Follow-ups and variations

- **"Now do Roman to integer."** `roman_to_int` above. The subtract-if-smaller-than-next
  rule. Reported as a standalone question in this loop too.
- **"Validate a Roman numeral string."** Round-trip through both conversions, or the regex.
  Prefer the round-trip; it is self-evidently correct.
- **"Why does the greedy work?"** The table is constructed so each decimal digit has a unique
  canonical encoding, and taking the largest usable symbol always lands you in the right
  digit position. Be honest that this is a property of the chosen symbol set rather than a
  general theorem - a greedy over an arbitrary coin system is *not* optimal (`[1, 3, 4]` and
  target 6 gives 4+1+1 greedily, but 3+3 is better).
- **"Handle 4000 and above."** Above 3999 the classical system needs an overbar (vinculum)
  meaning x1000. If asked, propose `M` repeated, or a bracket notation like `(V)` for 5000,
  and say which convention you are adopting.
- **"What about 0 or negatives?"** Romans had no zero. Raise.
- **"Do it without the subtractive forms"** (`IIII` style). Drop the six two-character rows
  from the table; the same loop works.
- **"Minimise the number of symbols for an arbitrary symbol set."** Now greedy is wrong in
  general and it becomes a coin-change DP. This is a good pivot to show you know the
  boundary of the greedy.

## Pitfalls

- **Writing the table out of order.** It must be strictly descending by value or the greedy
  silently produces nonsense. Double-check the six subtractive rows sit immediately above the
  symbol they modify.
- **Omitting the subtractive forms** and then trying to patch 4, 9, 40, 90, 400, 900 with
  special cases. That is the swamp the table exists to avoid.
- **Getting `CM` and `MC` the wrong way round.** `CM` is 900; `MC` is 1100.
- **Using `while num >= value` and forgetting to subtract**, producing an infinite loop.
- **`divmod` with the arguments reversed.**
- **Building the string with `+=` in a nested loop.** Use a list and `join` - it also reads
  better.
- **Not asking about 4000** when the prompt explicitly names it.
- **In the reverse direction, indexing `s[i+1]` without the bounds check** - `IndexError` on
  the last character.
