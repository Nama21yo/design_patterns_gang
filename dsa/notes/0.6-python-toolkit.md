## collections

### defaultdict

```python
from collections import defaultdict

graph = defaultdict(list)
graph["A"].append("B")          # no KeyError, no setdefault dance
graph["A"]                      # ['B']

groups = defaultdict(list)
for word in ["dog", "god", "oak"]:
    groups["".join(sorted(word))].append(word)
dict(groups)                    # {'dgo': ['dog', 'god'], 'ako': ['oak']}
```

**The trap:** reading a missing key **creates** it.

```python
d = defaultdict(int)
_ = d["missing"]
dict(d)                         # {'missing': 0}
```

That is a silent memory leak on a read path. Use `.get()` when you only want to look.

### Counter

```python
from collections import Counter

c = Counter("mississippi")
c["s"]                          # 4
c["z"]                          # 0   -- returns 0 and does NOT insert, unlike defaultdict
c.most_common(2)                # [('i', 4), ('s', 4)]
```

Counter arithmetic is the quiet superpower - it is the multiset difference:

```python
(Counter("aab") - Counter("ab"))            # Counter({'a': 1})
sum((Counter("leetcode") - Counter("practice")).values())    # 5
```

`Counter - Counter` **drops non-positive counts**, which is exactly "how many of these do I
still need". That one line answers *Minimum Number of Steps to Make Two Strings Anagram*,
reported in this loop.

Comparing anagrams:

```python
Counter("listen") == Counter("silent")      # True
```

### deque

```python
from collections import deque

q = deque([1, 2, 3])
q.appendleft(0)                 # O(1) at both ends
q.popleft()                     # 0
list(q)                         # [1, 2, 3]
```

Use it for **BFS queues** and **sliding window maximum**. A `list` with `pop(0)` is `O(n)`
per call and turns a linear BFS quadratic.

`deque(maxlen=k)` auto-evicts from the other end - occasionally handy for a fixed window.

### OrderedDict

Mostly superseded by plain `dict`, with one exception that matters:

```python
from collections import OrderedDict

d = OrderedDict(a=1, b=2, c=3)
d.move_to_end("a")              # O(1) - a plain dict cannot do this
list(d)                         # ['b', 'c', 'a']
d.popitem(last=False)           # ('b', 2)   -- pop the oldest
```

`move_to_end` + `popitem(last=False)` is an LRU cache in two lines. Underneath, `OrderedDict`
is a hash map over a doubly linked list - say that, because it is what an interviewer wants
to hear you know (see 23.11).

## heapq

Python's heap is a **min-heap**, always.

```python
import heapq

h = [5, 1, 3]
heapq.heapify(h)                # O(n), not O(n log n)
h[0]                            # 1   -- peek is O(1)
heapq.heappush(h, 0)
heapq.heappop(h)                # 0
```

**Max-heap:** negate on the way in and out.

```python
h = []
for x in [5, 1, 3]:
    heapq.heappush(h, -x)
-heapq.heappop(h)               # 5
```

**Tuples as keys**, with a counter to break ties and keep items comparable:

```python
import itertools
counter = itertools.count()
h = []
heapq.heappush(h, (2, next(counter), "task b"))
heapq.heappush(h, (1, next(counter), "task a"))
heapq.heappop(h)[2]             # 'task a'
```

The middle element matters: without it, two entries with equal priority would compare their
payloads, and if the payload is not orderable (a dict, say) that raises `TypeError`.

**Top-k:**

```python
heapq.nlargest(2, [5, 1, 9, 3])                     # [9, 5]
heapq.nsmallest(2, [5, 1, 9, 3])                    # [1, 3]
heapq.nlargest(2, {"a": 3, "b": 9}.items(), key=lambda kv: kv[1])   # [('b', 9), ('a', 3)]
```

`nlargest(k, ...)` keeps a heap of size `k`, so it is `O(n log k)` - better than sorting when
`k` is small. **Watch the tie-break:** it sorts *descending* by the key, so `(count, name)`
orders ties by name descending. If you need "count descending, name ascending", select by
count then sort the short result (see 23.8).

**Lazy deletion:** you cannot remove an arbitrary element from a heap in `O(log n)`. The
standard workaround is to push replacements and skip stale entries when popping.

## bisect

Binary search over a **sorted** list.

```python
import bisect

a = [1, 3, 3, 5, 7]
bisect.bisect_left(a, 3)        # 1   -- first index where 3 could go
bisect.bisect_right(a, 3)       # 3   -- last index where 3 could go
bisect.bisect_right(a, 3) - bisect.bisect_left(a, 3)    # 2   -- count of 3s
bisect.bisect_left(a, 4)        # 3   -- insertion point for a missing value
```

`bisect_left` and `bisect_right` are lower_bound and upper_bound. Between them you get: find
first occurrence, find last occurrence, count occurrences, and find the insertion point - see
Part 5.

`bisect.insort(a, x)` inserts in sorted position, but it is **`O(n)`** because of the shift.

Searching by a key (Python 3.10+):

```python
records = [(1, "a"), (3, "b"), (5, "c")]
bisect.bisect_left(records, 3, key=lambda r: r[0])      # 1
```

On older versions, keep parallel lists and bisect the key list - which is what 23.8 does.

## itertools

```python
import itertools

list(itertools.accumulate([1, 2, 3, 4]))                        # [1, 3, 6, 10]
list(itertools.accumulate([1, 2, 3], initial=0))                # [0, 1, 3, 6]
list(itertools.combinations([1, 2, 3], 2))                      # [(1, 2), (1, 3), (2, 3)]
list(itertools.permutations([1, 2], 2))                         # [(1, 2), (2, 1)]
list(itertools.product([0, 1], repeat=2))                       # [(0, 0), (0, 1), (1, 0), (1, 1)]
["".join(g) for _, g in itertools.groupby("aabbbc")]            # ['aa', 'bbb', 'c']
```

`accumulate` is prefix sums in one line. `groupby` gives you runs of identical adjacent
elements - useful for run-length problems, but note it only groups **adjacent** items, so
sort first if you want true grouping.

## functools

```python
import functools


@functools.lru_cache(maxsize=None)
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)


fib(50)                         # 12586269025
fib.cache_info().hits           # 48
```

`@lru_cache` turns exponential recursion into linear. Two caveats to state:
- **Arguments must be hashable** - no lists or dicts; convert to tuples.
- It does not help with **recursion depth**, which is a separate limit (see below).

`functools.cmp_to_key` adapts an old-style comparator when a sort rule is not expressible as
a key:

```python
from functools import cmp_to_key
sorted([3, 1, 2], key=cmp_to_key(lambda a, b: b - a))           # [3, 2, 1]
```

Prefer `key=` when you can - it evaluates once per element rather than once per comparison.

## Sorting

```python
sorted([("b", 2), ("a", 2)], key=lambda x: (x[1], x[0]))        # [('a', 2), ('b', 2)]
sorted([3, 1, 2], reverse=True)                                 # [3, 2, 1]
sorted(["bb", "a"], key=len)                                    # ['a', 'bb']
```

**Descending by one field, ascending by another** - negate the numeric one:

```python
sorted([("a", 2), ("b", 2), ("c", 3)], key=lambda x: (-x[1], x[0]))
# [('c', 3), ('a', 2), ('b', 2)]
```

Python's sort is **stable**, so you can also sort in passes, least significant key first.

## Numbers and strings

```python
divmod(17, 5)                   # (3, 2)
-7 // 2                         # -4   -- floors toward negative infinity, unlike C
-7 % 2                          # 1    -- result has the sign of the divisor
int("0b1010", 0)                # 10
bin(10)                         # '0b1010'
bin(10).count("1")              # 2
(10).bit_count()                # 2    -- Python 3.10+
float("inf") > 10**100          # True

"abc"[::-1]                     # 'cba'
"a,b,,c".split(",")             # ['a', 'b', '', 'c']
"  x ".strip()                  # 'x'
"abc".isalpha()                 # True
ord("a"), chr(97)               # (97, 'a')
```

`-7 // 2 == -4` is a real source of bugs if you are used to C or Java, where it truncates to
`-3`. For binary search midpoints it does not matter (indices are non-negative), but for
anything with negative values it does.

## Recursion limits

```python
import sys
sys.getrecursionlimit()         # 1000
```

Python's default limit is 1000 frames. This is why several notes prefer iteration:
- Collatz chains overshoot hugely before descending (23.2).
- A grid DFS on a 1000x1000 all-land grid is a million frames deep (23.15).
- A degenerate linked list or tree is `O(n)` deep.

`sys.setrecursionlimit(10**6)` exists but risks a genuine C-stack segfault. In an interview,
**say the limitation and write the iterative version** - that is what one reported
interviewer explicitly asked for.

# The internals questions they actually asked

These came up verbatim in these loops. They are recall; have the answers ready.

## "How does hashing work in a set and a hash map?"

1. A **hash function** maps the key to a fixed-size integer (`__hash__`). Equal objects must
   have equal hashes - which is why mutable types are unhashable, since mutating one would
   strand it in the wrong bucket.
2. That integer is reduced to a **bucket index**, in CPython by masking against the table
   size.
3. **Collisions** are resolved either by **separate chaining** (a list per bucket) or **open
   addressing** (probe for another slot). CPython uses open addressing with a perturbation
   probe sequence that mixes in the high bits of the hash.
4. The **load factor** is entries over table size. Above a threshold (two-thirds in CPython)
   the table is **resized** and every entry **rehashed**. That single operation is `O(n)`,
   but it is rare enough that insertion is **amortised `O(1)`**.
5. A `set` is the same machinery storing only keys. A `dict` since 3.7 also keeps a compact
   **entries array** that preserves insertion order, with the hash table holding indices
   into it.
6. **Worst case is `O(n)`** per operation when everything collides. This is why hash-flooding
   is a real attack and why CPython randomises string hashes per process by default.

## "What happens if you use `raise` instead of `return`?"

`return` hands a value to the caller and unwinds one frame normally. `raise` propagates an
exception up the call stack until something catches it; if nothing does, the program
terminates with a traceback.

For an error condition like popping an empty stack, **raise** - there is no in-band value
that safely means "empty" without colliding with a legitimate element (`None` and `-1` can
both be real data). It is also the **consistent** choice, since `list.pop()` itself raises
`IndexError`. A custom exception subclass makes it catchable without swallowing unrelated
errors.

## "What are the drawbacks of the recursive solution?"

Unbounded stack depth against a 1000-frame default limit; one stack frame of memory per
level; function-call overhead; and no tail-call optimisation in CPython, so a tail-recursive
loop is not free. The upside is that it often matches the recurrence exactly and is easier to
read - say both sides and then pick.

## Shallow vs deep copy

```python
import copy

original = [[1, 2], [3, 4]]
shallow = copy.copy(original)           # or original[:] or list(original)
deep = copy.deepcopy(original)

shallow[0].append(99)
original[0]                             # [1, 2, 99]   -- inner list is SHARED
deep[0]                                 # [1, 2]       -- fully independent
```

This is why `results.append(path)` in a backtracking loop is a bug and
`results.append(path.copy())` is not - see 23.7.

## Mutable default arguments

```python
def bad(item, bucket=[]):
    bucket.append(item)
    return bucket


bad(1)                          # [1]
bad(2)                          # [1, 2]   -- the SAME list, evaluated once at def time
```

The default is evaluated once, when the function is defined. Use `None` and create inside:

```python
def good(item, bucket=None):
    if bucket is None:
        bucket = []
    bucket.append(item)
    return bucket


good(1)                         # [1]
good(2)                         # [2]
```

## `is` vs `==`

`==` compares value, `is` compares identity. Use `is` only for `None`, `True`, `False` and
sentinels. Small-integer and short-string interning makes `is` *appear* to work on values,
which makes it a lurking bug.

## The GIL, briefly

CPython's Global Interpreter Lock means only one thread executes Python bytecode at a time.
So threads help with **I/O-bound** work (the lock is released during I/O) and not with
**CPU-bound** work, for which you want `multiprocessing`. `asyncio` is single-threaded
cooperative concurrency, also for I/O.

Relevant answer for a design follow-up: a single attribute assignment is atomic under the
GIL, so a lone `publisher.name = new_name` is safe; a read-modify-write across several
structures is not and needs a lock (see 23.23).
