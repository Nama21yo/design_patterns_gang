*Halve a search space that is monotone in the answer - not just sorted arrays.*

64 Bloomberg-tagged questions, 18 of them Tier A. This is the highest-leverage Part in the
course, because **"binary search on the answer"** unlocks a whole class of problems that do
not look like search problems at all (5.6, 5.12, 5.14), and most candidates never make that
leap.

## The one idea

Binary search does **not** require a sorted array. It requires a **monotone predicate**:

> **Some property `P(x)` that is `False` for all `x` below a threshold and `True` for all `x`
> at or above it - an `F F F F T T T` pattern. Binary search finds the boundary.**

Sorted-array search is the special case where `P(i)` is `nums[i] >= target`. Once you think
in predicates rather than arrays, "find the minimum capacity such that the shipment fits in D
days" becomes an ordinary binary search.

**Before writing any binary search, say what your predicate is and why it is monotone.** That
single sentence prevents most of the bugs below.

## Getting the boundaries right

Off-by-one errors here are the most common bug in interviews. The cure is to pick **one**
template and always use it.

### Template: find the first True (lower bound)

```python
def first_true(lo, hi, predicate):
    """Smallest x in [lo, hi] with predicate(x) True, or hi + 1 if none.

    Invariant: the answer is always in [lo, hi]. The range shrinks every iteration,
    and lo == hi when the loop ends, so there is no ambiguity about which to return.
    """
    while lo < hi:
        mid = (lo + hi) // 2        # biased LOW: safe because hi = mid keeps progress
        if predicate(mid):
            hi = mid                # mid might be the answer - keep it
        else:
            lo = mid + 1            # mid is definitely not - discard it
    return lo


first_true(0, 10, lambda x: x >= 7)         # 7
first_true(0, 10, lambda x: x >= 0)         # 0
first_true(0, 10, lambda x: x >= 11)        # 10
```

Three properties make this template safe:

1. **`while lo < hi`**, not `<=`. The loop ends with `lo == hi`, so you return `lo` with no
   final comparison.
2. **`hi = mid`, never `mid - 1`.** `mid` might be the answer, so you keep it.
3. **`mid = (lo + hi) // 2` rounds down**, which guarantees `mid < hi` whenever `lo < hi`, so
   `hi = mid` strictly shrinks the range. No infinite loop.

If you ever write `lo = mid` (rather than `mid + 1`), you **must** bias the midpoint upward
with `(lo + hi + 1) // 2`, or the range stops shrinking. Mixing the two is the classic
infinite loop.

### The classic array search, in the same shape

```python
def binary_search(nums, target):
    """Index of target, or -1. Uses the same lower-bound shape, then one final check."""
    if not nums:
        return -1
    lo, hi = 0, len(nums) - 1
    while lo < hi:
        mid = (lo + hi) // 2
        if nums[mid] >= target:
            hi = mid
        else:
            lo = mid + 1
    return lo if nums[lo] == target else -1


binary_search([1, 3, 5, 7], 5)      # 2
binary_search([1, 3, 5, 7], 4)      # -1
binary_search([], 1)                # -1
binary_search([2], 2)               # 0
```

The `nums[lo] == target` at the end is needed because lower-bound finds the **insertion
point**, which exists even when the target does not.

### `bisect` - use it when you can

```python
import bisect

a = [1, 3, 3, 5, 7]
bisect.bisect_left(a, 3)                            # 1
bisect.bisect_right(a, 3)                           # 3
bisect.bisect_right(a, 3) - bisect.bisect_left(a, 3)    # 2
bisect.bisect_left(a, 4)                            # 3
bisect.bisect_left(a, 0)                            # 0
bisect.bisect_left(a, 100)                          # 5
```

`bisect_left` is lower bound; `bisect_right` is upper bound. Between them you get: first
occurrence, last occurrence, count of occurrences, and insertion point. **Say you would use
`bisect` in production, then hand-roll it if asked** - most interviewers want the hand-rolled
version but appreciate knowing you know the library.

## Binary search on the answer

The high-value technique. The shape:

1. The answer is a number in some range `[lo, hi]`.
2. There is a `feasible(x)` check: *can the task be done with budget/capacity/speed `x`?*
3. `feasible` is **monotone**: if `x` works, anything larger works too.
4. Binary search for the smallest feasible `x`.

```python
def min_feasible(lo, hi, feasible):
    """Smallest x in [lo, hi] for which feasible(x) is True."""
    while lo < hi:
        mid = (lo + hi) // 2
        if feasible(mid):
            hi = mid
        else:
            lo = mid + 1
    return lo


# "Smallest divisor such that the sum of ceilings is at most the threshold."
def smallest_divisor(nums, threshold):
    def feasible(d):
        return sum((x + d - 1) // d for x in nums) <= threshold
    return min_feasible(1, max(nums), feasible)


smallest_divisor([1, 2, 5, 9], 6)       # 5
smallest_divisor([44, 22, 33, 11, 1], 5)    # 44
```

**Recognition signals for this variant:**

- "minimum / maximum X such that ..."
- "minimise the maximum" or "maximise the minimum"
- "the smallest capacity / speed / time that still works"
- a feasibility check that is easy to write but the optimum is not

The two questions to answer out loud before coding:

1. **What is the search range?** Usually `[max(single item), sum(all items)]` or
   `[1, max(nums)]`. Getting `lo` and `hi` right is half the problem.
2. **Why is feasibility monotone?** "A bigger ship can carry anything a smaller one can."
   Say it - it is the proof the method applies.

## The other shapes in this Part

### Rotated sorted arrays (5.2, 5.17)

The array is not globally sorted, but **at least one half of any split is**. Determine which
half is sorted by comparing `nums[lo]` with `nums[mid]`, then check whether the target lies
within that sorted half, and discard accordingly.

With **duplicates** the worst case degrades to `O(n)`, because `nums[lo] == nums[mid] ==
nums[hi]` gives no information - the only safe move is to shrink by one. Know that.

### Peak finding (5.5, 5.11)

Binary search works with **no sortedness at all**. If `nums[mid] < nums[mid+1]`, a peak must
exist to the right (the sequence is rising and must eventually fall or hit the boundary);
otherwise one exists at or left of `mid`. The predicate is "is the slope descending here?",
which is monotone in the required sense even though the array is not.

### Binary search over two arrays (5.1)

*Median of Two Sorted Arrays* searches over the **partition point** rather than over values.
Hard, and worth knowing as its own thing.

## How to talk about it

- "The array is sorted, so binary search - `O(log n)`."
- "It isn't sorted, but the answer is monotone: if capacity `x` works, so does `x + 1`. So I
  can binary search on the answer."
- "My predicate is `feasible(x)` = 'can this be done with `x`?', which is False then True,
  so I'm looking for the first True."
- "I'll use the lower-bound template: `while lo < hi`, `hi = mid`, `lo = mid + 1`."
- "`mid` rounds down, and I only ever assign `hi = mid`, so the range always shrinks - no
  infinite loop."
- "The search range is from the largest single item to the total sum, because those are the
  extreme feasible and infeasible values."
- "With duplicates, the rotated-array search degrades to `O(n)` worst case, because equal
  endpoints tell you nothing."
- "That's `O(log(range) * n)` - log iterations, each doing a linear feasibility check."

## Common pitfalls across this Part

- **`while lo <= hi` mixed with `hi = mid`** - infinite loop.
- **`lo = mid` without biasing the midpoint up** - infinite loop.
- **Returning `lo` without checking it actually matches**, when the target may be absent.
- **Wrong initial range** in answer-search problems - too small and you miss the answer, too
  large and feasibility may be undefined.
- **A non-monotone predicate.** Binary search silently returns nonsense; it does not crash.
- **Overflow in `(lo + hi) // 2`.** Not in Python, but say `lo + (hi - lo) // 2` is the
  portable form.
- **Assuming `O(log n)` on a rotated array with duplicates.**
- **Forgetting that binary search needs random access** - it is invalid on a linked list
  without `O(1)` indexing.
